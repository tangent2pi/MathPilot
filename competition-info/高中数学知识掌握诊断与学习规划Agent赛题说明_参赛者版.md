长株潭 Agent 训练营暨创新开发大赛

**高中数学知识掌握诊断与学习规划 Agent 赛题说明**

面向参赛者发布版

# 一、赛题背景

高中数学学习中，学生常通过大量刷题或整套试卷判断自己是否掌握某一章节。这种方式耗时较长，也容易出现归因不准确的问题：学生可能只是公式适用条件不清，却被笼统判断为基础薄弱；也可能只是计算失误，却被误判为知识点不会。本赛题以高中数学“解三角形”章节为试点，要求参赛团队构建一个聊天式知识掌握诊断与学习规划 Agent。

# 二、赛题定位

参赛团队需基于主办方提供的 5 份“解三角形”章节课件 PDF 和《高中数学AI题库模板\_v1.xlsx》，自行整理知识点库、题型库、错因库、题库和诊断规则，开发一个可通过少量选择题、判断题、填空题或追问完成诊断的 Agent。

主办方除附件外，不再额外提供结构化题库、学生真实作答数据、专家隐患标注或隐藏测试集。参赛作品应体现团队对附件材料的结构化能力、诊断建模能力和交互设计能力。

# 三、任务目标

* 从附件课件中抽取“解三角形”章节知识点、题型、常见错因和典型题。
* 基于 Excel 模板建立可被系统调用的结构化诊断数据层。
* 通过聊天方式采集学生画像，包括年级、当前分数、目标分、学习时间和薄弱感受。
* 用少量题目完成轻量测评，并根据作答表现动态调整后续问题。
* 识别学生在知识点、题型、方法和错因上的掌握情况。
* 生成章节掌握度报告、知识漏洞归因和阶段学习计划。

# 四、必选功能

| **功能** | **要求** |
| --- | --- |
| 资料结构化 | 能够把 5 份 PDF 课件整理成知识点、题型、错因、题目和诊断规则。 |
| 聊天式测评 | 支持选择题、判断题、填空题或简短追问，不依赖一次性长试卷。 |
| 自适应出题 | 根据学生前几题表现调整难度、题型或追问方向。 |
| 错因归因 | 每次错误应尽量落到知识点ID、题型ID、错因ID，并给出判断依据。 |
| 掌握度报告 | 输出各知识点掌握度、证据题目、薄弱项排序和风险等级。 |
| 学习计划 | 结合学生目标分和可投入时间，生成 1-4 周学习计划。 |
| 可解释性 | 说明为什么判定某知识点薄弱，避免只给“基础薄弱”“多刷题”等泛化结论。 |

# 五、可选加分项

* 答错后进行多轮追问，区分公式不会、思路会但计算错、概念混淆、条件遗漏等不同错因。
* 支持学生目标分路径规划，例如从 90 分提升到 110 分应先补哪些题型。
* 针对错因推荐变式题或低一档巩固题。
* 生成教师端复核报告，便于老师查看学生诊断证据。
* 支持按同一 Excel 模板迁移到函数、数列、导数等新章节。
* 支持过程性数据沉淀，例如测评历史、薄弱项变化和复测建议。

# 六、数据说明

## 附件范围

| **附件** | **说明** |
| --- | --- |
| 01解三角形的入门题型.pdf | 覆盖正弦定理、余弦定理、三角形个数、面积、形状判断、实际应用等入门题型。 |
| 02解三角形中的中线、角平分线、高线问题.pdf | 覆盖中线定理、角平分线定理、高线、张角定理、等面积法等题型。 |
| 03解三角形中的外接圆、内切圆问题及多三角形问题.pdf | 覆盖外接圆半径、内切圆半径、多三角形拆分、公共边与公共角转化等内容。 |
| 04解三角形中的最值、范围问题.pdf | 覆盖角化边、边化角、基本不等式、三角函数性质、范围与最值问题。 |
| 05一些定理或模型问题.pdf | 覆盖正切恒等式、正弦平方差、圆幂、隐圆、阿波罗尼斯圆、托勒密定理等模型。 |
| 高中数学AI题库模板\_v1.xlsx | 提供知识点库、题型库、错因库、题库样本、诊断规则库、AI输出格式和Prompt模板等结构。 |

## 参赛团队需自行整理的数据

主办方只提供上述附件，不额外提供结构化题库、学生作答样本、专家标注集或隐藏评测数据。参赛团队需基于 PDF 课件和 Excel 模板自行完成数据结构化，并在提交作品时附上数据整理说明。

| **数据项** | **最低要求** | **说明** |
| --- | --- | --- |
| 知识点库 | 不少于 25 条 | 需覆盖 5 个专题，建议采用三级知识点结构，并保留知识点 ID。 |
| 题型库 | 不少于 20 条 | 需从课件题型归纳中抽取，说明典型问法、解题步骤和评分点。 |
| 错因库 | 不少于 20 条 | 需面向解三角形常见错误，例如公式混用、条件遗漏、分类讨论不完整、取等条件遗漏等。 |
| 题库/测评题 | 不少于 80 道 | 可从课件例题、习题中整理，也可在不改变教学目标的前提下自建或改编。 |
| 诊断规则 | 不少于 20 条 | 需说明什么作答表现会触发什么诊断结论和补弱建议。 |
| 测评流程样例 | 不少于 3 个学生画像 | 用于展示不同基础、不同目标分学生的诊断路径和学习计划。 |
| 数据整理说明 | 必须提交 | 说明每类数据如何从附件整理、是否扩充、题目来源、标签规则和质量校验方式。 |

## 推荐数据表结构

| **表/文件** | **建议字段** |
| --- | --- |
| knowledge\_points.csv | knowledge\_id、一级模块、二级模块、三级知识点、难度、前置知识点、掌握标准、补弱建议 |
| question\_types.csv | type\_id、题型名称、关联知识点、典型问法、标准步骤、评分点、训练顺序 |
| error\_causes.csv | error\_id、错因大类、错因名称、表现形式、判断依据、补救建议 |
| questions.csv | question\_id、来源、题型、题干、选项、答案、解析、知识点ID、题型ID、常见错因ID、难度 |
| diagnosis\_rules.csv | rule\_id、触发条件、知识点ID、题型ID、错因ID、诊断结论、学习建议、优先级 |
| student\_cases.csv | case\_id、学生画像、目标分、作答记录、期望诊断重点、期望学习计划方向 |

# 七、交付物

1. 可运行 Demo 或在线访问链接。
2. 代码仓库或部署包，以及 README / 部署说明。
3. 结构化数据文件，包括知识点库、题型库、错因库、题库、诊断规则和学生案例。
4. 参赛数据整理说明，说明数据如何从附件课件和 Excel 模板整理而来。
5. 技术方案说明，包含测评流程、出题策略、归因逻辑、掌握度计算和学习计划生成逻辑。
6. 不少于 3 个完整学生诊断案例，展示测评对话、诊断报告和学习计划。
7. 5 分钟以内演示视频。

# 八、评审重点

| **维度** | **说明** |
| --- | --- |
| 资料结构化能力 | 是否真正从附件中抽取知识点、题型、错因和题目，结构是否清晰可复核。 |
| 诊断准确性 | 知识点、题型、错因识别是否具体，是否有证据支持。 |
| 轻量交互体验 | 是否能用较少题目完成有效诊断，聊天体验是否自然。 |
| 掌握度报告质量 | 报告是否具体、分层清楚，能否指出优先补弱项。 |
| 学习计划可执行性 | 计划是否匹配目标分、时间安排和薄弱项。 |
| 工程完成度 | 系统是否稳定，数据导入、测评、诊断和报告生成流程是否完整。 |
| 可迁移性 | 是否便于按模板扩展到其他数学章节。 |
