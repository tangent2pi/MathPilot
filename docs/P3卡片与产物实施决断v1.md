# P3 卡片与产物实施决断 v1

日期：2026-08-30

## 1. 延续的事实边界

- Pi JSONL 是对话与工具调用转录事实源；assistant-ui 只投影和渲染，不另造消息流。
- 当前线程的隔离工作区是 Agent 文件执行事实源。
- PostgreSQL 保存线程归属、RLS 与不可变交互审计，不复制 Pi 对话正文。
- ArtifactPublisher 是正式教学产物唯一发布通道；浏览器不读取工作区路径，也不接受 Agent 给出的任意 URL。
- 题卡不自行判答、不更新掌握度，且始终允许跳过和改用普通文字。
- 本阶段不接“下一题”fork、后台判答、Dream 或学习闭环编排。

## 2. assistant-ui 官方能力的实际映射

| 需求 | assistant-ui 能力 | 当前 Pi 接法 |
| --- | --- | --- |
| 选择、填空、判断、简答题卡 | Tool UI / Toolkit | Pi 扩展注册 `present_question_card`，`Tools({ toolkit })` 渲染固定领域组件 |
| Agent 按教学情境组合解释卡 | Generative UI | Pi 后端工具 `present_teaching_ui` 传受限 JSON 树，前端用官方 `renderGenerativeUI` 与官方 vocabulary 渲染 |
| 已发布的 HTML、媒体等产物入口 | Elements `ArtifactCard` | 工具只传产物身份与入口；浏览器按当前 thread id 构造同源鉴权地址 |
| 可编辑、带版本历史的侧栏 Artifact | Artifacts / Interactables 示例 | 暂不直接套用；当前 `react-pi` 不传前端工具定义及 interactable 状态回执，需要专门的 Pi transport bridge 后再接 |

不能把官方 AI SDK 示例中的 `unstable_interactableTool` 原样复制到 Pi：该示例依赖浏览器执行前端工具并把结果自动回传模型，而 `@assistant-ui/react-pi@0.0.20` 当前只投影 Pi 原生工具调用、结果和 Host UI。现在采用后端 Pi 工具 + 官方渲染器，不伪造不存在的回传链。

## 3. 三种展示协议

### `present_question_card`

- 固定 Schema：`mathpilot.question-card/v1`。
- 支持 `single_choice`、`multiple_choice`、`fill_blank`、`true_false`、`short_answer`。
- 可用于开场题面，也可由教学 Agent 在任意后续回合调用。
- 交互双通道：
  1. 回答摘要作为正常用户消息写入 Pi 转录；
  2. 网关先核对转录中的 `tool_call_id + artifact_id + card_id`，再写 `pi_card_events`。

### `present_teaching_ui`

- 固定 Schema：`mathpilot.teaching-ui/v1`。
- 只允许 `Card / Col / Row / Header / Text / Caption / Markdown / Fact / Badge / Alert / Divider`。
- 适合步骤拆解、概念对比、提醒和教学流程展示。
- 不包含任意 HTML、脚本、表单动作或判答权限；需要学生作答时使用题卡工具。

### `present_learning_artifact`

- Agent 先按 `mathpilot.learning-artifact/v1` 写入 `output/artifacts/<artifact_id>/`。
- manifest 的 `session_id` 必须取自 `input/session/thread.json`。
- 回合结束时 ArtifactPublisher 校验路径、哈希、MIME、CSP 与响应策略并复制到不可变发布区；鉴权 GET 还会做一次幂等发布以覆盖立即点击和恢复场景。
- 工具参数不含 URI，只含 `artifact_id / kind / renderer / entry`；前端只能构造 `/api/pi/threads/<thread>/artifacts/...`。

## 4. 后续 P3 范围

下一步仍在 P3 内，但需在本切片稳定后继续：

1. 给 HTML/媒体产物增加对话内预览 Surface，而不只打开独立鉴权资源。
2. 将 ArtifactPublisher 的发布描述符写入 PostgreSQL，并在归档到 MinIO 后保留版本索引。
3. 为恢复后的题卡从 `pi_card_events` 读取已提交状态，避免页面刷新后仍可重复作答。
4. 设计 Pi 专用 interactable state bridge 后，再接官方 Artifacts 侧栏、版本历史与可编辑状态；该桥不能通过修改 Pi 核心实现。
