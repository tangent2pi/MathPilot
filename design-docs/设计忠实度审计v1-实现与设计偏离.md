## 2. 结论先行

**用户的怀疑成立，且比预期更严重。** 逐文档核对后确认存在一批「流程能跑、设计意图被降级或偷换」的简要实现，其中最严重的一类不是"某处少了校验"，而是**证据生产侧的生产死路**：错因闭环（C_e）与复习层（R）的所有上游事实表在运行时没有任何写入路径，其"完成证据"全部来自测试 fixture 手工灌数据。这意味着 P4/P3 的验收结论（GOAL §8 自述）在真实服务上不可复现。

四条核心判断：

1. **切题硬路径的诊断门被省略**（doc03 §8.2）：FinalizeQuestionWorkflow 没有 diagnose 步骤，关闭事务恒定写 `diagnosticStatus = "unclassified"`。设计要求的「诊断结论或显式 inconclusive 才能关闭」被降级为占位常量——这正是"用简单方案混过去"的典型。
2. **C_e 与 R 的生产链路不存在**（doc01 §7.2、doc02 §3–4）：`science_v3_diagnostic_claim`/`diagnosis_outcome`/`retention_unit_*` 的 insert 只存在于测试 fixture；ErrorEvidence、ErrorPatternProjection、DelayedReviewEvent、复习队列在真实服务上恒为空。诊断、复测、错因消费在运行时全部空转。
3. **多个「已声明的封版能力」实际不可达**：Dream rollback 无任何调用方；教师审核路由是死端（且 student_trait 被 validator 整体拒绝）；REM/Deep 在 0 或 2+ 教师租户被静默禁用；Selector 不认学生的 mute；`mastered` 状态因 transfer_evidence 恒 false 而永不可达。
4. **前端 P7 停在"防御性渲染"层**：AnswerReceipt 产生后被前端丢弃（学生看不到提交回执）；AgentContextTransparency 的"本轮参考了什么"是后端硬编码标签而非真实注入清单（违反不变量 13）；MemoryLedger 读取一个服务端从不发送的字段而丢弃服务端实际发送的全部关键字段；主聊天管线 KaTeX 丢失。

**也有一批经核实"设计忠实"的部分**，不应返工：Judgment 逐维度编译与 rubric 一致性、BKT 公式与 pyBKT 独立 golden 对拍、ts-fsrs 固定版本重放、教师纠正幂等重放 + Annotation stale、关系矩阵逐候选编译、Dream 三重越权防护、单一 question_catalog 无答案泄露、commitSelection 七步事务、CutRequest 幂等与并发收敛、WorkspaceProjection 只读硬化（同账号/历史为数据/隐藏凭据与 Diary）、Temporal 无自研平行实现。

## 3. P0 发现（5 项）

### D-01（P0·简要实现）切题硬路径的诊断门被省略，关闭无条件盖章 "unclassified"

- 设计：doc03 §8.2 硬路径第 3 步「Diagnostic close：concluded / inconclusive / skipped / unclassified，将已发生关系写成 ErrorEvidence」；README 不变量 8「切题只等待硬事实：…诊断结论/显式 inconclusive…」。
- 代码：`finalizeQuestionWorkflow`（workflows.ts:250-317）只编排 prepare→grade→unresolved 兜底→commitClosure，无 diagnose 步骤；`commitClosure` 恒定 `diagnosticStatus = reason∈{skipped,abandoned} ? "skipped" : "unclassified"`（question-store.ts:674），只检查"缺判定"（:516-534），从不等待诊断结论。
- 影响：`concluded`/`inconclusive` 永远不可达；关闭卡上的诊断状态是占位常量而非硬事实；P4 错因闭环在切题边界断链。流程完全跑得通，硬门被降级。

### D-02（P0·未实现）错因闭环生产死路：DiagnosticClaim/DiagnosisOutcome 无任何运行时写入

- 设计：doc02 §3.3/§4（候选集合、是否值得追问、选探针、逐候选判定映射、停止条件）为完整宿主闭环；doc03 §13 场景「探针把候选分开，保存正反 ErrorEvidence」。
- 代码：`science_v3_diagnostic_claim`/`diagnosis_outcome` 的 insert 仅存在于 `test/scientific-core-fixture.sql:141-171`；`diagnose` TaskSpec 无 outbox 事件路由（outbox-routing.ts:29-42）、无 workflow 派发；contracts 无 `diagnose-input.schema.json`（URI 悬空）；foreground 唯一 learning_action 是 `revise_selection_intent`（foreground-store.ts:167）；probe attempt 被受理（learning-command/service.ts:278）后无下游。
- 影响：C_e 表生产恒空 → ErrorEvidence、ErrorPatternProjection、消费动作、报告、教师时间线全部空转；GOAL 的"P4 端到端用例通过"证据由 fixture 直灌获得，跳过候选建立与探针判定两步。

### D-03（P0·简要实现）R 层生产死路：RetentionUnit 无任何种子，复习队列恒空

- 设计：doc01 §7.2「内容层先定义逻辑 RetentionUnit」→ DelayedReviewEvent → RetentionProjection（ts-fsrs）；doc07 §8.4 复习队列。
- 代码：`compileDelayedReviews`（scientific-store.ts:437-448）从 `science_v3_retention_unit_measurement_rule` 映射观测到单元；该表及 `retention_unit_revision` 的 insert 仅存在于 `test/scientific-core-fixture.sql:55-61`；官方内容导入（migrate-official-content.ts）不写；教师内容 UI 无写路径。
- 影响：生产环境 unit 表为空 → 永不产生 DelayedReviewEvent → 复习队列、RetentionProjection 恒空。ts-fsrs 适配器真实但无事实源，P3 验收证据仅覆盖 fixture 测试。

### D-04（P0·错误实现）AnswerReceipt 产生但前端永远不显示

- 设计：doc07 §7.3 收据取代 JSON 追加（§13.2.3"得到正确收据"）。
- 代码：服务端产生 `view_kind: "answer_receipt"` 的 domain_ui part（learning-command/service.ts:296-322）；但 `LearningRuntimeProvider.tsx:242-252` 对 `author_kind==="student"` 的消息只映射 text/attachment，domain_ui part 被整体丢弃 → 收据气泡不可见。
- 影响：学生提交后看不到"你的回答已提交"；收据消息是唯一含 domain_ui part 的学生消息，渲染器完全跳过它。

### D-05（P0·错误实现）AgentContextTransparency 内容是硬编码标签，违反不变量 13

- 设计：doc07 §8.7「清单须来自 WorkspaceProjection 实际注入，每项带新鲜度与查看链接」；README 不变量 13「学生能知道本轮 Agent 实际参考了什么」。
- 代码：`learning-read/service.ts:282-287` 的 `includes` 是固定标签数组（`["当前对话", ...(currentQuestion?["当前题目"]:[]), ...annotations.map(()=>"相关学习观察")]`），与最新 foreground_request 的 input_artifact 实际内容无关；`relevant_memories`（:217-241）只是"最新 3 条未 mute 注解"，不证明已注入本轮。
- 影响：学生被告知"参考了什么"但无法核对真实注入内容；透明性承诺是伪造的。

## 4. P1 发现（按设计文档域分组，19 项）

### 学习流（doc03）

- **D-06（P1·简要实现）硬路径第 5 步"Next selection"缺失**：commitClosure 事务只排 light/dream（question-store.ts:829-865）；`cut_request.next_intent_ref` 写入后全仓无读取点。做题中改需求时 Selector 已因 active 题返回 already_committed 终止，切题后线程停在"无 active 题且无运行中 Selector"，下一题必须等学生再发消息。doc03 §8.2 第 5 步与 §13 场景落空。
- **D-07（P1·简要实现）InterventionEvent 缺失、hint_level 恒 0**：doc03 §7.2「先给个提示：不切题，写 InterventionEvent，之后的成功不再算独立」；代码 submitAttempt 固定传 `hint_level=0`（learning-command/service.ts:325），前台 teaching agent 无 hint 动作，无任何 InterventionEvent 写入路径（grep 零命中）。拒证兜底存在，但"提示后成功只记教学事实"的前半段（记录干预）不存在。
- **D-08（P1·未实现）自由/阶段/教师三来源未实现**：两个 intent 创建路径都硬编码 `source: "student"`（learning-selection.ts:370,459；foreground-store.ts:389）；无 program/teacher intent、无 LearningActivity 创建命令。统一流骨架正确，但 doc03 §4 验收 #3 不成立。
- **D-09（P1·未实现）外部题/临时生成题无创建路径**：doc03 §11.1/§11.2；schema 有 source 枚举与 provisional 资格（拒绝侧落地），但无命令/Workflow 能创建 `student_external`/`generated_provisional` Session；submitAttempt 对无 question_revision_id 的会话一律 409（learning-command/service.ts:292）。

### 科学内核（doc01）

- **D-10（P1·简要实现）transfer_evidence 恒 false，"mastered" 状态不可达**：`scientific-store.ts:590` 对每条观测硬编码 `transferEvidence: false`；`scientific-core.ts:386` `transferEvidence > 0 ? "mastered" : "possibly_mastered"`。五态状态机实际截断为四态，任何学生永远停在 possibly_mastered。
- **D-11（P1·简要实现）LearningOpportunity 生产不可达**：LO 仅在 `hintLevel > 0` 时生成（scientific-core.ts:178-193）；api-next 唯一 Attempt 入口恒传 0；kind=correction(hint 0) 只得到拒绝。提示路径与自我纠正路径在教学账本中全部丢失；DelayedReviewEvent 的 learning_opportunity 锚点永不触发。
- **D-12（P1·简要实现）EvidencePolicy 布尔资格门从未执行**：`rejectPriorSolutionExposure`/`rejectSameQuestionCorrection` 等 flag 在 `compileJudgment`（scientific-core.ts:164-275）中从未被读取（全文件仅类型声明处 2 次出现）；`parsePolicy`（scientific-store.ts:176-178）强制所有 flag 为 true。资格判定是"硬编码行为 + 摆设 flag"，doc01 §5.2 独立性两条要求（先前未显示解法、非机械复述）无任何检查点。

### 错因（doc02）

- **D-13（P1·简要实现）消费者建议动作层为死代码，诊断规划器不存在**：`deriveErrorConsumerActions`/`loadErrorConsumerActions`（error-core.ts:358-407、error-store.ts:593-641）除测试外零调用；Teaching/Selector 实际消费的是原始投影快照。doc02 §6.1 的 `next_probe | conclude | stop_inconclusive` 动作层整体缺失。
- **D-14（P1·简要实现）QuestionErrorRole 无生产数据**：表（0035:127）与 catalog SQL（selection-store.ts:151-158）存在，insert 仅测试 fixture；`discriminates/verifies_near/verifies_far/verifies_delayed` 四种角色在 catalog 与证据编译中永远不生效。
- **D-15（P1·未实现）reducer 缺「suspected --充分反证--> 无记录」转移**：counter 事实仅在 confirmed/improving 态生效（error-core.ts:291-307）；suspected 态的 counter 只计入计数，状态永不动。doc02 §5.3 明确列出该转移。
- **D-16（P1·简要实现）provisional 证据对状态机零贡献**：reducer 仅消费 `eligibility==="formal"`（error-core.ts:233-235）；doc02 §4.3「最多形成弱证据」退化为"证据存在但任何投影与报告不可见"。
- **D-17（P1·未实现）错因本体 supersede/合并无生产入口**：schema 与 reducer 支持 `superseded_by_error_cause_revision_id`，但无任何命令/CLI 写入；doc02 §6.8 教师"纠正、合并、supersede 入口"不可操作。

### Dream（doc04）

- **D-18（P1·错误实现）教师审核路由是死端，StudentTraitClaim 整体不可达**：REM/Deep 写 `science_v3_annotation_review_proposal`，但表 CHECK 锁死 `status='pending'`（0037:378）无其他值，全仓无任何读取方/API/UI；Deep validator 对 student_trait 一律拒绝（dream-store.ts:985）。doc04 §6.1 gate 10 与 §6.2 的能力无法产生、无人审。
