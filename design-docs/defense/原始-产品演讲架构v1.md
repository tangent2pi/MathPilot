# MathPilot 产品演讲架构

> 场景：长株潭 Agent 训练营暨创新开发大赛现场答辩（面向评委）。
> 形式：8–10 分钟演讲 + 实机演示，本文是可排练的架构蓝图，不是逐字稿。
> 与 `defense-spec.md` 的关系：本文定义「讲什么、按什么顺序、每段要达成什么」；defense-spec 定义「用什么工具渲染、现场怎么切」。两文配套使用，本文为上游。

## 0. 评审坐标系

答辩前先把五档得分映射到演讲段落，评委问什么都往这五档上收。

| 维度   |  权重 | 评委实际在找                 | 本架构落点              |
| ---- | --: | ---------------------- | ------------------ |
| 业务价值 | 30% | 是否解决真实教学问题、是否可落地       | 开场案例 + 收束愿景        |
| 技术实现 | 20% | 架构是否成立、是否跑得起来          | 学生端实机 + 教师端实机      |
| 创新性  | 20% | 与「题库 + 大模型聊天」的通用做法有何不同 | 过程证据 + 科学内核 + 教师裁决 |
| 完成度  | 20% | 功能是否闭环、交付物是否齐全         | 数据规模表 + 章节包迁移演示    |
| 展示表达 | 10% | 是否讲得清、看得懂、记得住          | 唯一主张 + 弧线设计 + 演示纪律 |

## 1. 唯一主张

评委离场后要能复述一句话：

> MathPilot 不是另一个会讲题的聊天机器人，它把学生「怎么想到这一步」变成可诊断、可回放、可复核的学习证据，让诊断结论能追溯到草稿上的每一笔。

支撑这句话的三个支柱，对应三个得分维度：

1. 过程可观察：草稿不是附件，是和聊天并列的第一交互空间，是证据来源。
2. 结论可复核：模型只提判定，程序算状态，教师保留最终裁决权并留痕。
3. 内容可迁移：解三角形只是第一个章节包，同一套数据模型与引擎可换章节。

## 2. 演讲弧线总览

| 幕       | 时间        | 一句话任务           | 主要载体         | 对应得分维度      |
| ------- | --------- | --------------- | ------------ | ----------- |
| 0 开场案例  | 0:00–0:50 | 用一个真实瞬间制造疑问     | 案例动画或录屏片段    | 业务价值        |
| 1 问题    | 0:50–1:40 | 指出「看答案」式诊断的失效   | 演讲 + 一页对比    | 业务价值        |
| 2 学生端实机 | 1:40–3:40 | 让评委亲眼看到过程被采集    | LIVE 实机      | 技术实现        |
| 3 教师端实机 | 3:40–4:50 | 展示人机协作与复核留痕     | LIVE 实机      | 技术实现 + 业务价值 |
| 4 科学内核  | 4:50–6:40 | 讲清掌握度数字从哪来      | 架构动画 + 公式级说明 | 创新性 + 技术实现  |

## 3. 幕 0 开场案例（0:00–0:50）

意图：让评委在第一分钟产生「这题他会做，但他真的会吗」的疑问。

- 主张句：一道做对了的题，可能藏着一个没被发现的知识缺口。

- 素材：取一段真实学生作答（推荐尖子生账号某轮中「答案正确但过程出现条件遗漏」的题），画面依次给出：题目 → 学生写的关键步骤 → 系统标记出的疑点 → 留白。

- 讲法：先念题，再陈述学生结果，然后停顿半秒，抛出问题句「如果只看答案，你已经给他打勾了。但过程里有东西不对。要不要检查一下？」

- 红线：这个案例必须是真实系统数据回放，禁止用合成截图充当实机。

## 4. 幕 1 问题（0:50–1:40）

意图：把个案升维成普遍痛点，给评委一个「为什么现在需要它」的理由。

- 主张句：刷题和整套试卷只能告诉你「对了几道」，说不清「错在哪一类、为什么错、下一步练什么」。

- 讲法：用三连问推进，一问一层：

  1. 公式条件不清被归成「基础薄弱」，归因到不了错因层，问题出在哪？
  2. 计算失误被当成「知识点不会」，教学资源全部打偏，损失是什么？
  3. 诊断结论没有证据链，学生不服、老师不敢信，闭环断在哪？

- 收口句：这三件事的病根相同——诊断只看结果，不看过程。MathPilot 把过程接进来。

## 5. 幕 2 学生端实机（1:40–3:40）

意图：用一次完整但克制的实机演示证明「过程真的被采集、被使用」。

- 主张句：草稿纸是第一表达空间，聊天是控制通道，系统只在旁边看、必要时刻追问。

- 演示路径（每一步说清「你刚才看到什么 → 它意味着什么」）：

  1. 画像采集：年级、当前分、目标分、每周可投入时间、自认薄弱点。一句话带过：画像只决定首题难度，不直接决定诊断结论。
  2. 开题作答：学生在草稿上画图、写列式，系统不打断、不代笔。
  3. 提交与判定：答案提交后，系统给出知识点、题型、错因三层归属。
  4. 答错追问（如有）：系统用追问区分「公式不会 / 思路会但算错 / 概念混淆」，不直接给答案。

- 讲法纪律：演示时说「现在你看到系统读取草稿笔迹并定位到第 X 步」，把每次画面切换翻译成能力词，不要念界面文字。

- 兜底：实机失败时切到同一路径的录屏，话术固定为「我们用同一条路径的实机录屏继续」，不允许现场假装在操作。

## 6. 幕 3 教师端实机（3:40–4:50）

意图：用「教师能改、改了有记录、AI 原结论不丢」证明系统可被信任、可进课堂。

- 主张句：模型给判断，程序守基准，教师保留最终裁决权。

- 演示路径：

  1. 教师打开某学生诊断报告，看到 AI 结论附带的证据与置信度。
  2. 教师对一条结论点「修改」，填复核理由。
  3. 界面显示：AI 原结论保留、教师结论并列、时间与理由留痕（supersede 语义）。
  4. 回到学生端，该题重新诊断时引用的是教师裁决后的结论。

- 加分讲法：顺带一句「这份报告不是给家长看的漂亮话，是给老师复核用的证据文件」，呼应赛题教师复核加分项。

## 7. 幕 4 科学内核（4:50–6:40）

意图：评委里若有技术背景，这是创新性得分的主战场；讲深讲浅都行，但必须诚实。

- 主张句：掌握度、遗忘曲线、错因是三个不同的数，由一个模型用一句话改掉它们，是不可信的。MathPilot 让模型提议、让程序计算。

- 讲三层，每层一句话 + 一个画面：

  1. 掌握度 M：用 OATutor 的 BKT 薄移植，按合格作答证据更新，程序消费事实算状态，模型不直接写数值。
  2. 保持率 R：复用 ts-fsrs，Stability 定义为可提取性降到 90% 的时间，决定何时复测。
  3. 错因 C\_e：每条错因是可证伪假设，带证据、反证、状态；答错后追问收集证据，由确定性 reducer 更新，而不是会话末尾贴一个标签。

- 加一层收口：以上全部沉淀为追加式证据账本，任何一次修改都产生 supersession，不覆盖历史。画面给一条证据链回放：草稿 → 作答 → K/T/E 归属 → 判定 → 状态更新。

- 诚实边界：BKT 参数用 OATutor 既有模型，pyBKT 仅做离线对拍；不宣称「自研算法超越 SOTA」，只讲分工设计与可解释性。

## 8. 幕 5 完成度（6:40–7:40）

意图：用可核查的数字和一次真实切换，证明交付物完整且可迁移。

- 主张句：这套系统不是为一道题写的，是为整个高中数学写的，解三角形只是装上去的第一个章节包。

- 数据页（答辩前按当前库实数值刷新，禁止背诵过期数字）：

  - 知识点库 / 题型库 / 错因库 / 题库 / 诊断规则条数，覆盖五个专题；

  - 完整学生诊断案例数量与三轮掌握度报告；

  - 五个专题各自覆盖范围一句话（入门题型、线角高、圆与多三角形、最值与范围、定理模型）。

- 迁移演示（30 秒内）：在界面上切换/装载另一章节包，或展示按同一 Excel 模板导入新章节的校验流程（ID 唯一、前置无环、K/T/E 关联完整）。讲法：把迁移成本讲成「填表格 + 过校验」，而不是「改代码」。

- 若现场不便跑迁移，用一页 Archify 图展示章节包与引擎的边界即可，标注为架构示意而非实机。

## 9. 幕 6 收束（7:40–8:20）

意图：让整场演讲在一个闭环里结束。

- 回放开场案例画面，给答案：那个「做对了但过程有疑点」的学生，系统给出了带证据的提示，教师复核后修正了结论，学生拿到的是可执行的下周计划。

- 收束句（与唯一主张同构，不用新词）：从一个答案到一个过程，从一个过程到一条可解释的学习路径。

- 最后一页只放一行字 + 一个二维码/链接：可运行 Demo 地址。任何截图和数字都不上这一页。

## 10. 答辩 Q\&A 预判

| 评委可能问           | 应答要点                                                          |
| --------------- | ------------------------------------------------------------- |
| 诊断准确率有多少？       | 不给编造的数字；讲证据设计：K/T/E 三层归属 + 置信度 + 教师复核，答「准确率由证据链支撑，单条结论可打开看依据」 |
| 和直接调用大模型聊天有何区别？ | 大模型给感觉，程序守基准；草稿过程、错因 reducer、状态更新都是确定性程序在管                    |
| 草稿识别错了怎么办？      | 识别不确定与学生错误分开呈现，教师端可标记「待观察」，系统不会把识别噪声当学生错误                     |
| 换章节要多久？         | 讲模板与校验：数据层按 Excel 模板整理，ID/前置/KTE 关联过校验即可装载，不需改引擎              |
| 数据从哪来？          | 从 5 份课件 PDF 结构化而来，题库来自课件例题与习题改编，整理说明与来源已随作品提交                 |
| 为什么选解三角形？       | 它是第一个垂直切片，用于验证「章节包 + 通用引擎」这套可迁移结构                             |

## 11. 排练与现场纪律

- 计时排练至少三轮，目标正文 8:20 讲完，余量给缓冲与提问开场。

- 实机演示前清空浏览器缓存与旧会话，用固定学生账号进入；教师端请以浅色主题演示（当前默认已为白色）。

- 每幕只带一块主屏内容，禁止同时开多个窗口让评委分心。

- 所有「已实现/已验证」的描述必须有对应素材可回放；标为架构示意或未来方向的内容，用词上明确区分，沿用 LIVE / EVIDENCE / CONCEPT 三档标记。

- 不念稿：只带每幕的主张句与演示路径，正文用口语组织。
