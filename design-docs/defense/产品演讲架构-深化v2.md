## 3. 最容易穿帮的 5 个点（实机/QA 前必须处理）

1. **报告数字口径**（高优先）：`测评报告_DemoStudent.pdf` 出现「余弦定理 答 9 对 3 → 掌握度 0.00」「正弦定理 答 9 对 1 → 0.00」与「目标差距 73.9（目标 75 − 掌握度 1%）」的算式出入。若评委盯上会反问口径。
   处理：T-7 用选定演示学生重新生成报告并人工核对：a) 答对≠计入掌握的证据口径（提示后作答不计入、独立完成才更新——用这条解释"答对仍 0.00"须先确认数据满足）；b) 换用数字体面的学生/轮次；c) 若必须用，预先写好口径话术（见 §7 Q&A 第一问）。
2. **导数章节层级**：只完成「文件库四库迁移验证」，不能口播为「产品库已发布、可测评」。话术：「同一套生产线已对导数章节完成迁移验证（116 题全对应题图），证明换章节不用改引擎」。
3. **实机依赖模型与网络**：判答/追问/报告生成走 DeepSeek 端点，无 key 时 502 不伪造。现场前必须：预热登录态与线程、预跑黄金路径、备同路径录屏；现场网络与密钥都是最高风险项。
4. **15 题/轮 ≠ 现场时间盒**：完整一轮 15 题不适合现场跑完。演示脚本只现场完成 1–2 题的关键时刻，其余用既有 3 轮 45 题线程回放 + 报告页（冒烟已证 3 轮闭环可出终版报告）。
5. **班级学情面板**：无路由可演（见 §2 末行），不要安排实机，QA 中被问就按「聚合能力在数据层、班级面板是产品化方向」诚实回答并转回已演示的单生报告。

## 5. 逐幕深化

### 幕 0 开场案例（0:00–0:50）

- 意图：第一分钟让评委对「答案对了=会了」产生怀疑。
- 断言（屏顶大字）：**答案相同的两个人，错因可能完全不同**。
- 素材（T-7 从运行实例选定真实一组，禁止合成截图）：
  - 首选：两位学生同题同答案（或同错），系统追问后判给不同 K/T/E 与不同补弱——判定卡对比并列。
  - 备选：单个学生答错→追问轮次→错因收敛为「公式适用条件不清 vs 漏补角条件」任一真实回放。
- 画面序列：题目卡 → 学生答案/作答轨迹 → 系统判定卡（知识点/题型/错因+依据）→ 停顿 → 另一学生同答案不同判定卡。
- 讲法节奏：念题 10s → 陈述判定 15s → 停顿 1s → 抛出「只看对错，这两个学生会被送去同一个补习班。可他们的病不一样。」
- 红线：素材必须来自运行系统回放（线程/报告截图或录屏），标注 EVIDENCE；当天数据以 T-7 选定轮次为准，禁止现场临时翻找。

### 幕 1 问题（0:50–1:40）

- 断言（屏顶）：**归因不到错因层，练习就全是损耗**。
- 三连问（一问一屏或一屏渐进）：
  1. 公式条件不清被归成「基础薄弱」——补强从哪下手？
  2. 计算失误被当成「知识点不会」——教学资源全部打偏，谁来纠偏？
  3. 诊断结论没有证据链——学生不服、老师不敢信，闭环断在哪？
- 收口句：病根相同——只看结果不看过程。MathPilot 把每次作答变成可追问、可复核的证据。
- 屏风纪律：三问只保留问题主干，解释全部口播（Mayer 冗余原则）。

### 幕 2 学生端实机（1:40–3:40，全场技术主线）

- 断言（屏顶常驻或角标）：**作答 → 判定 → 追问 → 归因，一题一闭环**。
- 演示三级方案（按现场状态选用，正文不重样）：
  - **L1（推荐）半程回放 + 一次新判定**：进入学生账号既有测评线程 → 快速回放到一个判答/追问关键时刻（流式已落库，秒开）→ 现场新提交一道预置题 → 展示判答卡与选题理由。
  - L0 全现场：从新开自我测评起 1–2 题（≤90s，依赖模型延迟可控性，需 2 次以上预演计时）。
  - L2 全录屏：同路径浏览器录屏，话术固定「我们用同一条路径的实机录屏继续」。
- 必须露出的 4 个能力词（每步把画面翻译成能力，不念界面文字）：
  1. 判答卡按评分要点落 K/T/E——「程序按题目声明的测量点给判定，模型只解释语义」；
  2. 答错不判死：可求助、可跳过——「求助与跳过不构成失败证据，诊断只吃真实独立作答」；
  3. 追问消歧 ≤3 轮——「错因是可证伪假设，系统追问把假设逼到收敛，最多三轮」；
  4. 出题卡给选题理由——「下一题为什么是它：补覆盖还是消歧，理由透明」。
- 红线：本轮若出现答错题，路径要能承接（预置候补题/话术），不许现场改口「这题不算」；任何等待 >3s 都要有盖话（见 §10 预演协议）。

### 幕 3 教师端实机（3:40–5:00）

- 断言（屏顶）：**机器判、教师裁、证据留、历史不覆盖**。
- 主路径（必演，≤50s）：教师账号 → 某学生测评报告 → 对一条薄弱结论改判（填写替代结论与理由）→ 系统提示"已追加替代结论并将重放科学状态" → 学生端刷新/回看该结论即时更新。
- 副路径（时间盒内可选，≤30s）：内容复核工坊一次「批准」或「退回自动重做」的既有批次回放（或练习包发布状态页）。
- 能力词：supersede 语义用大白话——「不是橡皮擦，是追加一份更正 + 按新裁决重放整个状态机；AI 原结论仍在证据里」。
- 红线：改判操作必须用预置学生与预置条目，理由字段预填；副路径若未预演过一律不上。

### 幕 4 科学内核（5:00–6:30，可深可浅但必须诚实）

- 断言（屏顶）：**模型提议，程序计算，教师裁决——三层分离才可解释**。
- 画面 1（Archify 正式拓扑，≤60s）：用队友的 `数学智元_系统架构.html`（或按 defense-spec 重新 deliver）逐关系点亮：浏览器→web-next(8080)→api-next(Better Auth)→learning-next（Temporal 编排、前台教学/后台画像分离）→PostgreSQL 事实源；content-next/storage-next/pi-chat-runtime 一条线讲内容；DeepSeek 视觉推理端点与 PaddleOCR-VL 标为外部系统。
- 画面 2（三层分离，≤50s）：一张小图三行：
  - M 掌握度 ← OATutor BKT 薄移植，程序按合格作答算状态，模型不写数值；
  - R 保持率 ← ts-fsrs 间隔重复调度，到期进复习队列；
  - E 错因 ← 追加证据 + 确定性 reducer，可证伪假设全程状态化。
  加一句对拍背书：「BKT 与 pyBKT 黄金对拍差异小于 1e-9（5 组黄金用例）」。
- 画面 3（证据链 + Dream 门控，≤30s，超时则删）：一次改判如何重放——「追加替代 + 确定性重放，历史永不覆盖」；Dream（Light→REM→Deep）只写语义记忆，附图「REM 候选 → Deep 冻结包 → add/supersede/keep/propose_review 四选一」一句话即可。
- 诚实边界：不说「自研算法超越 SOTA」；讲分工与可解释性。掌握度口径若被追问见 §7。

### 幕 5 完成度与可迁移（6:30–7:40）

- 断言（屏顶）：**不是为一道题写的系统，是为整个高中数学写的**。
- 数字表（T-7 从运行库/说明文档04 刷新后定稿，禁止背过期数字）：

| 章节 | 输入 | 题库样本 | 题型/知识点 | 错因 | 题图对应 | 状态口径 |
|---|---|---|---|---|---|---|
| 解三角形（试点） | 官方 5 份 PDF（174 项一次导入） | 139 | 36 / 49 | 73 | 139 张（100%） | 已入产品库 + 读侧验收 ✅ |
| 导数（迁移验证） | 3 份学生版讲义 | 116 | 19 / 32 | 22 | 116 张（100%） | 文件库四库验证 🔶 未发产品库 |

- 附加证明（时间盒内，任一即可）：
  - 组卷成品一句话 + 一张截图（实产 5 份试卷 PDF、答案解析全链路已浏览器实机验证）；
  - 内容工坊复核发布页静态展示（若幕 3 未演）。
- 讲法：把迁移成本讲成「填表格 + 过校验 + 换章节包」，不是改代码；导数证明这句话不是设想。
- 老实收口（呼应说明文档04 §10.1）：全量逐条人工复核与真实学生案例完整走完属于数据验收待办——**主动说比被问好**，且要接「但两轮章节库验收与冒烟断言已实跑」给出对照。

### 幕 6 收束（7:40–8:20）

- 回放开场画面；给答案：同答案不同错因的两人，一个去补适用条件、一个去补取等条件；教师复核过的裁决即时生效；两人各拿到可执行的下周计划。
- 收束句（与唯一主张同构）：**从一个答案，到一个过程，到一条可解释的学习路径。**
- 最后一页只放：作品名 + Demo 地址（`mathpilot.tangentpi.com`，与信息卡一致）+ 团队名；不上任何数字。

## 6. 唯一主张（沿用 v1，措辞对齐实机）

> MathPilot 不是另一个会讲题的聊天机器人：它把每次作答变成可追问、可归因、可复核的学习证据，让「怎么错的、错在哪一类、下一步练什么」都能追溯到一条具体的证据链。

三支柱（对应三得分维度）：
1. 判定可归因——rubric 判答落 K/T/E + ≤3 轮追问消歧 + 选题理由透明（业务价值）；
2. 状态可复核——模型提议、程序计算、教师裁决，追加替代 + 确定性重放（技术实现/创新）；
3. 内容可迁移——章节包 + 内容工坊 + 资料转库.skill，解三角形与导数两章验证（完成度）。

## 7. Q&A 扩表（v1 6 问 + 新增 8 问）

| 评委可能问 | 应答要点 |
|---|---|
| 诊断准确率多少？ | 不给编造数字。讲证据设计：K/T/E 归属 + 置信度/证据状态 + 教师裁决；「单条结论可打开看依据」。数据验收口径主动说明 |
| 答对 9 题里 3 题，掌握度为什么是 0.00？ | 先核对 T-7 选定案例是否仍有此现象；若在，口径话术：BKT 后验由独立完成、无提示的合格作答驱动（提示后/求助不计入掌握证据），少量成功不足以翻转发散的失败先验；报告同页展示证据不足·待复测与薄弱的分档，避免只看一个数 |
| 和「题库 + 大模型聊天」的通用做法有何区别？ | 大模型给语义判定，程序管资格校验、状态计算与原子提交；追问消歧、错因 reducer、保持率调度、改判重放全部确定性；模型没有数据库写权限，判定卡由后端投影生成 |
| 草稿/手写识别错了怎么办？ | 识别不确定与学生错误分开呈现（属视觉识别不确定性，不当学生错误）；内容生产线侧 PaddleOCR-VL 与人工复核把关；学生作答附件可溯源回原图 |
| 换章节/新章节要多久？ | 填四库模板（Excel）+ 自动校验（ID/前置/KTE 关联）+ 内容工坊复核 → 发布；导数 116 题已证明不需改引擎 |
| 数据从哪来、是否可信？ | 官方 5 PDF → 174 项一次导入 + 人工逐条核验；自研资料转库.skill 从讲义自动产四库与题图；字段血缘、自动校验、发布不可变版本；整理说明随作品提交 |
| 为什么选解三角形？ | 第一个垂直切片，验证「章节包 + 通用引擎」可迁移结构——导数迁移验证是这句话的证据 |
| 15 题一轮、45 题三次，一次诊断多久/成本可控吗？ | 对话流式 + Temporal 把画像更新/选题/重放与交互分离，前台无长事务等待；冒烟 3 轮闭环 45 题已实跑出终版报告（14 项断言）。成本讲「少量题信息最大化」定位，不给绝对金额 |
| 模型换了怎么办？ | 模型调用统一经 Pi 运行时、openai-responses provider，端点与密钥环境变量注入可替换；无 key 显式失败不伪造 |
| 为什么上 Temporal？ | 重试/定时/取消/恢复的唯一权威——Dream 画像、选题、状态重放与对话分离，保障交互稳定 |
| 教师班级学情聚合（说明文档提到 0.42 平均掌握度）？ | 如实：聚合在数据层/场景设计里，班级面板属于产品化方向（ROADMAP）；已演示单生报告与教师改判是当前交付 |
| 提示后完成的题算不算会？ | 不算掌握证据；提示等级记录在案，只用于教与练，不污染诊断（提示辅助不计入——说明文档04 口径） |
| 组卷答案解析是大模型生成，错了怎么办？ | 缺失/不确定解析由大模型补全但**标注待复核**，经在线复核后才出片下载——生产线全链路已浏览器实机验证 |
| 商业模式/落地？ | 机构内容生产单点成本低；模式可跨章节、跨学科（解题诊断）、跨场景（技能评估）——最后一句是方向不是承诺 |

## 9. 排练与现场纪律（v1 保留 + 补充）

- 计时排练至少三轮：首轮对脚本、次轮压时间、末轮全要素（含切换兜底与改判操作）彩排；目标正文 8:20 讲完。
- 每幕只带一块主屏；LIVE 页只有一处活动区域，禁止多窗口。
- 实机前清浏览器缓存与旧会话，用固定账号进入；教师端浅色主题（默认已为白）。
- 所有 LIVE 段先预演两次以上并录像回看，标注每个 >3s 等待点与盖话。
- 所有断言沿用 LIVE/EVIDENCE/ARCH 标注；凡标注 ROADMAP/CONCEPT 的内容（班级面板方向等）与实机分区，用词明确。
- 现场网络与模型密钥由专人负责：开场前完成登录态预热 + 黄金路径预跑一遍；断网走 L2 录屏兜底（话术固定）。
- 不念稿：只带每幕断言句与演示路径。
- 数据刷新三关：T-7 数字定稿 → T-3 用运行库复核一次 → T-0 只核对账号可用与黄金路径可放，不再改内容。
