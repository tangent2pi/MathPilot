## 0. 赛题的三个核心痛点（设计的总出发点）

1. **归因不准确**：大量刷题/整卷判断，耗时且混淆——"公式适用条件不清"被误判"基础薄弱"、"计算失误"被误判"知识点不会"；
2. **无现成结构化数据**：主办方只给 5 份 PDF 课件 + Excel 模板，K/T/E/Q/R 全部自建，且要"可复核"；
3. **要可解释**：不能只给"基础薄弱、多刷题"泛化结论，每次错误要落到知识点ID/题型ID/错因ID 并给判断依据。

设计 v3.3 的整套骨架（§0"证据型诊断系统"定位）就是这三个痛点的直接回答：**证据、归因、可解释**。

## 3. 评审标准 → 设计侧重

| 评审维度（权重） | 设计对应 |
|---|---|
| 业务价值 30% | 归因准确性（痛点①）+ 可解释 + 教师复核——证据型诊断定位（§0） |
| 技术实现 20% | pi 统一入口（Agent 特征：工具/规划/记忆，官网硬性要求）+ 契约先行 + 多租户 + 成品复用（pyBKT/OATutor） |
| 创新性 20% | 模型主判+程序基准+画像大模型最终更新三层量化（§9）；一题一 Session 双产物→Dream；字段血缘 |
| 完成度 20% | **骨架补全清单（§5）**——可运行、数据导入→测评→诊断→报告全流程 |
| 展示表达 10% | 数据整理说明、3 个学生案例、演示视频、README |

## 4. 设计选择溯源（为什么是这套设计，不是别的）

| 设计选择 | 目的（赛题关联） |
|---|---|
| **模型主判 + 程序校验证据**（§12） | 归因要落到 ID 并给依据，开放解答无法纯规则判定；纯模型又不可信→程序给科学校验证据，模型解释采纳与否 |
| **三层量化分离 M/R/C**（§9.1） | 赛题痛点①的根源是单分数混叠：运算错=概念不会、时间过=没学会、提示=自动会。分离后归因才能准 |
| **程序基准 + Dream 大模型最终更新**（§9.3） | BKT 看不到跨题纵向语义（方法稳定、自我纠错、迁移）；大模型综合双产物作最终决策，但必须证据账本可解释（赛题"可解释性"） |
| **双产物→Dream 队列**（§11） | 每题一次大模型画像更新会震荡且贵；确定性程序评价及时参与教学，画像统一由 Dream 整理——报告分层、过程数据沉淀（加分项） |
| **一题一 Session 一工作区**（§4.5/§5） | 聊天式测评的载体；防上下文污染（题间只传连续性包）——轻量交互体验 |
| **MeasurementTarget 多标签归因**（§2.3） | 模板要求"一道题关联多个知识点"，但总分不得无差别写入所有 K（归因准确性） |
| **不可变事件 + supersede + 血缘**（§1.3/§7.3/§8.4） | 教师复核报告要可信；数据"结构清晰可复核"（评审"资料结构化能力"） |
| **pi 统一入口 + policies/skills** | 官网硬性要求"Agent 特征（工具调用/规划/记忆）"；提供商可替换（TaoToken 等平台推荐）；模型行为全部策略化可管理 |
| **章节包不可变发布**（§7.2） | 模板迁移加分项：换章节包即换章节；正式 Session 只读已发布版本 |

## 5. 骨架补全清单（按赛题优先级；web 相关后置）

### P0 —— 赛题必选功能缺失（后端骨架）
1. **真实数据层**（赛题交付物核心）：5 份 PDF 的 OCR 稿已在 `competition-info/.../解三角形体系【2026.3.17】/*_by_PaddleOCR-VL-1.6.md`；经 content 管线（KTQ/ER 双 Session 真实跑）产出 **25+ K / 20+ T / 20+ E / 80+ Q / 20+ R** 章节包并发布；生成 student_cases ×3（不同基础/目标分）；数据整理说明文档
2. **DIAGNOSE + 错因归因 + PROBE 追问**（§8.3/§4.5）：submit 后进入诊断态——候选错因（题目关联 E 与规则）→ 消歧追问（≤3 轮）→ DiagnosticClaim 落库 → 闭合或"待观察"
3. **自适应选题器**（§10）：AssessmentRun 驱动——先选目标（覆盖/消歧/前置/复测）再选题（硬过滤+评分）；首次测评用少量覆盖题建立基线
4. **学习计划生成**（§10.3）：确定性约束排 1-4 周任务原子 + LLM 解释转写

### P1 —— 赛题加分/报告支撑（后端）
5. **画像采集端点**（§3.1）：年级/当前分/目标分/每周时间/自认薄弱/设备草稿方式 → 只影响选题与计划
6. **保持率层 retention.ts**（§9.6）：I90 网格后验 + 复测到期 → 错题重刷排序/报告"复测日期"
7. **错因排序与复测接口**（§9.7）：六档证据状态 → 报告与选题消费
8. **修复**：profile dream 长事务移出模型调用；Dream 接线 sidecar（Roster 输出 p_baseline）；evidence_index 检索

### P2 —— 完善
9. Qwen-MM-Plugins 落点（media/edu-agent/search 加分演示）；卡片/Artifact 协议（聊天式测评的卡片形态）；报告/计划接口聚合
