# 02. 错因证据与消费闭环

## 1. 目标

错因系统不是“答错后选一个最像的标签”，而是一个可证伪的假设系统：

```text
观察到异常
  → 提出多个候选原因
  → 选择能区分候选的最小追问/新题
  → 保存每个候选的支持、反证或不可区分结果
  → 确定性投影长期状态
  → 驱动教学、选题、验证、报告和内容改进
```

本设计专门解决现有系统“错因有采集、无消费”和“探针答对就确认第一个候选”的问题。

## 2. 错因不是什么

错因不是：

- 人格判断，例如“懒”“不认真”“天赋不足”；
- 与知识点同义的“不会正弦定理”；
- 单题错误的永恒结论；
- 模型自由生成的一段无结构解释；
- 能被 Dream 直接改写的画像枚举；
- 用一个概率掩盖冲突证据的分类器输出。

一个合格错因必须同时满足：

1. **可观察**：有可引用的表现；
2. **可区分**：存在与相邻候选不同的探针结果；
3. **可干预**：至少有一种针对性教学动作；
4. **可验证**：有近迁移、远迁移或延迟验证政策；
5. **有范围**：说明在哪些题型、表示方式、难度或步骤中成立；
6. **允许未知**：证据不足时能停在 inconclusive/unclassified。

## 3. 五层模型

### 3.1 ErrorCauseDefinition：错因本体

内容层的版本化定义：

```text
error_cause_revision_id
name
category
description
manifestation[]
judgment_basis[]
confusable_with[]
applicable_dimensions[]
remediation_recipe_ids[]
verification_policy_id
status / version / provenance
```

已有 `content_error_cause_revision` 的 name、description、manifestation、judgment_basis、remediation 可以继续复用；需补上混淆候选、验证策略和结构化角色关系，而非另建平行错因库。

### 3.2 DiagnosisRule：区分规则

规则不只是 trigger + probe 文本，而是可执行的候选区分表：

```text
diagnosis_rule_revision_id
applicability
candidate_error_causes[]
trigger_conditions[]
probe_spec
outcome_bins[]
relation_matrix[]
discriminates_pairs[]
burden_cost
stop_policy
provenance
```

`relation_matrix` 明确每个 outcome bin 对每个候选的意义：`supports | counters | non_discriminating`，并由规则指定证据级别，而不是由运行时代码猜测。

### 3.3 DiagnosticClaim：本题假设空间

每个 `QuestionSession` 可以有 0..n 个 Claim：

```text
diagnostic_claim_id
question_session_id
trigger_evidence_refs[]
candidates[]             error_cause_revision_id + prior rationale
active_rule_revision_id?
status                   open | concluded | inconclusive | skipped | unclassified
conclusion_refs[]
created_at / closed_at
```

Claim 是本题内的“待区分问题”，不等于学生长期错因状态。即使本题 concluded，也只是在账本中增加证据，长期 `C_e` 仍由跨事实 reducer 决定。

### 3.4 ErrorEvidence：追加证据

每个候选分别记录关系，绝不只保存“最终 topCandidate”：

```text
error_evidence_id
student_id
error_cause_revision_id
diagnostic_claim_id?
question_session_id
question_revision_id
relation                 supports | counters | non_discriminating
kind                     spontaneous_error | probe | self_correction |
                         explanation | near_transfer | far_transfer |
                         delayed_verification | teacher_confirmation |
                         teacher_correction
quality                   weak | strong | decisive
independent               boolean
hint_level
context_facets            题型、表示、难度、答题形式、方法、步骤
evidence_refs[]
rule_revision_id?
judgment_id?
model_id / prompt_version / policy_version
created_at
supersedes_error_evidence_id?
```

`quality` 由发布的诊断规则 outcome bin 或人工权限映射，不允许模型随意报 0.87 置信度后直接控制状态。

### 3.5 ErrorPatternProjection 与 ErrorAnnotation

长期科学投影：

```text
ErrorPatternProjection
  student_id
  error_cause_id
  active_definition_revision_id
  state                    suspected | confirmed | improving | resolved | superseded
  support_count
  counter_count
  independent_session_count
  recurrence_count
  verification_due_at?
  effective_evidence_ids[]
  policy_version
  projection_version
```

Dream 语义附注：

```text
ErrorAnnotation
  annotation_id
  student_id
  error_cause_revision_id
  claim
  scope
  support_refs[]
  counter_refs[]
  trend
  action_hint?
  confidence               low | medium | high
  valid_from / reviewed_at
  supersedes_annotation_id?
```

Projection 决定“状态是什么”，Annotation 解释“在什么情境下如何表现”。两者绝不互相写。每条事实仍引用精确 definition revision；只有经本体发布流程声明兼容的 revision 才能聚合到同一 stable error_cause_id，拆分/合并则走 supersession 和证据迁移审核。

## 4. 一次诊断如何进行

### 4.1 建立候选集合

候选来源按顺序组合：

1. 当前题 revision 绑定的 ErrorCause/DiagnosisRule；
2. 当前 K/T 下已发布且适用的错因；
3. 学生已有 `suspected/confirmed/improving` 且本题能区分的错因；
4. 永远保留 `unclassified`，避免强迫归类。

候选集必须小而可区分。仅仅“语义相似”但没有共同探针的候选不应同时进入一次 Claim。

### 4.2 是否值得追问

不是每次错误都应消耗学生耐心。宿主根据以下确定性条件决定是否开 Claim：

- 当前候选的不同结论会导致不同教学动作；
- 有低负担、可区分的探针；
- 当前不是学生明确要求立即看答案/切题；
- 未超过本题诊断负担预算；
- 判题本身不是 unresolved；
- 当前错误不像题目、rubric 或输入识别问题。

无可行动差异时直接教学或标记 unclassified，比伪精确诊断更好。

### 4.3 选择探针

探针目标是最大化候选分割能力，而不是继续问“你为什么这么做”。优先级：

1. 能把剩余候选分成不同 outcome bin；
2. 学生负担小；
3. 不泄露当前题完整解法；
4. 输出容易按 rubric 判定；
5. 不重复已经得到的证据。

首选内容库中版本化 DiagnosisRule；没有规则时，模型可以提出 provisional probe，但它的结果最多形成弱证据，不能单次确认长期错因。

### 4.4 探针判定与关系映射

例：原题中学生错误地写出 `A+B=C`。候选：

- `E_ANGLE_SUM`: 忘记三角形内角和；
- `E_SUPPLEMENT_CONFUSION`: 把补角关系写反；
- `E_SYMBOL_MAPPING`: 图中角标与代数符号映射错。

探针问“若 A=50°、B=60°，只求 C，不做其他计算”。规则矩阵可以是：

| outcome bin | E_ANGLE_SUM | E_SUPPLEMENT_CONFUSION | E_SYMBOL_MAPPING |
|---|---|---|---|
| 回答 70° 且能说明 180°-A-B | counters | counters | non_discriminating |
| 回答 110° | supports | supports | non_discriminating |
| 能口述内角和但仍把图中 C 指向外角 | counters | counters | supports |
| 无法判定/回答不相关 | non_discriminating | non_discriminating | non_discriminating |

模型只负责把回答归入 outcome bin 并引用证据；宿主按已发布矩阵为**每个候选**生成 ErrorEvidence。不能使用“probe correct → 第一个候选 resolved”这种快捷逻辑。

### 4.5 停止条件

满足任一条件即可结束本题诊断：

- 有 decisive 结果足以选择不同教学动作；
- 剩余候选对当前教学动作等价；
- 继续探针的信息增益低于负担；
- 达到硬上限；
- 学生请求切题/跳过；
- 判定服务不可用或证据质量不足。

结束状态可以是 `concluded`、`inconclusive`、`skipped` 或 `unclassified`。`inconclusive` 是正常科学结论，不是失败。

## 5. 长期状态 reducer

### 5.1 基本原则

- 只消费生效、授权、可追溯的 ErrorEvidence；
- 不按同一 Attempt 重复计数；
- 区分同题立即纠正、独立迁移和延迟验证；
- 状态规则版本化，变更后可全量重放；
- Dream Annotation 不进入 reducer；
- 证据相互矛盾时保留冲突，不让最后一条覆盖全部历史。

### 5.2 状态语义

| 状态 | 语义 | 最低基线条件 |
|---|---|---|
| 无记录 | 没有足够证据 | 不能显示成“无错因” |
| `suspected` | 有可行动支持，但尚未跨独立情境确认 | 至少一条有效支持；不能只有模型印象 |
| `confirmed` | 模式在独立证据或强区分规则下成立 | 通常需两个独立 Session 的支持，或 decisive 规则结果再加一个独立支持 |
| `improving` | 针对性干预后已有迁移反证，但验证策略尚未完成 | 先前 confirmed；至少一条合格 near-transfer counter evidence |
| `resolved` | 版本化验证策略已满足，近期无新支持 | 例如 near + far，或 near + delayed；取决于错因定义 |
| `superseded` | 本体定义被合并/废弃，或权威纠正表明该投影不应继续 | 必须指向替代定义或纠正事件 |

上述是基线而非写死常数。不同错因的 `VerificationPolicy` 可以要求不同情境，但政策必须在运行前发布，不能由 Dream 临时决定。

### 5.3 转移规则

```text
无记录 --support--> suspected
suspected --跨独立会话达到确认政策--> confirmed
suspected --充分反证/证据被纠正--> 无记录或 superseded
confirmed --合格迁移反证--> improving
improving --完成验证政策--> resolved
improving --再次出现强支持--> confirmed
resolved --强支持再现--> confirmed + RecurrenceRecorded
任意状态 --本体/教师权威替代--> superseded
```

复发不是第六个长期状态，而是一个追加事件和 `recurrence_count`。这样消费者仍可按 confirmed 采取干预，同时保留“曾解决后复发”的重要信息。

### 5.4 同题纠正的处理

学生在讲解后把当前题改对：

- 可为“学生能在提示下修正”提供 counter evidence；
- 不满足独立性；
- 不能单独把 confirmed 改为 improving/resolved；
- 应触发一题新的近迁移验证，而非立即宣告问题解决。

## 6. 错因如何被消费

### 6.1 即时追问

消费者：诊断规划器。

- suspected 候选之间选择最有区分力的探针；
- 已 confirmed 且当前表现完全匹配时，减少重复追问；
- 有强冲突证据时优先澄清；
- 无规则或不可行动时停在 unclassified。

输出不是“最可能错因 ID”，而是 `next_probe | conclude | stop_inconclusive` 及理由引用。

### 6.2 当前题教学

消费者：Teaching Agent。

| C_e 情况 | 教学动作 |
|---|---|
| suspected | 用不泄露标签的对比提示，顺便获取区分证据 |
| confirmed | 调用绑定的 RemediationRecipe，讲清错误表征与正确判据 |
| improving | 少讲解，多做结构相同但表征不同的近迁移 |
| resolved | 不重复贴标签，只在到期或复发时复测 |
| unclassified | 回到学生当前步骤，不编造原因 |

面向学生的语言描述行为，不宣告人格。例如内部是 `E_MISSING_SUPPLEMENT`，对学生说“你这一步把内角与外角的补角关系混在一起了，我们用一个只判断角关系的小题确认一下”。

### 6.3 下一题选择

消费者：模型选题器。科学内核先生成“建议动作”，模型结合学生自然语言意图选择具体题：

| 状态 | 建议的题目角色 |
|---|---|
| suspected | `discriminates`：能区分候选错因 |
| confirmed | `remediates`：针对性对比/重建概念 |
| improving | `verifies_near`，随后 `verifies_far` |
| resolved 且到期 | `verifies_delayed` |
| 复发 | 先快速重确认，再执行缩短版 remediation |

题目与错因的关系必须有角色，而不只是 `question.error_cause_ids[]`：

```text
evokes          容易暴露该错因
discriminates   能与指定候选对进行区分
remediates      用于纠正该错因
verifies_near   近迁移验证
verifies_far    远迁移验证
verifies_delayed 延迟验证
```

### 6.4 阶段活动与学习计划

错因状态可以生成活动目标，例如“在两个不同表征中验证补角关系”，但它不创建另一套训练流程。`LearningActivity` 只把该目标、预算和完成政策交给同一个选题/QuestionSession 流程。

计划完成度是独立投影：只有满足该计划项的题目角色和证据政策才计数；自由训练产生的科学事实仍照常更新 M/R/C_e。

### 6.5 复测调度

FSRS 只调度 K/T 保持，不为 C_e 伪造一个记忆概率。错因使用自己的 `VerificationPolicy` 产生 `verification_due_at`：

- confirmed：干预后尽快安排 near-transfer；
- improving：安排 far-transfer 或 delayed verification；
- resolved：按复发风险和绑定 K/T 的保持到期插入低频验证；
- 新支持出现：取消旧完成标记并重新打开。

### 6.6 Dream

Dream 的错因消费分三层：

- Light：把本题 Claim、各候选正反证据、干预和结果整理成证据原子；
- REM：发现重复、情境特异、矛盾、长期 unclassified 和“题目/规则可能有问题”的模式；
- Deep：写 `ErrorAnnotation` 或提出新的 ErrorCause/DiagnosisRule 内容候选。

Deep 不能把 suspected 改成 confirmed，也不能用一段总结替代 ErrorEvidence。

### 6.7 学生报告

报告遵循“行为—范围—下一步”，而不是“标签—分数”：

```text
在需要自行识别外角的题中，你两次把补角对象对应错；
给出标准内角图时能正确处理。下一步将用一题不同图形的近迁移确认。
```

只有 confirmed 才默认展示为“当前需要处理的问题”；suspected 应写“还需确认”。报告可链接证据，但不暴露模型隐藏推理。

### 6.8 教师视图

教师需要看到：

- 错因定义和当前 revision；
- 时间线上的 supports/counters/non_discriminating；
- 每条证据的题目、Attempt、提示等级、规则和模型版本；
- reducer 为什么处于当前状态；
- 下一项 remediation/verification；
- 纠正、合并、supersede 和重放入口。

教师的纠正新增权威证据并触发重放，不直接编辑一行状态值。

### 6.9 内容与规则改进

跨学生聚合必须区分三种情况：

1. 多名学生在多题重复同类错误：可能需要新错因或新 remediation；
2. 多名学生只在同一道题出现异常：优先怀疑题目、图形或 rubric；
3. 某探针经常 non_discriminating：DiagnosisRule 区分能力不足。

REM/Deep 可以生成 `ContentInsightProposal`，但必须进入教师/内容审核，不直接发布本体。

### 6.10 分析与评估

错因系统的目标不是最大化“有标签率”，而是最大化可行动、可验证的正确结论。核心指标：

- top-k 候选覆盖率与 unclassified 率；
- confirmation precision / false confirmation；
- 教师 overturn rate；
- 每次 conclusion 的探针数与学生耗时；
- DiagnosisRule outcome 的实际区分度；
- remediation 后 near/far transfer lift；
- resolved 后复发率和时间；
- 状态校准：suspected/confirmed 对未来匹配错误的预测能力；
- 同题重复证据误计率必须为 0。

## 7. 需求变化与错因

学生随时可以说“别追问了，换道题”“我只想看解法”。系统应：

1. 停止继续探针；
2. 把当前 Claim 关闭为 `skipped` 或 `inconclusive`；
3. 保存已经产生的 supports/counters，不伪造结论；
4. 完成切题硬事务；
5. 将新需求写入最新 SelectionIntent。

错因诊断服务学习，而不是绑架对话。

## 8. 失败和冲突场景

| 场景 | 正确处理 |
|---|---|
| 模型无法判探针 | 写 unresolved/non_discriminating，必要时转人工，不确认任何候选 |
| 诊断规则版本在本题中途发布新版 | QuestionSession 继续使用冻结 revision；下一题使用新版 |
| 两条证据相互冲突 | 同时保留；reducer 按质量/独立性/时间政策投影，REM 标记冲突 |
| 教师指出题目 rubric 错 | supersede 相关 Judgment/Observation/ErrorEvidence，重放所有投影 |
| 错因本体被拆分 | 旧状态 superseded；证据按审核映射到新 revision，不能静默复制 |
| 同一答案同时暴露知识失败和错因 | M 消费一次逐维度 Observation；C_e 消费关系证据；Dream 不再数值加权 |
| 外部题无可靠规则 | 只保留 provisional 语义证据，不能 confirmed |
| Dream 认为状态应改变 | 只能写附注/建议验证，等待新事实使 reducer 改变 |

## 9. 当前实现的直接问题与目标替代

| 当前行为 | 问题 | 封版目标 |
|---|---|---|
| `closeChain` 取 Claim 第一个 candidate 写 suspected，冲突时 `DO NOTHING` | 丢失反证、积累和状态转移 | 写逐候选 ErrorEvidence，再由 reducer 重放 |
| 探针答对即把第一个候选设为 resolved | 正确回答与候选关系没有逻辑保证 | outcome bin × candidate relation matrix |
| TSS 写 `{claim_id,status}` 到 misconception candidates | 与既有 schema 的 `error_cause_id/supporting_refs` 不一致 | TSS/Light 直接引用规范 ErrorEvidence |
| Dream 输出 `misconception_updates` 并覆盖状态 | 模型越权，无法稳定重放 | 删除该写路径；Dream 只写 ErrorAnnotation |
| `state_misconception_state.evidence_refs` 是无类型数组 | 无法区分支持、反证、独立性和来源 | 追加式 `ErrorEvidence` 表 + 派生 projection |
| question 与 E 只有泛关联 | 选题不知道是诊断、干预还是验证 | 增加结构化 `QuestionErrorRole` |

## 10. 最小实现切片

第一切片只需完成以下闭环，不必一次构建复杂自动发现：

1. 为已发布 E/R 增加 relation matrix 与 verification policy；
2. 新增 append-only ErrorEvidence；
3. 实现可重放 reducer；
4. 修正 probe 映射；
5. 让 Teaching/Selection 消费状态和题目角色；
6. 让 Light 读取 ErrorEvidence；
7. 禁止 Dream 写错因状态；
8. 增加教师时间线和 supersede API。

自动聚类新错因、跨学生内容洞察和更复杂的规则质量学习可以在闭环稳定后加入，但它们只能生成审核候选。

## 11. 验收用例

必须至少通过：

1. 一个探针结果同时反对候选 A、支持候选 B，系统生成两条关系正确的证据；
2. 同题提示后改对不会把 confirmed 直接改成 improving；
3. 两个独立 Session 的支持按政策确认错因；
4. near + far 验证按该错因政策进入 resolved；
