# 07. 前端设施、后端读模型与统一交互语言

> 状态：科学内核与 Dream 的用户呈现权威设计
> 日期：2026-08-31
> 范围：对话内学习交互、个人学习记录、科学状态、复习安排、Dream 记忆、证据查看，以及直接相关的教师审计视图

## 1. 目标与边界

科学内核、错因和 Dream 只有在用户能看懂、追溯和纠正时才算完整。这里设计的不是一组孤立卡片，而是以下闭环：

```text
领域事实 / 科学投影 / Annotation
             │
             ▼
后端面向界面的读模型
             │
     ┌───────┴────────┐
     ▼                ▼
规范消息部件       个人学习空间
assistant-ui       记录 / 状态 / 记忆 / 复习
     │                │
     └───────┬────────┘
             ▼
        有权限的领域命令
             │
             └──► 新事实、投影与消息
```

本设计遵循三个边界：

1. 学习仍以普通对话为主，不增加“诊断模式”“画像模式”“Dream 模式”等前端状态机；
2. 个人学习空间是同一批事实的可读投影，不是第二套学习流程或第二套状态；
3. 本文只覆盖科学内核与 Dream 的直接前端，不重做账号、内容生产、班级运营和全站品牌设计。

## 2. 封版决策

| 问题 | 决策 | 原因 |
|---|---|---|
| 学习主入口是什么 | 普通 ConversationThread | 允许学生自然提问、修改要求、答题和换题 |
| 记录、状态和记忆是否都塞进聊天 | 否 | 高频即时信息留在对话；需要筛选、比较和追溯的内容进入个人学习空间 |
| assistant-ui 负责什么 | Thread、Message、Composer、Attachment、ActionBar、Branch、Suggestion、结构化消息渲染 | 复用现有成熟交互和无障碍语义 |
| assistant-ui 是否保存科学状态 | 否 | Runtime 是视图运行时，不是领域事实源 |
| 正式题卡和判定卡由谁产生 | 后端领域事件投影器 | 模型不能伪造“已开题”“已判定”“状态已更新” |
| 模型能否继续生成 UI | 能，但只用于非权威教学产物 | 使用有界 Generative UI 词表，不承载 M/R/C_e 或 Annotation 写入 |
| 页面是否直连原始事实表 | 否 | 后端按使用场景组装版本化读模型，前端不自行拼接科学语义 |
| 学生默认看到精确概率吗 | 默认看可解释状态和下一步；精确程序值放在展开详情并带校准说明 | 避免把 `prior_only` 显示成精确教育结论 |
| 科学状态和 Dream 记忆如何呈现 | 并排、分栏、不同标签 | Annotation 解释情境，不能覆盖程序状态 |
| 学生能否修改记忆 | 不能直接改写；可以查看依据、报告不准确、暂停用于个性化 | 保留来源和 supersession，同时给用户实际控制权 |
| 历史消息能否随意编辑或重生成 | 普通未消费消息可以；已成为证据或领域事件的消息锁定 | assistant-ui 的编辑/分支能力不能破坏追加事实 |

## 3. 总体前后端结构

### 3.1 三条读路径，一条写路径

```text
PostgreSQL 规范事实
  ├── reducer / projector ──► M / R / C_e / Annotation 投影
  ├── MessageProjector ─────► CanonicalMessage + DomainUIPart
  └── ReadModelAssembler ───► 页面和侧栏 View

CanonicalMessage ──► External Store adapter ──► assistant-ui
Page View ─────────► server-state cache ───────► 学习记录页面
Outbox cursor ─────► 授权事件流 ───────────────► 消息追加 / resource invalidation

用户动作 ─────────► Command API ──► 领域服务或 Temporal Workflow
```

只有 Command API 可以发起领域写入。组件不得直写 projection，不得把本地状态当成“已经提交”，也不得通过向模型追加一段 JSON 文本来模拟领域事务。

### 3.2 前端状态所有权

| 状态 | 唯一所有者 | 前端使用方式 |
|---|---|---|
| 当前 Thread 的消息、流式状态、输入草稿 | MathPilot canonical messages + assistant-ui External Store | assistant-ui Runtime 渲染；应用负责加载和提交 |
| Thread 列表、路由、归档、标题 | MathPilot 应用壳 | 不依赖 deprecated 的 External Store thread-list adapter |
| 当前 QuestionSession、选题意图、切题操作 | 后端领域服务 | `ThreadContextView` 只读展示，动作走 command capability |
| M/R/C_e | 版本化科学投影 | 页面和卡片读取，永不在浏览器重算 |
| Dream Annotation | Annotation 账本 | 页面读取；反馈和暂停使用是新命令，不原地编辑 |
| 展开/收起、筛选、未提交表单值 | React 局部状态 | 不持久化为领域事实 |
| 页面请求缓存、重试和失效 | 统一 server-state 数据层 | 不在每张卡中各写一套 `useEffect(fetch)` |

assistant-ui External Store 的 `state`/`extras` 只可携带当前 Runtime 的展示辅助信息，不能成为学习状态的隐蔽数据库。

### 3.3 规范消息与 UI 部件

应用消息保持框架无关：

```text
CanonicalMessage
  message_id
  conversation_thread_id
  sequence
  author_kind          student | assistant | system
  lifecycle            streaming | committed | failed | superseded
  parts[]               text | attachment | domain_ui | teaching_artifact
  reply_to_message_id?
  question_session_id?
  editable              boolean
  lock_reason?
  created_at
```

权威卡片使用输出专用部件：

```text
DomainUIPart
  schema                mathpilot.message-part/domain-ui/v1
  part_id
  view_kind             question | answer_receipt | judgment | probe |
                        question_closure | learning_update |
                        memory_update | review_due | activity_milestone
  resource_ref
  resource_version
  snapshot              当时可见、已脱敏的不可变视图
  action_slots[]         允许出现哪些动作位置，不含可执行 URL/令牌
  occurred_at
  origin                domain_projector
```

External Store 的 `convertMessage` 将 `DomainUIPart` 转为 assistant-ui 可渲染的结构化 part。首版可使用保留命名空间的完成态 tool-call envelope，例如 `mathpilot.ui.question`；它只是展示协议：

- 不出现在 Agent 的工具定义中；
- 不接受模型自行构造的同名调用；
- `resource_ref + version` 必须能在服务端验证；
- renderer 只消费投影器给出的脱敏 payload；
- 未识别 schema 使用安全 fallback，不渲染原始 JSON。

这既复用 assistant-ui 的 typed tool UI/parts 渲染，又不把“UI part”误当成 Agent 权限工具。

可执行 `command_capabilities` 不持久化在历史快照中。`ThreadMessagesView` 每次读取时根据当前 actor、资源状态和版本为消息/part 叠加能力；过期历史卡因此自然只读，不会留下可重放的旧 URL 或权限令牌。

### 3.4 历史快照与当前状态

消息是“当时发生了什么”，页面是“现在状态是什么”，两者不能互相覆盖：

- Question、AnswerReceipt、Judgment、Closure 保存事件发生时的可见快照，重放历史时不随今天的状态改写；
- “状态已更新”消息只保存当时的变化摘要，并链接当前详情；
- 当前 M/R/C_e、Annotation 是否仍生效、复习是否到期由页面读模型返回；
- Judgment 被教师 supersede 后，旧卡仍可见但标为“后来已更正”，并链接新卡；
- message projector 以 `domain_event_id + view_kind` 幂等，重试不能产生两张相同卡。

## 4. 后端读模型契约

### 4.1 统一 envelope

所有学习读接口返回统一元信息：

```ts
type LearningView<T> = {
  schema: string;
  resource: {
    kind: string;
    id: string;
    version: number;
  };
  generated_at: string;
  facts_through: string;
  projection_status: "ready" | "updating" | "rebuilding" | "unavailable";
  freshness_note?: string;
  permissions: string[];
  redactions?: string[];
  data: T;
};
```

规则：

- `version` 同时用于 ETag、乐观并发和客户端失效判断；
- `facts_through` 说明投影覆盖到哪个事实时间，不用一个无限 spinner 掩盖延迟；
- `rebuilding` 返回上一份有效结果和明确提示，不回落成全零；
- `permissions` 是服务端算出的能力，不由前端角色名推断；
- 学生 ID、tenant ID 从认证上下文推导，客户端不能借 URL 越权指定；
- evidence link 使用有权限的 opaque handle，前端不自行拼数据库主键。

### 4.2 读模型与消费者

| 读模型 | 核心内容 | 主要消费者 |
|---|---|---|
| `ThreadMessagesView` | 规范消息、游标、流式占位、编辑锁 | assistant-ui External Store |
| `ThreadContextView` | 当前题、当前 intent、切题/选题 operation、相关 Annotation、本轮 Agent 参考清单 | 对话右侧栏或移动 Sheet |
| `QuestionInteractionView` | 冻结题目、回答形式、提交状态、证据说明、选择理由 | QuestionCard |
| `JudgmentView` | verdict、rubric、uncertainty、证据链接、supersession | JudgmentCard |
| `QuestionClosureView` | 关闭原因、产生/未产生的事实、科学影响摘要、下一步 | QuestionClosureCard、历史条目 |
| `LearningOverviewView` | 当前最值得做的事、活动进度、到期复习、最近重要变化 | 个人学习空间首页 |
| `LearningHistoryView` | 按 QuestionSession 分组的游标时间线 | 学习历程页 |
| `ScientificStateView` | 维度的 M、R、证据量、校准状态、关联 Annotation | 学习状态页 |
| `ErrorPatternListView` | C_e 行为描述、状态、验证计划、复发提示 | 状态页、复习页 |
| `MemoryLedgerView` | 当前 Annotation、状态、范围、正反证据摘要、使用偏好 | “系统记住的内容”页 |
| `AnnotationDetailView` | claim、scope、support/counter、版本链、使用记录 | 记忆详情 |
| `ReviewQueueView` | FSRS 到期项、错因验证项、推荐顺序 | 复习安排页、ReviewDueCard |
| `EvidenceBundleView` | 题目、Attempt、Judgment、提示等级、关系、来源版本 | Evidence Drawer/详情页 |
| `LearningActivityView` | 目标、来源、预算、完成政策和证据进度 | 活动进度组件 |
| `AgentContextManifestView` | 本轮实际提供给前台 Agent 的授权材料和新鲜度 | “本轮参考内容”面板 |

这些是按界面任务组装的 read model，不是把所有表做一层 CRUD API。一个页面可以一次取得首屏所需内容，证据和长时间线再按需分页。

#### 4.2.1 关键 View 的必需形状

以下是语义下限，最终以 `src/packages/contracts` 中的 JSON Schema 为准。

```ts
type CommandCapability = {

  href: string;

    revision_id: string;
    source: "catalog" | "student_external" | "generated_provisional";
    prompt_parts: Array<
      | { type: "text"; text: string }
      | { type: "image"; src: string; alt: string }

    response_kind: "single_choice" | "multiple_choice" | "fill_blank" |

    summary: string;

    compromises: string[];
  };
```

### 4.3 学生可见投影与内部投影

同一事实有不同权限投影，但不能有不同结论：

| 内容 | 学生 | 有授权教师 | 运维/审核 |
|---|---|---|---|
| 行为结论与下一步 | 是 | 是 | 是 |
| 精确程序值与 `calibration_status` | 展开后可见 | 默认可见 | 可见 |
| 题目、本人回答、rubric 证据 | 是 | 是 | 按权限 |
| 内部 K/T/E code、policy/model/prompt version | 技术详情内可见或脱敏 | 可见 | 可见 |
| Annotation 正反证据和版本链 | 是 | 是 | 是 |
| LightAtom、REM 未晋升候选 | 否 | 默认否 | 审核权限可见 |
| DreamRun diff、preimage、拒绝原因 | 否 | 仅特权审核 | 是 |
| 模型隐藏推理、系统 Prompt、凭据 | 永不 | 永不 | 永不通过产品读接口 |

“可解释”指提供证据、规则、版本和结果，不等于泄露 chain-of-thought。

### 4.4 查询接口

建议的 BFF 资源边界：

```text
GET /api/learning/threads/:threadId/messages?after=<cursor>
GET /api/learning/threads/:threadId/context

GET /api/learning/me/overview
GET /api/learning/me/history?after=<cursor>&kind=<filter>
GET /api/learning/me/state?kind=knowledge|question_type|error
GET /api/learning/me/memories?after=<cursor>&status=active
GET /api/learning/me/reviews?after=<cursor>

GET /api/learning/question-sessions/:questionSessionId
GET /api/learning/activities/:activityId
GET /api/learning/evidence/:evidenceHandle
GET /api/learning/annotations/:annotationId
```

教师使用同一组 view assembler，但路由由授权学生资源确定，例如 `/api/learning/students/:studentHandle/...`；不能在前端复制一套不同的科学解释逻辑。

### 4.5 命令接口

前端只需要少量明确动作：

```text
POST /api/learning/question-sessions/:id/attempts
POST /api/learning/question-sessions/:id/cut-requests
POST /api/learning/threads/:id/intent-revisions
POST /api/learning/reviews/:id/start
POST /api/learning/annotations/:id/feedback
POST /api/learning/context-preferences
POST /api/learning/operations/:id/cancel
```

共同要求：

- mutation 带 `Idempotency-Key` 和读模型给出的 `expected_version`；
- 回包是已提交资源或 `OperationView`，不是一句无法恢复的“成功”；
- capability 过期、Session 已关闭或版本冲突返回可解释问题详情；
- 无任何 `/mastery/set`、`/error-pattern/update-state`、`/memory/edit` 之类越权接口；
- 教师纠正使用第 01/02 文档定义的 supersession 命令，不直接改 projection 行。

### 4.6 事件流

消息流和页面刷新共用一个带游标的授权事件通道，事件只传引用和版本：

```text
canonical_message.appended
canonical_message.updated
learning_resource.changed
learning_operation.changed
```

事件最小字段为 `event_id`、`cursor`、`resource_key`、`resource_version`、`occurred_at`。处理方式：

- message 事件交给 External Store 合并；
- resource 事件使统一 server-state cache 按 key 失效；
- operation 事件更新 `aria-live` 状态并在完成后拉取新资源；
- 断线用 last cursor 补拉，不能假设 SSE 永不丢包；
- payload 不广播回答正文、记忆内容或跨学生 PII。

### 4.7 一致性与降级

| 情况 | 界面行为 |
|---|---|
| 消息已提交但 HTTP 回包丢失 | 相同 idempotency key 查询到同一 Attempt；事件流补回 canonical message |
| 页面 projection 稍后才更新 | 保留上一有效值，显示“记录正在更新”，不阻塞继续聊天 |
| Judgment 暂时失败 | 显示“尚未形成正式判定”，允许继续解释或按硬路径明确关闭 |
| Dream 失败 | 旧 Annotation 保持；学生只看到“学习记忆尚未更新”，不出现空白覆盖 |
| 卡片 schema 新于前端 | 安全 fallback 显示标题、时间和“更新应用后查看”，不输出原始 payload |
| 多设备同时提交 | 服务端只接受一个匹配 Session/version 的生效 Attempt；另一端转为只读收据 |
| 网络离线 | 保留输入草稿和已加载历史；命令明确禁用或可重试，不乐观伪造科学结果 |

## 5. 信息架构与响应式应用壳

### 5.1 路由结构

```text
/                         新对话
/c/:threadId              普通学习对话

/learning                 个人学习概览
/learning/history         学习历程
/learning/state           学习状态与错因
/learning/memory          系统记住的内容
/learning/review          复习安排

/learning/evidence/:ref   可分享给同账号的稳定证据详情
```

`/learning/*` 是一个“个人学习空间”，导航项使用真实链接，保留浏览器前进、后退和深链；不要实现成一个无法定位的巨大弹窗，也不要继续在 `app.tsx` 里累加正则路由分支。具体路由库属于 Web 基础设施选型，但必须复用成熟实现，不手写浏览器路由器。

### 5.2 对话页

桌面目标结构：

```text
┌───────────────┬──────────────────────────────┬──────────────────┐
│ 应用侧栏       │ assistant-ui Thread          │ 学习上下文        │
│ 新对话         │ 普通消息                     │ 当前题            │
│ 学习记录入口   │ 题卡 / 判定 / 教学产物       │ 本轮目标          │
│ Thread 列表    │ Composer                     │ 相关记忆与依据    │
│ 账户           │                              │ 查看全部记录      │
└───────────────┴──────────────────────────────┴──────────────────┘
```

- 中列继续使用当前 `--thread-max-width: 44rem` 的阅读宽度；
- 右栏不是实时 debug 面板，只显示当前题、当前活动、最多三条真正注入本轮的相关记忆和异步操作；
- 右栏的“本轮参考内容”来自 `AgentContextManifestView`，不是前端猜测；
- 任何复杂选题要求仍可直接在 Composer 中说，不要求打开选题表单；
- `调整要求`、`换一题` 等按钮只是普通领域命令的快捷入口，不形成独立模式。

### 5.3 个人学习空间

一级标题统一为“学习记录”，下设五个链接：

1. **概览**：下一项最值得做的事、正在进行的活动、到期复习、最近一到三条重要变化；
2. **学习历程**：以 QuestionSession 为单位还原题目、回答、提示、判定、科学影响和所在对话；
3. **学习状态**：分别查看掌握状态、提取风险和错因验证，不做一个混合总分；
4. **系统记住的内容**：查看 Deep 已发布 Annotation、范围、依据、反例与使用状态；
5. **复习安排**：合并 FSRS 到期项与错因 verification 项，但明确标注两种来源。

概览只回答“现在做什么”和“最近发生了什么”，不铺满统计图。长时间趋势不是首版必需；没有真实比较价值时不引入图表库。

### 5.4 证据详情

证据详情在桌面作为可深链的右侧 Sheet/Dialog，在手机作为全页打开。它应展示：

- 题目和冻结 revision；
- 学生当时提交的内容或获授权的草稿片段；
- 提示等级和是否独立；
- Judgment rubric 与引用；
- 该证据对 M、R、C_e 或 Annotation 的具体关系；
- supersession 和版本信息；
- 返回原 ConversationThread 对应消息的链接。

不展示隐藏推理。若证据已被纠正，顶部首先显示替代结论，不让用户从旧页面误判当前状态。

### 5.5 教师复用

教师查看学生时复用相同的 State、Memory、History、Evidence 组件，只改变：

- actor banner 明确“正在查看哪位学生”；
- 展开显示内部 code、规则和版本；
- 根据权限增加“提交纠正”“请求复核”等命令；
- 所有纠正都创建新事实并触发重放。

不得复制一个教师专用 reducer，也不得让教师 UI 直接编辑 `p_mastery`、FSRS Card 或 ErrorPattern state。

### 5.6 响应式规则

| 视口 | 对话 | 个人学习空间 |
|---|---|---|
| `>= 1180px` | 左侧栏 + Thread + 可折叠上下文栏 | 左导航 + 最大 72rem 主内容；详情可右侧展开 |
| `721–1179px` | Thread 为主，侧栏和上下文分别进入 Sheet | 双列摘要，证据详情进入 Sheet |
| `<= 720px` | 单列 Thread；顶栏提供会话与记录入口；Composer 独占底部安全区 | 单列；分区链接可横向滚动或折叠；详情走全页 |

移动对话页不再叠加一个固定底部导航和固定 Composer。记录入口放在顶栏/侧栏 Sheet；在个人学习页面才显示页面级导航。最小验收视口为 `390×844`，同时回归 `375px` 极窄宽度。

## 6. assistant-ui 复用边界

### 6.1 直接复用

| 需求 | assistant-ui/现有实现 |
|---|---|
| 消息滚动、锚点、自动到底 | `ThreadPrimitive.Root/Viewport/Messages/ScrollToBottom` |
| 消息与分段渲染 | `MessagePrimitive.Root/GroupedParts/Parts/Error` |
| 输入、发送、取消、附件 | `ComposerPrimitive` + 现有 `UnifiedAttachmentAdapter` |
| 消息动作 | `ActionBarPrimitive`、`ActionBarMorePrimitive` |
| 普通对话分支 | `BranchPickerPrimitive`，但受领域锁限制 |
| 建议入口 | `SuggestionPrimitive` |
| 条件状态 | `AuiIf`、`useAuiState`，仅用于 Runtime 展示状态 |
| Thread 导航外观 | 现有 `ThreadList` 与 sidebar 组件；数据源改为应用持有 |
| 结构化消息 UI | typed tool UI/`MessagePrimitive.Parts` renderer |
| 非权威教学布局 | 当前有界 `@assistant-ui/react-generative-ui` 词表 |

若 app-owned Thread 列表无法通过当前受支持的 Runtime API 接给 `ThreadListPrimitive`，就保留现有 Sidebar、Button、Menu、focus 和视觉结构，用普通有语义的链接列表绑定应用数据；不能为了“全用 primitive”重新引入 deprecated adapter。

### 6.2 两类 UI registry

前端 registry 必须拆开：

```text
domainPresentationRegistry
  mathpilot.ui.question
  mathpilot.ui.answer_receipt
  mathpilot.ui.judgment
  mathpilot.ui.probe
  mathpilot.ui.question_closure
  mathpilot.ui.learning_update
  mathpilot.ui.memory_update
  mathpilot.ui.review_due

teachingArtifactRegistry
  一个经验证的 artifact 展示入口
  内含 Card / Col / Row / Header / Text / Markdown / Fact / Alert 等白名单
```

前者只由 MessageProjector 发出；后者允许 Agent 在教学回复中组合低风险内容。两者不可共用“present_xxx”模型工具名，否则 UI 权威边界又会变模糊。

### 6.3 Generative UI 的限制

当前 `TeachingGenerativeUI` 和白名单组件可以继续使用，但：

- 只解释概念、步骤、对比和已验证教学 artifact；
- 不显示“你已掌握”“错因已确认”“记忆已更新”等权威声明；
- 不发领域命令，不接任意 JavaScript/HTML；
- Markdown 继续安全渲染，数学继续使用本地 KaTeX；
- sandboxed HTML artifact 保持 CSP、sandbox 和已发布 URI 校验；
- 生成失败退化为普通文本，不阻塞 QuestionSession。

### 6.4 编辑、分支和导出限制

assistant-ui 的通用能力要服从证据账本：

| 消息 | 编辑 | 分支/重生成 | 删除 | 正确替代方式 |
|---|---:|---:|---:|---|
| 尚未被消费的普通用户文本 | 可 | 可 | 可 | 常规消息操作 |
| 已形成 Attempt/Intent 的用户消息 | 否 | 否 | 否 | 新增补充、纠正或切题请求 |
| 普通教学解释 | 否原地改写 | 可请求“换种讲法”，生成新消息 | 否 | 保留两种解释和上下文 |
| Question/Judgment/Closure 等领域消息 | 否 | 否 | 否 | supersession 后显示新事件 |
| Dream 记忆更新通知 | 否 | 否 | 否 | Annotation feedback/supersession |

因此 `ThreadMessagesView` 的 message item 必须携带实时 action capabilities；ActionBar 和 BranchPicker 按消息能力渲染，不能只按 role 决定。Markdown 导出需要为 DomainUIPart 提供用户可读 serializer，不得把内部 JSON、opaque handle 或未授权证据导出。

### 6.5 对现有代码的迁移映射

| 当前代码 | 目标处理 |
|---|---|
| `PiRuntimeProvider.tsx` 直接使用 `usePiRuntime` | 收敛为 app-owned Thread External Store；Pi Epoch 留在后端 Runtime |
| `thread.aui.tsx` | 保留主要 Thread/Message/Composer 结构，增加 domain part renderer 和 action capability gating |
| `thread-list.aui.tsx` | 保留可访问交互和样式，数据与路由改由应用壳持有 |
| `learning-toolkit.tsx` | 拆成权威 presentation registry 与单一教学 artifact renderer |
| `question-card.tsx` | 移除本地“已提交即成功”和 JSON 文本 append；改走 Attempt Command 和服务端收据 |
| `teaching-generative-ui.tsx` | 保留有界教学用途，禁止科学结论 |
| `surfaces.tsx` | 作为所有新学习组件的表面、按压、折叠和 motion 语言基础 |
| `components/ui/*` | 继续复用 Button、Dialog、Sheet、Collapsible、Tooltip、Skeleton 等封装 |

新代码应主要是读模型 adapter、少量领域卡 renderer 和页面组合，不建设另一套聊天框架、组件库、动画系统或客户端状态机。

## 7. 对话内组件规格

### 7.1 统一卡片骨架

所有权威卡片共享 `LearningCardShell` 概念，而不是每张重新决定样式：

```text
语义 section/article
  ├── 类型图标 + 标题 + 状态文字
  ├── 一句话结论或任务
  ├── 主体内容
  ├── 可选 Disclosure：依据 / 程序详情
  ├── 最多一个主动作 + 一个次动作 + overflow
  └── 时间、来源和当前/历史状态
```

共同规则：

- 默认与 assistant 消息正文同宽，最大 `max-w-2xl`；
- 使用 `bg-card`、`border-border/60`、`rounded-2xl` 和克制 `shadow-sm`；
- 卡内不再套多层完整 Card，次级信息使用 `field` surface、分隔线或列表；
- 状态必须有文字和图标，颜色只是辅助；
- 展开依据不抢占首屏；
- 运行态用 `aria-busy`，只让当前操作通过 `aria-live=polite` 宣告；
- 错误用 `role=alert`，不能只有红边框；
- 所有按钮从服务器 capability 得到是否可用和原因。

### 7.2 QuestionCard

QuestionCard 是 `QuestionOpened` 的投影，不是模型调用 `present_question_card` 的结果。至少显示：

- 题干、必要图像和数学公式；
- 来源/临时题说明；
- 当前题为何符合用户要求的简短说明；
- 若是阶段活动，显示“本轮目标”而非“阶段模式”；
- 回答控件、允许跳过与否、正式证据资格提示；
- 当前服务端状态：`open | submitting | submitted | closed | stale`。

交互要求：

- 单选使用真正的 radio group，多选使用 checkbox 语义，不用一组仅有 `aria-pressed` 的按钮模拟；
- 提交时携带 QuestionSession、题目 revision、expected version 和 idempotency key；
- 提交成功以服务端 `AnswerReceipt` 为准，跨设备自动禁用旧卡；
- “改用文字回答”只聚焦并预填 Composer，不提前记录 bypass；实际文本发送后才形成 Attempt；
- “跳过”产生显式 CutRequest/skip 事实，不伪装成答错；
- 临时题若不能进入科学状态，要在提交前清楚说明“可正常讲解，本次不计入正式学习状态”。

### 7.3 AnswerReceipt

学生点选或填写题卡后，后端原子保存 Attempt，并生成一条用户作者的可读收据：

```text
你的回答：B、D
已提交 · 14:32
```

它取代当前把 `mathpilot.card-response/v1` JSON 追加进聊天的做法。模型通过规范 Attempt 投影获得回答，用户和导出内容只看到自然表达。重复 HTTP 请求返回同一收据，不生成第二个用户回合。

### 7.4 JudgmentCard

默认层只显示：

- `正确 / 部分正确 / 需要调整 / 尚不能判定`；
- rubric 的达成、未达成、待澄清；
- 一句基于证据的说明；
- 下一步教学动作。

展开层显示 evidence link、不确定性、是否产生 Observation、是否更新 R、model/prompt/policy version。若 `unresolved`，文案是“这次回答还不足以形成正式判定”，不能显示为错误。

教师改判后，旧卡顶部显示“此判定已于某时更正”，新 JudgmentCard 作为新消息或历史替代链接出现；不在原卡上静默换颜色。

### 7.5 DiagnosticProbeCard

探针仍表现为普通对话中的小问题：

- 学生标题为“确认一个步骤”或“再看一个小情境”；
- 不提前暴露内部错因名和候选排名；
- 只呈现一个低负担问题及回答控件；
- 可以跳过，跳过对应 `DiagnosticClaim.skipped`；
- 结果卡可以说“这一步已区分/仍不能区分”，不宣告人格标签；
- 是否构成 ErrorEvidence 由后端规则矩阵决定，前端不推断。

### 7.6 切题、选题与关闭

切题过程不做成多步 Wizard：

1. 用户直接说“换简单一点”“不要计算量大的”或点快捷按钮；
2. 当前消息下出现紧凑 `OperationStatus`：“正在保存本题记录并按新要求找题”；
3. `QuestionClosureCard` 说明本题是否形成正式判定、哪些内容只用于教学连续性；
4. 新 QuestionCard 直接进入同一 Thread；
5. 若无候选，普通 assistant 消息解释冲突并邀请修改要求。

QuestionCard 顶部可折叠显示 `SelectionIntentSummary`：满足了哪些要求、哪项因题库约束未完全满足。`调整要求` 只把焦点交给 Composer；复杂需求始终由自然语言和 Selector Agent 处理。

### 7.7 学习更新、记忆更新与复习提醒

后台变化不能冒充 Assistant 自己说的话。由 `author_kind=system` 的中性事件卡显示：

| 卡片 | 何时出现 | 默认内容 |
|---|---|---|
| `LearningUpdateCard` | 本题造成有意义的 M/R/C_e 变化 | “新增一条独立证据”“现在适合安排一次复习”等变化摘要 |
| `MemoryUpdateCard` | Deep 发布或 supersede 与当前学生直接相关的 Annotation | 新记住的一句情境观察、依据数量、查看/反馈入口 |
| `ReviewDueCard` | 用户打开相关 Thread 或主动查看安排，且确有到期项 | 到期目标、来源是保持复习还是错因验证、开始入口 |
| `ActivityMilestoneCard` | 正式活动达到里程碑或完成 | 目标进度和完成依据，不按普通自由对话刷屏 |

投影器需要通知节流：只有用户需要知道、需要行动或与刚完成题目直接相关时才进入消息；其余更新只进入个人学习空间的变化流。不能让每次 reducer 重放或每个 Dream phase 都生成聊天卡片。

### 7.8 OperationStatus

`OperationView` 统一表示选题、切题、判定和记忆反馈等异步动作：

```text
operation_id
kind
status              accepted | running | succeeded | needs_input | failed | cancelled
user_message
related_resource_refs[]
retryable
started_at / updated_at
```

UI 使用同一个小型状态组件，不为每个后台 Workflow 手写 loading/error 分支。技术性的 Temporal/Pi ID 只在有权限的技术详情中出现。

## 8. 个人学习空间组件

### 8.1 LearningOverview

首屏按行动优先级排列：

1. 一个“建议下一步”，可能是继续当前题、到期复习、完成错因验证或继续活动；
2. 当前 LearningActivity 进度；
3. 最近重要变化；
4. 学习状态、记忆、历程的简短入口。

没有数据时显示“完成几次练习后，这里会出现有依据的学习记录”，不显示 0%、空雷达图或伪造示例学生。

### 8.2 LearningHistoryTimeline

时间线以 QuestionSession 为原子，而不是把每条模型消息都当学习记录：

```text
8 月 31 日 · 正弦定理应用
  回答：部分正确 · 使用 1 次提示
  记录：未计入独立掌握；形成一条错因支持证据
  状态：本题已完成
  查看对话 · 查看依据
```

- 每页 20–50 条、cursor pagination 和显式“加载更多”；首版不手写虚拟滚动；
- 过滤项是“全部 / 独立作答 / 复习 / 错因验证 / 状态变化”，不暴露数据库表名；
- 每项能跳回 `/c/:threadId#message-...`；
- 清楚解释“为什么本次没有更新掌握状态”，例如提示后成功、外部题无 rubric 或判定 unresolved；
- superseded 记录仍在时间线上，但有更正链接。

### 8.3 ScientificStateView

维度列表每行同时但分开显示：

```text
正弦定理的选择与使用
  掌握记录：正在形成        独立证据 3 次
  复习状态：建议 9 月 2 日前复习
  学习观察：标准图形稳定；需自行补线时容易停住
```

默认不把多个维度塞成一个总分。展开“程序详情”才显示 `p_mastery`、retrievability、parameter set、calibration status 和 projection time。`prior_only` 必须解释为“尚未用本地学生样本校准的程序基准”。

Annotation 以“学习观察”单独出现，绝不画成覆盖程序值的第二条概率条。

### 8.4 ErrorPatternView

学生文案遵循“行为—范围—下一步”：

| 内部状态 | 学生标题 | 默认动作 |
|---|---|---|
| `suspected` | “还需确认：在……时可能容易……” | 做一题区分性小题 |
| `confirmed` | “当前需要处理：在……时会……” | 针对性讲解/练习 |
| `improving` | “正在改善：已在近迁移中做到……” | 远迁移或延迟验证 |
| `resolved` | “近期已通过验证” | 低频复查；不持续贴标签 |
| recurrence event | “最近再次出现，需要快速确认” | 缩短版重确认 |
| `superseded` | 仅历史中显示“定义或判定已更新” | 跳转替代项 |

`non_discriminating` 是一条证据关系，不向学生显示成失败。只有 confirmed 默认进入“当前需处理”，suspected 不可用确定语气。

### 8.5 MemoryLedger

学生页面标题使用“系统记住的内容”，不要求用户理解 Light/REM/Deep。只显示 Deep 已发布且仍有权限的：

- **知识/题型观察**：DimensionAnnotation；
- **容易出错的情境**：ErrorAnnotation；
- **适合你的学习方式**：合规 StudentTraitClaim；
- ContentInsightProposal、LightAtom 和 REMThemeCandidate 不进入个人记忆页。

每条 `MemoryNote` 显示：

```text
观察
  需要自行补线时，你更容易停在建模步骤。
范围
  解三角形 · 隐含辅助线 · 中等难度
依据
  来自 3 次学习记录，含 1 条不同表现
状态
  正在用于个性化 · 8 月 31 日复核
动作
  查看依据 · 这不准确 · 暂不用于个性化
```

不默认显示一个伪精确置信百分比；证据次数、情境范围和反例比“87% 确信”更有意义。详情页可显示 low/medium/high、版本链和 review due。

### 8.6 记忆反馈与使用控制

学生操作不是直接改 Annotation：

- `这不准确`：新增 `AnnotationFeedback(needs_review)`，进入 REM/Deep 或人工复核；原注显示“正在复核”；
- `暂不用于个性化`：新增用户级 `AnnotationUsagePreference(muted)`，WorkspaceProjection 立即排除该注，但证据账本仍保留；
- `恢复使用`：新增后继 preference；
- 删除账户数据属于通用隐私系统，不由 MemoryNote 私自删除历史事实；
- 教师/审核的撤销产生 supersession，不能覆盖原文本。

如果反馈处理失败，Annotation 仍保持原状态并明确可重试，不能在浏览器先隐藏后永久丢失。

### 8.7 AgentContextTransparency

对话上下文栏提供“本轮参考内容”：

- 当前 QuestionSession 与题目 revision；
- 当前 LearningActivity/SelectionIntent 摘要；
- 实际装入 WorkspaceProjection 的 Annotation；
- 相关的同账号可见历史 Thread/QuestionSession；
- 每项的新鲜度和查看链接。

学生可以对软记忆执行“本轮不参考”或全局暂停个性化；该选择写入 `ContextUsePreference`，不改科学事实。界面不展示系统 Prompt、隐藏推理、工具调用链或未被实际装载的海量历史。

这使“Agent 能主动查看自己的可见 Session”对用户同样透明：用户知道它参考了什么，也能进入原对话核对。

## 9. 统一视觉与交互语言

### 9.1 视觉方向

沿用现有 web-next 的中性、低 chrome 对话界面，而不是新建紫色渐变的“AI 仪表盘”：

- 基础只使用现有 `background / foreground / card / muted / accent / border / ring / destructive` token；
- sidebar 的蓝色继续作为品牌/当前位置提示，不给每类科学状态发明一种高饱和色；
- 成功、提醒、错误如需新增语义色，以 core token 的浅背景/边框/文字三元组实现并同时支持 dark mode；
- support/counter/non-discriminating 使用文本、关系图标和结构区分，不能简单等同绿/红/灰；
- 正文继续使用项目 `font-sans`，ID、版本和参数使用 `font-mono`，公式使用本地 KaTeX；
- 图标统一使用现有 Lucide，不用 emoji 充当功能图标。

本次 UI/UX 资料检索支持 AI-native 的低 chrome、上下文卡片、150–300ms 反馈和 reduced-motion，但其紫色配色、营销字体和产品 Demo 模板不适合现有 MathPilot，故不采纳。

### 9.2 表面与层级

复用 `surfaces.tsx` 的语言：

- `paper`：页面内稳定内容；
- `floating`：Sheet、Popover、临时详情；
- `field`/`fieldInteractive`：卡内次级区域；
- `pressable`/`ghostButton`/`inkButton`：统一交互反馈；
- `collapsePanel`：证据详情展开；
- `ShimmerLabel` 只用于真实运行态，不用于静态装饰。

层级限制：页面背景 → 一个主 surface → field/list；禁止 `Card > Card > Card`。阴影只表示浮层或与消息流区分的权威卡片，普通记录列表以 border/divider 为主。

### 9.3 文案语言

学生默认文案不用内部缩写：

| 内部术语 | 学生文案 |
|---|---|
| M / MasteryProjection | 掌握记录 / 程序基准 |
| R / retrievability | 复习状态 / 当前提取风险 |
| C_e / ErrorPattern | 容易出错的情境 / 验证状态 |
| Dream Annotation | 学习观察 / 系统记住的内容 |
| Observation | 一条独立学习证据 |
| `unresolved` | 尚不能形成正式判定 |
| `inconclusive` | 目前还不能区分原因 |
| `prior_only` | 尚未用本地学生样本校准 |

不使用“能力低”“粗心型”“你总是”“系统已经完全了解你”等人格化或过度确定表述。

### 9.4 动效

- hover/press：约 150ms，沿用现有 easing；
- disclosure/Sheet：约 200ms；
- 新消息/卡片淡入不超过 200ms；
- 不动画滚动数字、掌握概率或状态进度条，避免制造科学精度感；
- streaming 和长任务只保留一个明确活动指示；
- `prefers-reduced-motion` 下关闭位移、脉冲和 shimmer，只保留即时状态变化。

## 10. 无障碍、安全与隐私

### 10.1 无障碍

- 交互控件最小目标 `44×44px`，桌面紧凑图标按钮也要有足够可点击容器；
- 所有图标按钮有可翻译的 accessible name 和 Tooltip；
- radio、checkbox、dialog、sheet、collapsible 使用已有可访问 primitive，不自行模拟；
- 焦点顺序跟随消息和卡片视觉顺序；新 QuestionCard 到达时不强抢正在输入的 Composer 焦点；
- 提交后把焦点移到 AnswerReceipt 或状态摘要，并允许继续键盘导航；
- Sheet 关闭后恢复触发器焦点；
- 流式文字不逐 token 向读屏器播报，完成或关键状态变化时再宣告；
- 数学内容保留可访问文本/MathML 路径，图像必须有业务 alt；
- 颜色对比至少达到正文 4.5:1，焦点环始终可见；
- 组件测试优先按 role、label 和可见文本查询，不用 `data-testid` 代替语义。

### 10.2 安全

- DomainUIPart 和 read model 必须通过共享 schema 校验；规范契约延续现有 `src/packages/contracts` JSON Schema/TypeBox 路径，前端 validator/type 从同一契约生成或薄适配，不各写一套松散解析；
- Annotation、题目、模型文本均按不可信内容渲染；不允许记忆内容注入任意 HTML 或事件处理器；
- evidence handle 每次访问重新鉴权，深链不是永久公开 URL；
- card capability 只包含用户已获授权的动作，服务端仍重复校验 actor、resource version 和状态；
- 线程导出、复制和分享执行同样的字段级脱敏；
- 历史会话内容在 WorkspaceProjection 中继续标记为数据而非指令。

### 10.3 隐私

- 学生能看见哪些软记忆正在用于个性化；
- muted、stale、under_review 的 Annotation 不进入前台 Agent 上下文；
- 教师只访问授权学生，班级关系变化立即影响读模型和 evidence handle；
- 页面分析事件只记录组件/动作类型和资源类别，不记录回答正文或 Annotation claim；
- Dream Diary、preimage 和内部审核材料遵循比学生记录更严格的权限与保留策略。

## 11. 组件—读模型—命令配对清单

| 前端设施 | 必需读模型 | 可发命令 | 没有后端时的状态 |
|---|---|---|---|
| Thread | `ThreadMessagesView` | send/cancel ordinary message | 可读历史，发送禁用并保留草稿 |
| LearningContextPanel | `ThreadContextView`、`AgentContextManifestView` | cut、intent revision、context preference | 显示上次有效快照和新鲜度 |
| QuestionCard | `QuestionInteractionView` | submit attempt、skip/cut | 不允许仅本地提交 |
| JudgmentCard | `JudgmentView` | request review（有权限时） | 显示 unresolved/服务暂不可用 |
| DiagnosticProbeCard | Question/Claim view | submit probe、skip | 普通文本追问或明确 inconclusive |
| QuestionClosureCard | `QuestionClosureView` | start next selection | 保留已关闭事实，不伪造影响 |
| LearningOverview | `LearningOverviewView` | start recommendation | 可继续打开对话 |
| HistoryTimeline | `LearningHistoryView` | 无直接科学写入 | 可分页重试 |
| ScientificState | `ScientificStateView` | start review | 显示上一有效投影和重建提示 |
| ErrorPattern | `ErrorPatternListView` | start verification | 没有记录不显示成“无问题” |
| MemoryLedger | `MemoryLedgerView` | feedback、mute/unmute | 旧记忆保留，失败可重试 |
| ReviewQueue | `ReviewQueueView` | start review | 空状态说明尚无到期项 |
| EvidenceDetail | `EvidenceBundleView` | teacher correction（按权限） | 鉴权失败不泄露引用内容 |
| ActivityProgress | `LearningActivityView` | pause/cancel（若政策允许） | 不影响已有科学事实 |

每增加一个组件，必须在此找到后端读模型、权限、空状态和命令；每增加一个面向用户的投影，也必须明确它在哪个组件可见。禁止“后端已经有字段但用户永远看不到”和“卡片自己猜后端状态”两种断裂。

## 12. 实现边界与复用纪律

建议目标目录只表达职责，不复制库源码：

```text
src/apps/web-next/src/
  learning/
    contracts/              共享 schema 的前端导出
    data/                   read client、event bridge、cache adapter
    presentation/           DomainUIPart registry 和 serializers
    cards/                  薄领域卡 renderer
    context/                LearningContextPanel
    records/                overview/history/state/memory/review 页面组合
    evidence/               EvidenceSheet / EvidencePage

src/services/api-next/src/
  learning-read/            view assemblers、ACL、cursor、ETag
  learning-command/         HTTP 到领域服务/Workflow 的薄入口

src/packages/contracts/
  schemas/learning-view/    JSON Schema、枚举、示例与拒绝样例
```

复用要求：

- assistant-ui 继续承担 chat primitives、runtime bridge 和 part renderer；
- Base UI/Radix 的现有封装承担 Dialog、Sheet、Collapsible、Tooltip、Menu；
- Lucide、KaTeX、ReactMarkdown/remark-gfm 继续复用；现有 Zod 只承担前端局部表单，跨服务契约以 contracts 包为准；
- 服务器分页优先于首版自制虚拟列表；
- 不自制 router、server-state cache、焦点陷阱、toast 系统、图表库或动画引擎；若现有设施不足，选择成熟库并先核对其当前文档；
- 不把第三方组件源码大段复制进仓库，只写 MathPilot 的薄 styling/contract adapter；
- 不让每张卡各自 fetch、解析、缓存、重试和订阅事件。

## 13. 验收标准

### 13.1 契约与一致性

1. 每个权威卡都能追到 domain event、resource version 和当前详情；
2. 模型伪造 `mathpilot.ui.*` 内容会被服务端拒绝或按普通不可信文本处理；
3. 同一 Attempt 重试只产生一个事实、一个 AnswerReceipt 和一个生效 Judgment 链；
4. 卡片在刷新、切 Thread、换设备后保持服务端提交状态；
5. supersession 后历史和当前视图都正确，旧卡不会冒充当前结论；
6. projection rebuilding、Dream lag 和事件流断线均有明确降级；
7. 前端无法表达直接写 M/R/C_e 或编辑 Annotation 的请求。

### 13.2 使用场景

1. 学生在同一 Thread 连续做三题，三张题卡分别绑定正确 QuestionSession；
2. 学生随时用自然语言修改复杂选题要求，UI 不要求进入筛选器模式；
3. 学生点题卡选项、改用文字、跳过和重复点击都得到正确收据；
4. 提示后答对时，历史明确说明“用于教学连续性，未计入独立掌握”；
5. suspected/confirmed/improving/resolved 的错因分别显示正确语气和下一步；
6. Dimension 状态同时显示程序结果和 Dream 情境附注，互不覆盖；
7. 学生能查看一条记忆的支持与反证、报告不准确并暂停用于个性化；
8. 学生能看到本轮 Agent 实际参考了哪些记忆和历史会话；
9. 教师能从状态进入证据、提交 supersession，并看到重放后的新投影；
10. Dream 或 Judgment 暂不可用时，对话和换题仍按已定义降级继续。

### 13.3 前端质量

1. 复用现有 assistant-ui Thread、Message、Composer、Attachment 和 ActionBar，无第二套聊天实现；
2. `390×844`、`834×1112`、`1440×900` 无页面横向溢出；
3. 键盘可完成答题、提交、展开证据、关闭 Sheet 和切换记录页面；
4. 读屏器能获得卡片标题、当前状态、错误和完成通知，streaming 不逐 token 噪声播报；
5. light/dark mode、200% zoom、reduced motion 均可用；
6. 操作控件有 loading、disabled、empty、error、stale 和 permission-denied 状态；
7. 卡片导出为可读文本，不包含内部 JSON 或无权限字段；
8. 测试使用可访问查询，覆盖跨设备更新、重复提交和 capability 失效。
