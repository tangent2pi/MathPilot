# 06. 场景审计、复用选型与验收

## 1. 审查结论

在限定范围内，架构没有必要继续扩张成更多“模式”或更多 Agent。真正缺失的是边界：题级事务、证据资格、错因证据、Dream 写权限和耐久执行。补齐这些后，普通对话、模型选题和三相位 Dream 可以同时成立。

本轮审查对晚期讨论做了五项关键修正：

1. 同一可见 Thread 不等于取消一题一 QuestionSession；
2. 模型主导选题不等于模型绕过硬资格和原子提交；
3. Dream 形成语义记忆不等于 Dream 修改科学数值/错因状态；
4. 统一后台 Runtime 不等于自己手写一个 Job 系统；
5. 后端形成事实不等于前端已经完整；权威卡片、个人记录、记忆控制和证据查看必须有同源读模型。

## 2. 成品复用选型

### 2.1 科学内核

| 能力 | 选型 | 使用方式 | 不做什么 |
|---|---|---|---|
| 在线 BKT | 现有 OATutor `BKT-brain.js` 薄移植 | 合格 Observation 的确定性 replay | 不再写第二套公式 |
| BKT 离线拟合/对拍 | pyBKT | 参数拟合、变体实验、golden comparison | 不作为第二个在线状态权威 |
| 保持/调度 | `ts-fsrs` | 薄 `RetentionEngine` 适配，固定版本 | 不继续维护自研 I90 曲线/网格/调度 |
| FSRS 参数优化 | `@open-spaced-repetition/binding` | 数据充足后的离线任务 | beta API 不进入首版在线硬依赖 |
| 错因状态 | MathPilot 小型 reducer | 这是独有的诊断证据语义 | 不造通用规则引擎/概率分类平台 |
| 数据验证 | 现有 TypeBox/JSON Schema 体系 | 契约、工具和结果统一生成/校验 | 不为每个服务手写重复 validator |

FSRS 的 Stability 被官方定义为可提取性降到 90% 的时间，语义上可替代 I90；`ts-fsrs` 还提供 retrievability、next/repeat、rollback 和 reschedule。需要钉住库版本、参数版本和 golden outputs，不能跟随 latest 自动改变历史状态。

### 2.2 Runtime

| 方案 | 优点 | 关键缺口/代价 | 结论 |
|---|---|---|---|
| 自建 PostgreSQL Job 表 | 初看依赖少 | lease、heartbeat、retry、cancel、wait、child、schedule、history、恢复都要自己写 | 拒绝 |
| Graphile Worker | PostgreSQL 原生、MIT、重试、backoff、job_key、cron 很成熟 | 本质是 Job queue；父任务等待子任务、耐久交互和工作流恢复仍需较多自编排 | 不作为统一 Runtime；简单独立 Job 场景才合适 |
| Trigger.dev self-host | TypeScript 体验好、任务/子任务/实时能力完整 | self-host 当前无 Checkpoints，非阻塞等待能力与 Cloud 不同；还需 Redis/Postgres/多容器 | 不选作本项目统一自托管基线 |
| Temporal OSS + TS SDK | Workflow history、Activities、Signals/Updates、Child Workflow、取消、Schedule、恢复均成熟；MIT | 运维比单一 Job queue 重，需要独立服务和确定性 Workflow 纪律 | 采用；恰好覆盖用户关心的统一异步和 subagent |

选择 Temporal 不是因为“Agent 一定需要复杂框架”，而是本需求已经明确包含父子任务、需求变更、长期等待、可靠切题和 Dream 调度。若使用简单队列，缺失部分最终仍会变成 MathPilot 自制工作流引擎。

### 2.3 对话与 Agent

| 能力 | 选型 | 边界 |
|---|---|---|
| 当前 Thread 消息渲染 | assistant-ui ExternalStore Runtime | MathPilot 持有规范消息；Thread 列表/路由由应用壳维护，不依赖 deprecated 的 ExternalStore thread-list adapter |
| 模型 AgentAttempt | Pi SDK | 一次 Attempt 的工具/Skill/事件；不承担耐久编排 |
| Dream 行为 | 参考 OpenClaw memory-core | 继承相位和安全纪律，不直接复用其自由文本 MEMORY 存储 |
| 模型选题 | Pi Selector Agent + 单一 catalog tool | 模型做偏好折中，宿主做硬校验与提交 |
| 工作区透明 | Pi 原生只读 `read`/`grep` + 宿主投影 | 不新增重叠 session APIs，不给任意数据库 |

OpenClaw 的具体 memory-core 面向通用 Agent 文件记忆；MathPilot 已有结构化教育事实、正反证据和多租户权限，直接嵌入会产生两套规范状态。因此复用其经过验证的三相位、门禁、preimage、Diary 和回滚模式，领域存储和 validator 保持薄而专用。

### 2.4 前端设施

| 能力 | 复用 | 边界 |
|---|---|---|
| 对话壳与消息交互 | 现有 assistant-ui Thread/Message/Composer/Attachment/ActionBar primitives | 不建设第二套聊天组件或把 Runtime 当领域数据库 |
| 权威卡片 | assistant-ui typed part/tool UI renderer + MathPilot `DomainUIPart` | renderer 复用，卡片只能由后端领域事件投影器产生 |
| 教学 UI | 现有有界 `@assistant-ui/react-generative-ui` registry | 只做非权威教学展示，不承载 M/R/C_e/Annotation 声明 |
| 浮层和基础控件 | 现有 Base UI/Radix 风格 `components/ui` | 不自制 Dialog、Sheet、focus trap 和 menu |
| Markdown/数学/图标 | ReactMarkdown、remark-gfm、KaTeX、Lucide | 不再引入平行渲染栈 |
| 契约验证 | 现有 `src/packages/contracts` JSON Schema/TypeBox 路径 + 生成的前端 adapter | 不让每张卡各写松散解析与 fetch/cache/retry |

完整的组件、读模型、权限和响应式契约见 [07-前端设施后端读模型与统一交互语言.md](./07-前端设施后端读模型与统一交互语言.md)。

## 3. 科学有效性审计

### 3.1 RetentionUnit 不能过宽

FSRS 的 DSR 状态面向相对单一的记忆单元。若一个题型 ID 同时涵盖多种方法和表征，把它直接当一张 Card 会产生虚假平均。因此生产模型引入逻辑 `RetentionUnit`：

```text
retention_unit_revision_id
dimension_revision_id
scope_facets              method/representation/subskill
measurement_rules[]
```

- 原子 K/T 可以一对一映射；
- 过宽 T 必须拆成有明确测量规则的 unit；
- 一次延迟题可以更新多个 unit，但每个都要有 rubric 证据；
- 报告可再聚合到题型，FSRS Card 不在聚合层维护；
- Content 审核需检查 unit 是否满足“同类提取”假设。

这是采用 FSRS 的必要边界，而不是让成品算法替代教育测量建模。

### 3.2 BKT 标签粒度

一个答案不能因为题目挂了三个标签就给三个维度全部 success。只有 rubric item 能独立支持的维度才产生 Observation。对共享步骤或不可区分多技能题，保留 unresolved，或以后用经过验证的多技能模型；首版不以启发式分摊权重。

### 3.3 学习与测量混合

普通对话天然混合教学和测量，因此证据级 `independent/hint_level/eligibility` 必须替代会话级 mode。讲解本身不直接提高 M；下一道独立迁移题证明学习是否发生。这使自由训练和阶段训练真正共用一条管线。

### 3.4 模型富信号的去向

部分正确、不确定、疑似蒙对、方法不稳定等信息全部保存，但生产 BKT 只消费已经验证的二值逐维度 Observation。新数值消费方式必须作为新 Engine 版本离线评估后晋级，而不是在 Prompt 里临时设置权重。

### 3.5 因果表述

`C_e` 是“与观察相符、可区分的教学假设”，不是因果证明。报告避免“因为你粗心所以错”，改为“在这些步骤反复出现 X；探针支持 Y 假设；下一题将验证”。

## 4. 场景审计

### 4.1 正常学习

| 场景 | 必要结果 |
|---|---|
| 独立答对 | 合格维度进入 M；若为延迟复测也进入 R；可为某 E 提供反证 |
| 独立答错 | M failure；按规则建立 C_e 候选；不自动确认第一候选 |
| 部分正确 | 只对可明确映射的 rubric item 产生逐维度事实 |
| 提示后答对 | LearningOpportunity；可能成为 C_e 改善证据，不进独立 M/R |
| 同题自纠 | 保存行为，不重复计数；安排近迁移验证 |
| 学生跳过 | 显式 close reason，不写失败 Observation，Claim 可 skipped |

### 4.2 选题与需求

| 场景 | 必要结果 |
|---|---|
| 复杂偏好 | 模型用一个 catalog tool 迭代搜索并解释折中 |
| 用户在选题中改需求 | 新 revision；旧结果提交失败 |
| 无完全满足候选 | 返回 unsatisfied/no_candidate，不编造题 |
| 正式阶段测评 | Activity policy 施加覆盖/预算，但仍走同一 QuestionSession |
| 自由题恰好覆盖计划 | 科学状态照常更新；计划是否计入由 policy projection 决定 |
| 外部题 | 可教学；无验证 contract 不进正式科学状态 |

### 4.3 切题和并发

| 场景 | 必要结果 |
|---|---|
| 双击下一题 | 一个 Cut 结果 |
| 两标签页提交不同答案 | QuestionSession version/Attempt admission 明确接受或拒绝 |
| Cut 时有迟到判题 | 只有冻结前被接纳的 Attempt 可进入 final judgment |
| 科学事务提交后响应丢失 | 重试读取同 operation result，不双写 |
| 下一题提交后前一题 Light 失败 | 下一题不受影响，Light 独立重试 |
| 回到旧题 | 新建 revisit Session；旧证据不改写 |

### 4.4 错因

| 场景 | 必要结果 |
|---|---|
| 探针同时支持 B、反对 A | 逐候选写两条关系，不只存 resolved ID |
| 证据不足 | inconclusive/unclassified 是正常输出 |
| 已 confirmed 后近迁移成功 | improving，而非立即 resolved |
| resolved 后复发 | confirmed + recurrence event |
| 多学生只在同题出同错 | 优先产生题目/rubric review proposal |
| 教师纠正 | supersede 事实并重放 M/R/C_e，相关 Dream 附注 stale |

### 4.5 Dream

| 场景 | 必要结果 |
|---|---|
| 单题出现新现象 | Light 保存题级 atom；不足以长期晋升 |
| 多题重复但有反例 | REM/Deep 附注必须带 counter refs 和 scope |
| Deep 模型输出 p_final | schema 拒绝 |
| Deep 试图 confirmed 一个 E | schema/数据库权限拒绝 |
| 输入证据被纠正 | 提交前候选失效；已写附注变 stale |
| 两个 Deep 并发 | expected version 阻止覆盖 |
| Dream 模型长期不可用 | 科学内核和下一题继续工作，旧附注保留 |

### 4.6 隐私与权限

| 场景 | 必要结果 |
|---|---|
| Agent 搜索同账号历史 | 只读 sessions projection 中可找到 |
| 请求另一个账号/班级私密 Thread | 宿主不投影，模型没有绕过工具 |
| 后台 transcript 含内部提示 | 不进入用户 workspace 或 Dream corpus |
| 用户删除会话 | 按保留政策清除/匿名化；依赖 Annotation 标 stale 或删除 |
| 外部工具文本带 Prompt injection | 标 untrusted，不进入证据或 Deep promotion |
| Temporal history 含敏感数据 | payload 只用引用并加密；设置保留/归档政策 |

## 5. 现有实现差距

### 5.1 learning-service

当前 `closeChain`：

- 先等待模型 TSS，失败就保持 Session OPEN；
- `mode=diagnostic` 决定独立性，无法适配普通对话中混合教学/测量；
- 自研 I90 只在 `mode=review` 更新；
- 只把 Claim 第一候选 `ON CONFLICT DO NOTHING` 写成 suspected；
- TSS misconception payload 与 schema 不一致；
- probe correct 被错误映射为第一候选 resolved。

目标：拆为 FinalizeQuestionWorkflow 的硬事实事务 + 全部软异步产物；证据资格下沉到 Attempt/Observation；引入 ErrorEvidence/reducer；FSRS 适配。

### 5.2 profile-service

当前路径让 Dream：

- 输出 `p_final` 并用手工 LR 修改 BKT baseline；
- 输出 `misconception_updates` 覆盖错因状态；
- 生成同时混合数值和语义的 StudentSnapshot。

目标：删除 Dream 数值/状态写入口；科学投影由三类 reducer 发布；Profile/Dream 只提交 AnnotationChangeSet。现有引用授权、窗口校验、supersedes 和 review audit 可继续复用。

### 5.3 selector

当前固定六目标、确定性评分只能处理预定义需求，无法表达用户反复变化的自然语言偏好。

目标：保留搜索/硬过滤能力，删除“程序假装最终理解需求”的权重主选择；由 Selector Agent 通过一个 catalog tool 选择，宿主原子提交。

### 5.4 agent-runtime

当前同步 HTTP + 进程内 `activeRuns Map` 无法跨实例恢复；所有任务容易获得 Bash、数据库和全部 Skills。

目标：`PiTaskExecutor` 作为 Temporal Activity；TaskSpec 最小授权；后台 Attempt 不持有前台 Session；正常科学任务无 Bash/SQL。

### 5.5 pi-chat/assistant-ui

当前 react-pi 的 session 变化容易直接同步前端，从而诱导出“不能动 Session”的架构限制；question card 与 learning artifact 又有两个重叠展示工具。

目标：assistant-ui ExternalStore 渲染应用持有消息；Pi Epoch 仅作为模型上下文；QuestionOpened 自动生成题卡消息；额外教学产物收敛为一个有界 action。

### 5.6 数据模型

建议直接切到以下权威对象，不为旧 `mode/run/PUD` 设计长期兼容层：

- `conversation_thread` + canonical message；
- `learning_intent`、可选 `learning_activity`；
- 简化生命周期的 `question_session`；
- `judgment`、`observation`、`learning_opportunity`；
- `diagnostic_claim`、`error_evidence`、`error_pattern_projection`；
- `retention_unit`、FSRS card projection、delayed review event；
- `light_atom`、`rem_candidate`、各类 annotation、dream_run；
- 现有 outbox + workflow correlation/operation result。

旧数据若缺少可靠 provenance/hint/rubric，不强行升级为正式科学事实；可以只读归档或作为 provisional 历史，避免迁移制造虚假精度。

## 6. 实施顺序

### P0：冻结契约与权限

- 建立新的 ID、事实、projection 和 Annotation schemas；
- 禁止 Dream 数值/C_e 状态写；
- 定义 EvidencePolicy、ErrorReducerPolicy、TaskSpec；
- 建立 contract examples 与拒绝样例。

完成门槛：schema 层已经无法表达越权写入。

### P1：耐久 Runtime

- 在开发组合中加入 Temporal 服务和 TypeScript Worker；
- 将现有 Pi `runTask` 收敛为 PiTaskExecutor Activity；
- 接通 outbox、stable workflow ID、idempotent operation result；
- 落地 Task Registry、最小 Skill/工具装载。

完成门槛：重启/超时/重复投递测试通过，后台不再依赖进程 Map。

### P2：题级事实与切题

- 引入应用持有 Thread messages 和 ForegroundAgentEpoch；
- 简化 QuestionSession 生命周期；
- 实现 CutRequest/FinalizeQuestionWorkflow；
- TSS/Light 等移出硬关闭；
- 自由/阶段统一为 Intent + optional Activity。

完成门槛：并发切题和模型失败不串题、不双开、不永久卡住。

### P3：科学内核迁移

- 固化 Judgment → Observation 资格编译；
- 保留 OATutor BKT 适配并对拍 pyBKT；
- 引入 RetentionUnit 和 `ts-fsrs`，迁移 delayed review facts；
- 删除自研 I90 生产写路径。

完成门槛：M/R 可从事实完整重放，第三方 golden tests 通过。

### P4：错因闭环

- 扩展 DiagnosisRule relation matrix；
- 实现 ErrorEvidence/reducer；
- 修复探针；
- Teaching/Selection/Report 消费 C_e；
- 教师 supersede 与内容 insight proposal。

完成门槛：从错误到诊断、干预、近/远验证、解决/复发的端到端用例通过。

### P5：模型选题与需求修订

- 单一 question_catalog；
- Selector Skill/AgentAttempt；
- intent revision Signal、commit revalidation；
- assistant-ui ExternalStore 和自动 QuestionOpened 渲染。

完成门槛：复杂/变化需求和无候选场景均正确，旧选择无法提交。

### P6：三相位 Dream

- Light per QuestionSession；
- REM window/compiler；
- Deep gates/AnnotationChangeSet/preimage/Diary/rollback；
- 前台 relevant annotations 和只读历史 workspace。

完成门槛：Dream 能产生有用情境附注，所有数值/状态越权测试被拒绝。

### P7：用户可见读模型与前端设施

- 建立 LearningView envelope、read assembler、ACL、cursor/ETag 和授权失效事件；
- 将 `QuestionOpened`、Attempt、Judgment、QuestionClosed 和 material projection change 投影为规范 DomainUIPart；
- 用 assistant-ui External Store 接管 app-owned canonical messages，拆分权威 presentation registry 与教学 artifact registry；
- 落地对话上下文栏、AnswerReceipt、判定/关闭/更新卡片；
- 落地学习概览、历程、状态、错因、记忆、复习和证据详情；
- 落地 Annotation 反馈/暂停个性化与 AgentContextManifest 透明界面；
- 完成跨设备、响应式、键盘、读屏、dark mode 和 reduced-motion 验收。

完成门槛：每个用户可见投影都有组件和证据入口，每个组件都有服务端读模型与命令；模型不能伪造权威卡片，刷新/重试不会丢提交状态。

P0–P7 是依赖顺序，不意味着所有能力必须等到最后一次性发布；P2 起即可逐步落地对应卡片，P7 负责收口完整个人学习空间和全链路验收。每个阶段可在 feature flag 下完成回归后直接替换旧路径。由于不要求兼容，最终只保留新权威写路径。

## 7. 测试与评估架构

### 7.1 确定性测试

- schema contract examples；
- Observation 资格表驱动测试；
- OATutor/pyBKT BKT golden tests；
- `ts-fsrs` next/retrievability/rollback golden tests；
- ErrorReducer 全转移和 supersession property tests；
- Cut/commit 的数据库并发测试；
- Annotation Validator 禁止字段测试。

### 7.2 Workflow 测试

使用 Temporal 官方 TypeScript testing utilities，而不是手工 mock 整个调度器：

- virtual time 的 retry/timer/Schedule；
- Worker crash 与 Activity timeout；
- Signal 与 intent revision race；
- Child Workflow cancel/parent close；
- DB committed/response lost 的幂等恢复；
- Continue-As-New 后消息去重。

### 7.3 Agent evals

固定输入事实和工具返回，评估：

- Judgment rubric 准确/引用完整/unresolved 校准；
- Selector 对复杂意图的满足率、无候选诚实率和工具调用数；
- REM 候选的正反证据覆盖；
- Deep Annotation 的 groundedness、scope 质量和教师接受率；
- Prompt injection 和越权工具拒绝；
- Skill 改动前后的回归。

Agent eval 只评模型负责的语义部分，不能用端到端“最后答案看起来不错”掩盖 reducer/事务错误。

### 7.4 教育效果

- M 的未来独立题预测与校准；
- FSRS 到期时实际 recall；
- C_e confirmation precision、remediation lift、near/far transfer、recurrence；
- 自由/阶段同证据政策下的一致性；
- Dream Annotation 对选题和教学效果的增量，不以附注数量作为成功指标。

### 7.5 前端契约与可用性

- DomainUIPart schema/权限/supersession contract tests；
- External Store 消息 replay、断线续传、重复事件和跨设备提交；
- 已形成证据的消息不可编辑/重生成，普通消息能力不受误伤；
- QuestionCard 的 radio/checkbox、文字回答、跳过和幂等收据；
- 学习记录、科学状态、MemoryLedger、EvidenceDetail 的权限与空/旧/重建状态；
- Annotation feedback、mute/unmute 和 WorkspaceProjection 排除一致；
- `390×844`、`834×1112`、`1440×900` 响应式截图与无横向溢出；
- keyboard、screen reader、200% zoom、dark mode、reduced motion 回归。

## 8. 运维和可观测门槛

必须有统一关联链：

```text
conversation_thread
  → question_session
  → cut_request / selection_intent
  → workflow / activity / agent_attempt
  → judgment / observation / error_evidence
  → M/R/C_e projection
  → light/rem/deep run
  → annotation
  → canonical domain_ui message / learning read model
```

面板至少展示：

- active/finalizing QuestionSession 和卡住时长；
- Workflow backlog/retry/non-retry failure/cancel；
- model latency/token/cost/tool calls；
- stale intent/selection commit conflict；
- unresolved Judgment/inconclusive Claim；
- outbox delivery lag；
- Light/REM/Deep backlog 与 rejected reasons；
- projection replay version 和数据新鲜度。

告警针对事实一致性和积压，不针对“模型没有输出漂亮总结”。

## 9. 最终验收清单

以下全部满足，才算本范围实现完成：

### 科学内核

- [ ] M、R、C_e 三层有独立事实和投影；
- [ ] Dream 无数值/状态写权限；
- [ ] BKT/FSRS 均为薄适配且版本钉定；
- [ ] 提示、部分正确、外部题和 supersession 的资格清楚；
- [ ] 投影可全量重放且结果一致。

### 错因

- [ ] 每个候选都有支持/反证/不可区分证据；
- [ ] DiagnosisRule 有 outcome relation matrix；
- [ ] Teaching、Selection、Verification、Report、Dream 和内容审核都消费 C_e；
- [ ] improving/resolved/recurrence 有独立验证语义；
- [ ] 教师纠正会重放而非编辑状态。

### 学习流

- [ ] 同一 Thread 多 QuestionSession；
- [ ] 一题一硬 Cut 事务；
- [ ] 自由/阶段只在 Intent/Activity 上不同；
- [ ] 模型主选、程序硬校验、单一 catalog tool；
- [ ] intent revision 防止陈旧提交；
- [ ] 软异步失败不阻塞下一题。

### Dream

- [ ] Light → REM → Deep 顺序与单深层写入口；
- [ ] Annotation 有 scope、support/counter、provenance 和 supersession；
- [ ] preimage、Diary、rollback 和 stale 处理可用；
- [ ] Diary/REM 不会反哺成伪证据；
- [ ] 题型数值与语义附注可并排显示。

### Runtime 与 Agent

- [ ] Temporal 承担 retry/cancel/timer/schedule/child/recovery；
- [ ] Pi 只执行隔离 AgentAttempt；
- [ ] TaskSpec 是 Skill、工具和权限的单一事实源；
- [ ] 多数任务零业务工具，Selector 只有一个；
- [ ] 正常学习任务无通用 Bash/SQL；
- [ ] 同账号可见会话以只读工作区投影对 Agent 透明；
- [ ] Thread、Epoch、QuestionSession、Workflow、Attempt ID 不混用。

### 前端设施与透明度

- [ ] assistant-ui 继续承担 Thread/Message/Composer，应用持有规范消息和 Thread 路由；
- [ ] 权威 DomainUIPart 仅由领域事件投影器产生，模型展示工具无法伪造；
- [ ] QuestionCard 提交走幂等 Attempt Command，并生成自然语言 AnswerReceipt；
- [ ] 学习概览、历程、M/R/C_e、复习、记忆和证据均有版本化读模型；
- [ ] 科学状态和 Dream Annotation 并排且有不同语义标签；
- [ ] 学生能查看记忆依据、报告不准确、暂停个性化并查看本轮 Agent 参考内容；
- [ ] 已成为事实的消息不能通过通用编辑/分支改史；
- [ ] responsive、keyboard、screen reader、dark mode、reduced motion 通过验收。
