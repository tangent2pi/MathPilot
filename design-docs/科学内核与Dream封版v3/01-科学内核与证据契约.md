# 01. 科学内核与证据契约

## 1. 目标

科学内核不负责“像老师一样解释学生”，而负责回答三个边界清楚的问题：

- `M`：依据合格的独立作答，学生对某个知识点或题型的掌握状态是什么；
- `R`：在当前时间点，这项已经学过的内容有多大概率仍可提取，何时值得复测；
- `C_e`：某个可区分、可干预的错因假设，目前得到怎样的支持、反证和验证状态。

三者共享证据来源，但不能合成一个“总熟练度”。`M` 是习得状态，`R` 是时间相关提取状态，`C_e` 是原因假设的证据状态。Dream 位于三者之上，只能补充语义附注，不能重算三者。

## 2. 为什么需要这一层

只让模型输出“掌握度 80%”有四个问题：

1. 同一作答会被不同提示重复计数；
2. 模型升级后历史状态无法重放；
3. “做错了”和“为什么做错”混为一谈；
4. Dream 很容易把跨题印象再次写回数值，形成循环自证。

因此科学内核采用“模型判语义、程序定资格、成品算法做投影”的分工。

## 3. 核心流水线

```text
Attempt / 草稿证据 / 上下文
             │
             ▼
Judgment Proposal（模型）
  - 逐评分点判定
  - 证据引用
  - 不确定性
  - 可能的错因关系提议
             │
             ▼
Evidence Policy（确定性）
  - 来源是否可信
  - 是否独立、是否受提示
  - rubric/measurement target 是否允许映射
  - 是否重复、是否已 supersede
             │
             ├── Observation ──► MasteryEngine ──► M
             ├── DelayedReview ─► RetentionEngine ► R
             └── ErrorEvidence ─► ErrorReducer ───► C_e

Light/REM/Deep 只读取以上事实和投影
             └──────────────────► 语义 Annotation
```

模型不是 reducer，Dream 也不是 reducer。只有宿主验证器能把模型提议编译成事实，只有版本化程序能把事实投影成状态。

## 4. 规范事实对象

### 4.1 Attempt

`Attempt` 是一次学生提交，不等于一次可用观测。至少包含：

```text
attempt_id
question_session_id
question_revision_id
student_id
kind                 answer | probe | correction | explanation
content_refs          文本、图片、草稿片段等
hint_level
submitted_at
supersedes_attempt_id?
```

### 4.2 Judgment

`Judgment` 是对一次 Attempt 的可审计判定，不直接改学生状态：

```text
judgment_id
attempt_id
verdict               correct | partially_correct | incorrect | unresolved
rubric_results[]       rubric_item + status + evidence_refs
dimension_proposals[]  dimension_revision + outcome proposal
uncertainty            low | medium | high
decision_summary
model_id / prompt_version / skill_version
created_at
supersedes_judgment_id?
```

要求：

- `partially_correct` 必须依评分点拆成逐维度结果；没有可靠映射时只能产生 `unresolved`，不能粗暴压成成功或失败；
- 高不确定性不通过人工权重“打折”，而是进入确定性资格规则：拒绝、要求复核或只保留为教学事实；
- 判定必须引用具体证据；隐藏推理不保存、不进入 Dream。

### 4.3 Observation

`Observation` 是已经通过资格策略、能被科学引擎消费的最小事实：

```text
observation_id
student_id
dimension_revision_id
question_session_id
question_revision_id
judgment_id
outcome               success | failure
eligibility           independent_measurement
measurement_rule_id
hint_level             必须为 0
evidence_refs[]
occurred_at
policy_version
supersedes_observation_id?
```

一个 Judgment 可以产生多个逐维度 Observation，但每个评分点/维度/Attempt 组合只能有一个生效观测。

### 4.4 LearningOpportunity

提示、讲解、自我纠正和带帮助完成仍然有教学价值，但首版不直接提高 BKT：

```text
learning_opportunity_id
student_id
dimension_revision_ids[]
question_session_id
intervention_kind
hint_level
evidence_refs[]
occurred_at
```

它用于教学连续性、错因改善判断和后续独立验证选题。等有真实数据证明某类干预的学习转移参数可靠后，才能以新版本 `MasteryEngine` 消费，不能先用拍脑袋的 `T` 提高掌握度。

## 5. 证据资格

### 5.1 资格矩阵

| 情况 | M | R | C_e | 说明 |
|---|---:|---:|---:|---|
| 首次、零提示、题目和评分规则可信的独立作答 | 是 | 仅满足延迟复测时 | 可产生支持/反证 | 标准测量证据 |
| 提示后答对 | 否 | 否 | 可作“经干预改善”证据 | 不能冒充独立掌握 |
| 同题立即改对 | 否 | 否 | 可作自我纠正/教学证据 | 防止重复计数 |
| 解释思路但无可判定结果 | 否 | 否 | 可产生弱语义证据 | 需保留不确定性 |
| 探针回答 | 默认否 | 否 | 按诊断规则映射 | 探针用于区分错因，不顺便提高 M |
| 独立近迁移题 | 是 | 视时间间隔 | 强反证/验证 | 与原题不同情境 |
| 独立远迁移或延迟复测 | 是 | 是 | 可完成验证 | 同时消费时各层用途明确，不重复改 M |
| 外部题但无验证 rubric/measurement target | 否 | 否 | 只作未正式化语义证据 | 可以教学，不能伪装科学测量 |
| 教师纠正后的替代判定 | 由新事实决定 | 由新事实决定 | 由新事实决定 | 旧事实 supersede 后全量重放 |

### 5.2 独立性的定义

“独立”不是前端模式，而是一次证据的属性，至少要求：

- 该 Attempt 之前未显示解法、关键提示或判定；
- `hint_level = 0`；
- 不是同题答案的机械复述；
- 题目版本、评分规则和测量目标在提交时固定；
- 未被另一条 Observation supersede；
- 归属的学生、题目和 QuestionSession 可验证。

自由训练和阶段训练都可以产生独立证据；来源不决定证据资格。

## 6. 掌握层 M

### 6.1 生产引擎

在线生产路径继续复用仓库已有的 OATutor `BKT-brain.js` 薄移植：

- 输入是逐学生×逐维度的 `success/failure` Observation 序列；
- 参数集版本化，输出始终附 `parameter_set_id` 与 `calibration_status`；
- 状态由重放得到，不维护不可解释的模型私有状态；
- pyBKT 用于离线拟合、变体评估、批量核对和 golden test，不与在线引擎形成两个写权威。

这不是重新实现 BKT。在线 TypeScript 适配器保持很薄，核心公式与 OATutor/pyBKT 做对拍。

### 6.2 跟踪维度

首版分别跟踪：

- 学生 × 知识点 lineage；
- 学生 × 题型 lineage。

每条 Observation 必须引用答题时冻结的 dimension revision；Projection 则按稳定 `dimension_id + lineage_version` 聚合兼容 revision。仅文字、来源等不改变测量语义的 revision 可由发布的兼容映射合并；语义发生变化时必须新建 lineage 或显式迁移，不能静默混算历史证据。

题型不能简单继承知识点概率，两者各自需要有有效测量目标的题目。一个题可以同时为多个维度产生 Observation，但必须由版本化 rubric 明确分解。

### 6.3 部分正确与多步答案

不对 `partially_correct` 使用通用 0.5 权重。正确做法是：

1. Judgment 对每个 rubric item 给出状态和证据；
2. measurement rule 将 rubric item 映射到对应 K/T；
3. 能明确证明的维度产生 success/failure；
4. 无法区分的维度不产生 Observation。

这会损失一部分“看起来有用”的数据，但避免把不可校准权重混入 BKT。

### 6.4 slip、guess 与“粗心/蒙对”

BKT 的 slip/guess 是按资源类拟合的模型参数，不是模型对单题的临时标签：

- 学生疑似粗心，写入 ErrorEvidence/Annotation；不临时上调该学生的 slip；
- 学生疑似蒙对，保留证据并安排区分题；不把本题 success 手工乘权；
- 有足够样本后，用 pyBKT 的 `multigs` 等变体离线比较并发布新参数集；
- 任何新参数集都需做时间切分预测、校准和教师一致性评估。

丰富判定信号因此不会丢失，只是先进入证据账本，不越级进入未经验证的数值公式。

`prior_only` 参数集默认采用保守转移策略；首版不因一次讲解单独提高 M。将来若 pyBKT 离线评估证明某类资源的学习转移 `T` 可校准，可在新的参数/Engine 版本中随后续 Observation 使用；不能由前台模型按单题临时修改。

### 6.5 输出语义

```text
MasteryProjection
  p_mastery
  state                 insufficient_evidence | weak | learning |
                        possibly_mastered | mastered
  independent_count
  transfer_evidence
  parameter_set_id
  calibration_status    prior_only | calibrated
  input_observation_ids
  projection_version
  projected_at
```

`prior_only` 的 `p_mastery` 只能称“程序基准分数/模型状态”，不能对外宣称经过本校学生数据校准的真实概率。0.95 等状态阈值是版本化运营政策，不是普适教育定律。

## 7. 保持层 R

### 7.1 采用 FSRS，而非继续自研 I90 网格

当前 `packages/mastery/src/retention.ts` 的 I90 网格完成了概念验证，但生产目标改为 `ts-fsrs` 薄适配器：

- FSRS 的 `Stability` 就是可提取性 `R` 降到 90% 所需的时间，与 I90 语义一致；
- `get_retrievability` 提供当前 R；
- `next`/`repeat` 提供调度状态转换；
- `rollback`/`reschedule` 支持纠错和重放；
- `@open-spaced-repetition/binding` 可在数据充足后优化参数。

因此不再维护第二套遗忘曲线、网格后验、调度、回滚和优化逻辑。

### 7.2 RetentionUnit 与 Card 映射

FSRS 假设被跟踪对象是相对单一的记忆单元，不能把内部包含多种方法和表征的宽泛题型粗暴映射成一张 Card。内容层先定义逻辑 `RetentionUnit`：原子的 K/T 可以一对一映射；过宽题型按方法、表示或子技能拆成带明确 measurement rule 的 unit。

每个学生×RetentionUnit 有一个 `RetentionCard` 投影：

```text
student_id + retention_unit_revision_id
dimension_revision_id + scope_facets
fsrs_card                 due, stability, difficulty, state, last_review ...
last_review_event_id
review_count
parameter_set_id
projection_version
```

事实源仍是 MathPilot 的 `DelayedReviewEvent`，FSRS Card 只是可重建投影。报告可以把多个 unit 聚合到题型层展示，但聚合结果本身不维护另一张 FSRS Card。RetentionUnit 的粒度审计见第 06 文档。

### 7.3 什么能更新 FSRS

只有满足以下条件的事件更新保持层：

- 是独立作答；
- 与上一次学习/测量之间达到版本化的最小延迟；
- 对该维度有可靠 rubric；
- 不是同题即时重做；
- 没有被 supersede。

保守评级映射：

| 事实 | FSRS Rating |
|---|---|
| 延迟复测失败 | `Again` |
| 延迟复测成功 | `Good` |

首版不让模型从“答得有点犹豫”推断 `Hard`，也不从“很快”推断 `Easy`。只有经过校准的确定性测量规则才能在未来开放这两档。

### 7.4 M 与 R 的关系

- M 不随时间直接衰减；
- R 随时间变化并影响“现在是否容易提取”的预测；
- 复测的新独立 Observation 可以更新 M，同时对应的延迟复测事实更新 R；
- 不能执行 `M = M × R`，也不能因到期未复测就降低 M。

对外读模型可同时展示：“题型掌握基准 0.80；当前提取风险较高；建议 2 天内复测”。

## 8. 错因层 C_e

`C_e` 不输出一个仿佛精确的概率，而输出证据状态：

```text
suspected -> confirmed -> improving -> resolved
                    ^                    |
                    └──── recurrence ────┘
superseded 为本体修订/教师纠正后的终止状态
```

它由 `ErrorEvidence` 和版本化 reducer 得到；具体对象、转移和消费见 [02-错因证据与消费闭环.md](./02-错因证据与消费闭环.md)。

## 9. 语义附注与数值状态并行

科学状态和 Dream 附注必须在读模型中并排，而非互相覆盖：

```json
{
  "dimension_id": "T_SSA_AREA_COMPOSITE",
  "mastery": {
    "p": 0.8,
    "calibration_status": "prior_only",
    "parameter_set_id": "bkt_prior_v1"
  },
  "retention": {
    "retrievability": 0.71,
    "due_at": "2026-09-02T..."
  },
  "annotations": [
    {
      "claim": "给出标准图形时方法稳定；需要自行补线时容易停在建模步骤",
      "scope": { "representation": "implicit_auxiliary_line" },
      "support_refs": ["observation://...", "session://..."],
      "counter_refs": ["observation://..."],
      "confidence": "medium"
    }
  ]
}
```

Dream 可以新增或 supersede `annotations`，不能把 `p=0.8` 改成 0.7，也不能改 FSRS Card。

## 10. 教师纠正与重放

纠正采用追加式 supersession：

1. 教师或审核流程新增 Judgment/Observation/ErrorEvidence；
2. 新事实指向被替代事实；
3. 投影器排除已被 supersede 的旧事实；
4. BKT、FSRS、C_e 从生效事实按版本重放；
5. 受影响的 Dream Annotation 标为 stale，进入下一次 REM/Deep 复核；
6. 所有旧结果保留以便审计，不原地篡改。

任何投影器都必须幂等，同一事实重放两次不能多更新一次。

## 11. 外部题与临时题

学生可以直接发来题目，普通对话也可以正常教学，但科学内核分级处理：

| 内容状态 | 可教学 | 可建 QuestionSession | 可更新 M/R | 可更新正式 C_e |
|---|---:|---:|---:|---:|
| 已发布题目 revision + rubric + measurement target | 是 | 是 | 是 | 是 |
| 临时题，经宿主验证出可靠 rubric/target | 是 | 是 | 是 | 视诊断规则 |
| 只有题干/图片，模型临时理解 | 是 | 是 | 否 | 只保留 provisional 证据 |
| 来源或题干不完整 | 可澄清 | 是 | 否 | 否 |

这不是阻止自由学习，而是防止未经验证的外部内容污染长期科学状态。

## 12. 引擎端口

实现只需要薄端口，不建立一个“大一统智能评分类”：

```text
JudgmentCompiler
  compile(judgment, frozenContext) -> Observation[] + ErrorEvidence[] + rejects[]

MasteryEngine
  replay(validObservations, parameterSet) -> MasteryProjection

RetentionEngine
  replay(validDelayedReviews, parameterSet) -> RetentionProjection

ErrorEvidenceReducer
  replay(validErrorEvidence, policy) -> ErrorPatternProjection
```

端口输入输出必须是可序列化契约；算法实现由适配器提供。领域服务不复制第三方算法内部代码，也不把第三方 Card/Model 对象直接泄漏到 API。

## 13. 评估与晋级门槛

### 13.1 Judgment/Evidence

- rubric item 一致率；
- unresolved 校准率；
- 证据引用完整率；
- 高不确定性样本的人工覆核率；
- 提示后证据误入独立观测率必须为 0。

### 13.2 M

- 与 OATutor/pyBKT 的公式对拍；
- replay 与增量结果一致；
- 时间切分预测 log loss/Brier score；
- 概率校准曲线；
- 参数版本切换可重建。

### 13.3 R

- 与 `ts-fsrs` golden outputs 一致；
- teacher correction 后 rollback/replay 一致；
- 到期预测的实际召回校准；
- `Again/Good` 映射改变必须经离线实验。

### 13.4 C_e

见第 02 文档。任何模型或公式只有在离线实验优于当前基线、通过预先定义的校准门槛后，才能发布为新引擎版本；不能在生产 Prompt 中偷偷改变科学行为。
