# 进一步实施规划 v1.1：教学双产物、Dream 与 Artifact 契约

> 日期：2026-08-17  
> 设计基线：`系统设计v3.3-参照Claude系统设计v2.1整合架构与学习状态跟踪内核-重构与结构审查.md`  
> 目标：把已确认架构转换成可执行工作包、依赖关系、验收门槛和首批开发任务。  
> 原则：不建立比赛临时分支，不采用 SQLite/CSV 运行时，不先切一个孤立 Demo；所有正式模块先按契约进入同一个可启动系统，再逐个替换 stub。

---

## 1. 已冻结的一级决策

以下内容进入架构基线，后续实现不得在模块内部自行改变：

1. 前后端分离，前端只通过版本化 API 和事件流访问后端；
2. PostgreSQL 是唯一运行时事实源，CSV/XLSX 只能作为派生导出；
3. Keycloak/OIDC 负责认证，项目只实现租户映射与领域授权；
4. Pi 是首个 Agent Harness 实现，但领域服务不能依赖 Pi 私有数据结构；
5. 模型、OCR、搜索、媒体理解、讲解渲染、沙箱和认证均通过 Provider 契约接入；
6. Agent 可见工具只有 `bash` 和 `search`；shell 能运行一般命令，但环境固定写区、其余只读、无一般外网并有资源/时长上限；
7. KTQ 抽取与 ER 调研使用两个全新、无共享模型历史的 Session；
8. Teaching Agent 负责模型主判答，传统程序只提供科学校验证据；
9. 每个教学 Session 同时生成程序 `ScientificEvaluationReport` 和模型 `TeachingSessionSummary`，长期画像只由 Dream 大模型综合更新；
10. 草稿是可选模块，有草稿和无草稿必须通过同一学习流程契约；
11. 所有正式语义字段都有可审计来源；
12. Qwen-MM-Plugins 的 `core`、`api`、`search`、`edu-agent` 均保留为独立实验模块；
13. `edu-agent` 和 Teaching Agent 通过统一 Learning Artifact 文件协议生成知识可视化 HTML、小题卡、图片和视频；
14. 卡片支持单选、多选、填空、判断，默认允许跳过或不作答直接回复；
15. Teaching Agent 的消息原生支持文字、图片、视频和卡片多段组合。

任何一级决策的变化都要增加 ADR、迁移影响和回归计划，不能只改代码或 Prompt。

## 2. 规划产物和完成标准

规划阶段应产出：

- `architecture/decisions/`：已接受 ADR；
- `packages/contracts/`：跨模块 Schema、事件和 Provider 接口；
- `db/migrations/`：PostgreSQL 模型及约束；
- `deploy/dev/`：能启动所有正式模块的本地组合环境；
- `tests/contract/`：所有 Provider 和服务的契约测试；
- `tests/e2e/`：学生、教师、内容生产、画像更新四类完整流程；
- `evals/`：判答、画像更新、OCR、内容抽取和 Prompt 注入黄金集；
- `apps/web-test/`：仅用于验证流程的前端；
- `docs/runbooks/`：部署、密钥、备份、恢复、模型回退和安全事件手册。

“骨架完成”不是只有目录，而是所有服务能在同一组合环境启动、交换真实契约对象、写入 PostgreSQL、产生审计事件，并以 fake Provider 跑完完整业务流程。

## 3. 先冻结的契约目录

### 3.1 身份、租户与通用标识

- `TenantId`、`UserId`、`StudentId`、`TeacherId`；
- `SessionId`、`AttemptId`、`EventId`、`SnapshotId`；
- 全局时间、版本、幂等键和 correlation/causation ID；
- OIDC subject 与领域用户的映射；
- 租户、班级、学生数据边界。

### 3.2 内容契约

- `SourceDocument`、`SourceFragment`、`QuestionAsset`；
- `CandidateClaim`、`FieldLineage`、`ReviewTask`；
- K/T/Q staging 与冻结投影；
- E/R staging 与引用关系；
- `ChapterPackageManifest`、发布校验报告和撤回事件。

### 3.3 学习契约

- `AssessmentRun`、`QuestionSession`、`Attempt`；
- `AnswerJudgment`、`DiagnosticClaim`、`StateObservation`；
- `InterventionEvent`、`DraftReference`、`QuestionSessionResult`；
- `TeachingMessage`、`LearningArtifactManifest`、`QuestionCard`、`ArtifactResponse`；
- Session 状态机、模式、提示级别和终止原因。

Learning Artifact 契约必须冻结：

- 固定输出目录、允许文件名、MIME、大小和引用 URI；
- `agmath.learning-artifact/v1` manifest；
- `knowledge_visualization`、`question_card`、`mixed_lesson` 三种 kind；
- `native_card`、`sandboxed_html`、`media` 三种 renderer；
- HTML `postMessage` 事件、interaction token 和 sandbox/CSP；
- 单选、多选、填空、判断的答案结构；
- 作答、跳过、不作答直接回复的事件语义；
- Artifact 是否有资格成为正式测量证据。

### 3.4 画像契约

这部分先于 BKT 和 Prompt 代码冻结：

```text
Session events
  → ScientificEvaluationReport        # 教学阶段的传统程序评价
  + TeachingSessionSummary             # 教学模型简要总结
  → SessionLearningRecord              # 成对封装并进入 Dream
  → ProfileEvidenceBundle              # Dream 的多 Session 投影
  → ProfileUpdateDecision             # 大语言模型最终更新
  → ProfileDecisionValidationResult   # 程序只校验
  → StudentSnapshot                    # 物化结果
```

必须定义：

- 每个对象的生产者、消费者和写权限；
- `ScientificEvaluationReport` 的计算输入、参数版本与 trace；
- `TeachingSessionSummary` 的长度、字段、证据引用和禁止写画像规则；
- `SessionLearningRecord` 对双产物的一一对应和完整性约束；
- `ProfileEvidenceBundle` 可包含哪些 Session 内容、裁剪规则和权限；
- `ProfileUpdateDecision` 每个量化/语义字段的证据要求；
- Decision 重试、教师复核、supersede 和 replay 语义；
- Dream 触发、批次窗口、按需回看 Session 原始证据和去重规则；
- `profile_lag` 和模型不可用时如何继续教学。

### 3.5 Provider 契约

- `ModelProvider`：文本/视觉能力声明、结构化输出、流式、取消、成本与追踪；
- `OCRProvider`：本地/API/MCP、页级产物、图片分割、坐标与来源；
- `SearchProvider`：查询、引用、来源元数据、安全策略；
- `MediaUnderstandingProvider`：图像/视频输入和证据引用；
- `ExplanationRenderer`：普通 HTML、交互 HTML、视频；
- `ArtifactPublisher`：目录校验、发布、稳定引用和交互事件；
- `SandboxProvider`：挂载、写区、网络、超时、配额和审计；
- `AuthProvider`：OIDC claims 到领域主体和权限。

每个接口同时定义成功结果、可重试错误、不可重试错误、超时、取消和降级语义。

## 5. 工作流 A：内容生产

### A1. 文档接收与 OCR

- 上传原件，计算哈希并扫描文件；
- 调用 `OCRProvider` 生成 Markdown、布局块、图片和坐标；
- 复用队友 TEACHER 管线的分页、题目切割和题图关联逻辑；
- 同事务写入题干和 `question_asset.image_bytes`；
- 为 OCR 生成的每个字段写来源。

### A2. KTQ 独立 Session

- 创建只含 KTQ Prompt、Skill、Schema 和来源片段的工作区；
- 禁止出现 ER Schema、任务和搜索材料；
- 输出 KTQ candidate，校验后冻结；
- 销毁 Session 工作区和模型历史。

### A3. ER 独立 Session

- 新建 Session，只给 ER 任务、搜索和冻结 KTQ 只读投影；
- 搜索结果先成为来源文档/片段；
- 禁止读取 KTQ 抽取对话、候选推理或写 KTQ；
- 输出 ER candidate 及每字段引用。

### A4. Link、Review、Publish

- 独立服务建立 K/T/Q/E/R 和 MeasurementTarget 关系；
- 执行引用、图结构、答案、许可、重复与字段血缘校验；
- 教师逐字段确认；
- 发布不可变 ChapterPackage。

验收：随机抽取一个正式字段，可以从 API 一路追溯到文档页码/区域、Agent Run、模型、Prompt、工具调用和审核决定。

## 6. 工作流 B：单题教学与模型判答

### B1. Session 编排

- 一题一 Pi Session、一题一沙箱；
- 挂载题目、最小画像、章节包、知识库、错因库和 Skills；
- 根据能力矩阵选择直接多模态模型或文本模型+媒体 Provider；
- 草稿模块按设备/租户策略挂载，不影响基本状态机。

### B2. 模型主判

- GRADE 状态向 Teaching Agent 提供题目、评分规则、回答和可选草稿；
- 类型工具返回符号、数值、解集、单位或图形约束证据；
- Teaching Agent 输出最终 `AnswerJudgment`；
- 模型/工具冲突或高不确定触发第二模型或教师复核；
- 教学阶段的程序评价可以作为 Teaching Agent 追问和总结的参考；
- Session 关闭输出单题证据、`ScientificEvaluationReport` 与 `TeachingSessionSummary`，不直接写长期画像。

### B3. Learning Artifact 与多模态回复

- Teaching Agent/`edu-agent` 只能在 `/workspace/output/artifacts/<artifact_id>/` 写 Artifact；
- `manifest.json` 必需，HTML 使用 `index.html`，原生卡片使用 `card.json`，图片/视频放在 `media/`；
- Teaching Agent 通过 `artifact://<session>/<artifact>` 引用，不返回原始文件路径；
- `ArtifactPublisher` 校验并发布后，前端才渲染；
- `edu-agent` 的知识点 HTML、小题卡和混合讲解统一遵循 `agmath.learning-artifact/v1`；
- HTML 通过受限消息桥提交 `card.answer_submitted`、`card.skipped`、`card.free_text_requested` 等事件；
- 单选、多选、填空、判断卡均默认 `required=false`；
- 学生直接发文字时记录 bypass，不把未答卡片视为错误；
- TeachingMessage 支持 text/image/video/card part；耗时视频通过状态事件异步变为 ready；
- HTML/卡片自身不判答，Teaching Agent 读取交互并作模型判答。

### B4. 安全边界

- Agent 只看到 `bash`、`search`；
- 文件系统除 `tmp/output` 外只读；
- shell 无一般外网、无供应商密钥；
- OCR/视觉/讲解/Artifact 发布通过受控 Broker；
- 每条命令、搜索和 Provider 调用进入审计。

验收：同一题分别用有草稿和无草稿运行；两条路径都能完成判答、追问、Artifact 交互、程序评价、教学总结和 Dream 入队。卡片提交、跳过和直接回复三条路径均可继续 Session。

## 7. 工作流 C：画像量化与 Dream

### C1. 教学阶段的程序科学评价器

输入已确认事件，输出 `ScientificEvaluationReport`：

- BKT 基准；
- 保持率/复测估计；
- 独立观测、提示依赖和错因统计；
- 数据缺口、矛盾和质量标志；
- 参数集、输入事件和完整计算 trace。

它的结果可以交给 Teaching Agent 形成下一步教学和简要总结，但不能写 `StudentSnapshot`，也不能产生“最终掌握”结论。

### C2. 教学总结与双产物封装

Teaching Agent 在关闭 Session 时读取程序评价和本题证据，输出 `TeachingSessionSummary`：

- 本题方法、关键成功和错误；
- 程序评价中需要解释的变化；
- 提示依赖、候选错因和未决项；
- 答案、聊天、草稿和 Artifact 交互引用；
- 模型、Prompt 和 Skill 版本。

系统将报告与总结封装为 `SessionLearningRecord`。缺少任意一项、Session ID 不一致或来源不完整时，不得进入 Dream。

### C3. Dream Context Compiler

按学生、维度和窗口构建 `ProfileEvidenceBundle`：

- 旧画像快照；
- 多个 `SessionLearningRecord` 中成对的程序评价和教学总结；
- 摘要所引用的题目、题图、答案、聊天、提示、可选草稿和 Artifact 交互索引；
- 只有矛盾、证据不足或 Dream 模型明确需要时才展开的原始 Session 投影；
- 题目之间的迁移/难度/表征关系；
- 数据权限、截断和缺失声明。

不得加入 Teaching Agent 的隐藏推理或直接继承其模型 Session。

### C4. Dream/Profile Update LLM

新建独立大模型 Session，以 Profile Skill 和严格 Schema 输出最终 `ProfileUpdateDecision`：

- 每个维度的 `p_baseline`、`p_final` 和状态；
- 证据码、rubric、LR/调整值、正反证和 Session 引用；
- 错因、方法稳定性、提示依赖和语义画像更新；
- 未决项、替代解释、不确定性和复核要求；
- 模型、Prompt、Skill 和输入 bundle 版本。

### C5. Decision Validator 与发布

程序只检查：

- 引用存在且有权限；
- 字段 provenance 完整；
- 参数/调整值在允许范围；
- 算术可以重算；
- 同一证据未双计数；
- 更新幅度、矛盾和高风险状态是否需要教师复核。

校验通过后，reducer 原样物化 Decision；校验失败时退回模型或送审，禁止自动改成程序基准。

### C6. Dream 调度与重放

- 长期画像不做每题一次的 Profile LLM 快更新；每题只生成双产物；
- Dream 按日终、Session 阈值、矛盾、教师请求等条件消费双产物；
- Dream 可以 supersede 旧 Decision，但不覆盖历史；
- 教师纠正后重放：Session 事件 → 程序评价 → 教学总结重建/失效 → Dream Decision → 校验 → 新快照。

验收：给定固定 Session、程序报告、教学总结和 Dream Decision，可以解释每个画像字段的来源；替换一条教师纠正后，旧 Decision 保留，新 Decision 正确 supersede。

## 8. 工作流 D：前端和教师复核

### D1. 流程验证前端

首期只实现：

- OIDC 登录和角色入口；
- 学生首页、单题页、文字/图片回答和可选草稿占位；
- 流式文字/图片/视频回复、Artifact 引用、提示状态和结束本题；
- 原生与 HTML 单选/多选/填空/判断卡片；
- 卡片作答、跳过、不作答直接回复和异步视频状态；
- 程序基准/大模型最终画像的分层报告；
- 内容字段复核；
- 判答/画像 Decision 复核与 supersede；
- 来源追溯页和审计入口。

页面使用生成的 API Client，不在前端复制领域判断。

### D2. 后期专业化

流程和 API 稳定后，将正式 `apps/web` 交给前端专长模型完善设计系统、响应式布局、可访问性、动画和视觉表达。前端美化不得改变后端 Schema 或把判答逻辑搬到浏览器。

## 9. 安全和基础设施工作流

- Keycloak realm、client、role、MFA 和服务账号配置即代码化；
- PostgreSQL RLS、最小权限账号、迁移账号分离；
- 模型/OCR/搜索密钥只进入 Broker 的 secret store；
- 对象存储前缀和数据库租户边界一致；
- 上传扫描、SSRF 防护、CSP、CSRF、CORS 和速率限制；
- Artifact 路径归一化、符号链接逃逸检查、MIME 解码验证、媒体转码和哈希固定；
- edu-agent HTML 无同源 sandbox、严格 CSP、无网络，以及带一次性 token 的受限消息桥；
- 沙箱 rootless、只读根、固定写区、禁网、资源和输出限制；
- SBOM、许可证、依赖固定、漏洞扫描；
- OpenTelemetry trace 贯穿 API、Session、Provider、数据库、任务和 Decision；
- PostgreSQL 与对象存储的备份恢复演练；
- 未成年人数据保存、导出、删除和监护策略。

安全门槛不是最终上线前再补；每个模块的第一个可运行实现就必须带身份、租户、审计和最小权限。

## 12. 第一轮验收门槛

在进入真实内容和模型效果调优前，必须满足：

- 全系统组合环境可重复启动；
- 所有请求有 tenant、actor、trace 和 correlation ID；
- PostgreSQL 中不存在无来源的正式语义字段；
- KTQ 与 ER 的模型历史、Prompt、工具和写区隔离可由测试证明；
- Teaching Agent 不能写画像表；
- 程序评价器不能写 `StudentSnapshot`；
- 每个进入 Dream 的 Session 必须同时有程序评价和教学总结；
- 每题结束不会触发长期画像 LLM 快更新，只有 Dream 能生成 `ProfileUpdateDecision`；
- 只有已通过 Validator 的 `ProfileUpdateDecision` 能生成快照；
- Validator 不能静默修改大模型 Decision；
- 有草稿和无草稿路径都能结束 Session；
- `edu-agent` 能用同一 Artifact 协议生成知识 HTML 和小题卡；
- 文字、图片、视频和混合 TeachingMessage 均可渲染；
- 单选、多选、填空、判断均支持提交、跳过和直接回复；跳过不会生成失败观测；
- 未发布文件、越界路径、危险 HTML 和伪造交互事件均被拒绝；
- shell 越界写、联网、超时和资源炸弹测试全部失败关闭；
- 教师纠正能触发完整重放且保留旧版本；
- 前端不含数据库或模型密钥；
- 所有 Provider 能替换为 fake 并保持契约不变。

达到这些门槛后，才进入真实模型、OCR 质量、证据码区间和教学效果的迭代。
