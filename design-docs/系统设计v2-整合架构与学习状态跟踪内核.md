## 2. 总体架构：五个子系统

```
┌──────────── 教师端 Web ────────────┐   ┌────────── 学生端 Web ──────────┐
│ ①内容生产线      ⑤复审台           │   │ 注册/画像 每日练习 错题重刷 问问AI │
│ 上传→暂存库→确认→正式库             │   └──────────────┬────────────────┘
└──────────────┬─────────────────────┘                  │
               ▼                                        ▼
┌──────────────────────────┐   ┌─────────────────────────────────────┐
│ 正式库：六类数据+引用表    │──▶│ ②教学运行时（主模型 Qwen3.8-Max）     │
└──────────────┬───────────┘   │ 一题一Session一沙箱；search+bash      │
               ▼               │ 产出：Session JSONL + 回顾评价 JSON   │
┌──────────────────────────┐   └──────────────┬──────────────────────┘
│ ④学习状态跟踪内核         │◀── 观测记录 ──┐   │ Session结束事件
│ （纯Python，见§6）        │              │   ▼
│ 选题/三态/计划 由此输出    │   ┌──────────┴──────────────────────────┐
└──────────────────────────┘   │ ③画像系统（辅助模型 DeepSeek V4 Flash）│
```

两类核心 Agent（母稿定案，不增第三类）：**教学 Agent**（question 模式 / report 模式）+ **画像 Agent**（fast 模式 / dream 模式）。外部程序只做六件事：创建 Session、准备工作目录、同步文件、转发消息、触发画像更新、保存 Session。

## 3. 子系统①：内容生产线（教师端，辅助模型异步）

### 3.1 执行路径

1. 教师在教室管理页上传 PDF 讲义/习题/易错总结 → 落 `uploads/<batch_id>/`；
2. 后台任务队列启动内容 agent（DSv4f，pi agent 形态，Skills 控制动作）：
   - 文档转 md：PaddleOCR-VL 管线（复用队友 TEACHER 阶段一脚本，**改造：保留 LaTeX，仅清 PUA/HTML 噪声**）；
   - 知识点抽取 → 题型归纳 → 题目切割打标（K/T/E 多标签）→ 错因归纳 → 诊断规则推导；
   - 联网调研（DSv4f 搜索）为错因/规则补文献佐证，**每条写引用表**；
3. 程序跑 9 项校验（ID 唯一、K/T/E 引用存在、前置无环、答案解析齐全、规则引用有效、来源记录、案例可运行等）；
4. 写**暂存库**（与正式库同构 + `review_status` 列）→ 教师管理页逐表核对 → 确认合入**正式库**（版本化 chapter-pack，可回滚）。

### 3.2 数据层

- 六类表：knowledge_points / question_types / error_causes / questions / diagnosis_rules / student_cases（SQLite 正式库 + CSV 导出双形态）；
- 模板改造：删"使用说明/AI输出格式/Prompt模板/模板总览"四表；删"AI输入拼接"列；"AI识别关键词"→"**关键词**"；
- 新增**引用表 sources**：`ref_id, table_name, row_id, source_type{pdf_page|url|teacher_upload|literature|ai_generated}, locator, excerpt(≤200字), fetched_at, confidence`。每条数据至少一条引用，`ai_generated` 必须显式标注；
- 内核产出的**观测记录表 observations**（§6.3）与**画像版本目录**也属数据层，见各节。

## 4. 子系统②：教学运行时（操作路径级）

### 4.1 Session 生命周期状态机

```
INIT → PRESENT → AWAIT ⇄ CLARIFY(L0)
AWAIT --提交--> JUDGE
JUDGE --对--> VERIFY_PROCESS（过程追问，估计F）--> WRAP
JUDGE --错--> HYPOTHESIZE（列候选错因）→ PROBE（消歧追问，≤3轮）
PROBE --可判--> MICRO_RETEST（可选微型复测1题）→ WRAP
PROBE --学生卡住/求助--> HINT（沿L1→L4逐级，记录等级）→ AWAIT
WRAP：生成回顾评价JSON → 程序校验 → Session关闭事件
```

逐状态规则：
- **INIT**（程序做）：建沙箱、挂载工作区（4.2）、按 4.3 拼系统提示词；
- **PRESENT**：主模型用题目卡呈现题干（KaTeX），不改写题意；
- **AWAIT**：等待作答；学生可点"我卡住了"（→HINT）、"完成"（→JUDGE）；
- **JUDGE**：bash 跑 `scripts/verify_math.py`（SymPy 等价判定：数值代入+符号化简双通道；选择/判断直接比对；填空做等价形式归一）。**模型不得凭语感判对错**；
- **VERIFY_PROCESS**：答对也要一次轻量过程确认（"你是用哪个定理列的式？"），据回答估 F∈{0, 0.3, 0.7, 1.0} 四档（档位定义：0 说不出方法；0.3 能说出定理名但步骤混乱；0.7 步骤对但有跳步/说不清依据；1.0 完整清晰）；
- **HYPOTHESIZE**：从本题 questions.error_ids + diagnosis_rules 取候选错因集（禁止编造库外 ID），按先验频率排序；
- **PROBE**：每轮选**最能区分剩余候选**的追问（依据 diagnosis_rules 的判断依据字段；示例见 4.4.3）；每轮后淘汰/确认候选；最多 3 轮，超出则带多候选进 WRAP（置信度分摊）；
- **HINT**：只在求助模式/学生卡住时进入；严格逐级 L1→L4，禁止跳级，L5 仅复盘模式；每级记录；
- **MICRO_RETEST**：对最高候选出 1 道判断/选择微题验证（如 SSA 出"sinB=0.8 时 B 一定是锐角，对吗？"）；
- **WRAP**：产出回顾评价 JSON（4.6），程序校验 Schema+ID 存在性，不合格打回重写（最多 2 次，仍失败则标 `review_invalid` 人工兜底）。

### 4.2 沙箱工作区（一题一份，只读挂载为主）

```
workspace/
├─ AGENTS.md              # 教学纪律（4.4.1 三模式表 + L0-L5 + 禁止事项）
├─ question.md            # 题干/答案/解析/K-T-E标签/本题诊断目标/允许的提示上限
├─ handoff.md             # 上一题连续性包（4.7，150-300字）
├─ student/
│  ├─ summary.md          # 画像摘要（画像Agent最新版，直接进系统提示词）
│  └─ detail/             # mastery.md 三态明细 / misconceptions.md 错因画像 / recent.md 近期记录
├─ library/               # 本题相关知识点/题型/错因/诊断规则的文件视图（程序按标签裁剪生成）
├─ scripts/verify_math.py, search_questions.py, plot_math.py
├─ skills/                # 仅暴露 名称+描述，按需 read 全文（4.4.4）
└─ tmp/                   # 模型工作草稿（Session结束即弃）
```

写权限：模型只可写 `tmp/` 与最终回顾评价；其余只读。**没有画像更新工具、没有数据库接口**。

### 4.3 三层上下文（原始对话定案，照此实现）

第一层·系统提示词只放：当前模式 / 当前题目 / 本题诊断目标 / 学生摘要（≤5 句，含"本题应重点观察 X"）/ 当前提示等级 / 教学原则。第二层·Skills 目录仅名称+描述。第三层·工作区文件由模型按需 read。禁止把题库、完整画像、历史 Session 预塞进上下文。

### 4.4 教学方式

**4.4.1 三模式行为表**（模式写入 question.md，学生按钮切换，切换即记录）

| 模式 | 目标 | 允许 | 禁止 |
|---|---|---|---|
| 诊断 | 采集独立能力证据 | L0 澄清、中性追问、微型复测 | 任何解法提示（L1+）、评价性反馈泄露对错 |
| 求助 | 帮学生完成当前题 | L1→L4 逐级提示，记录等级 | 直接给答案、跳级提示 |
| 复盘 | 讲透本题与错因 | L5 完整讲解、变式题、edu-agent 生成讲解视频 | — |

**4.4.2 提示等级 L0-L5**（原始对话定案表，话术照用）

| 级 | 行为 | 话术示例 |
|---|---|---|
| L0 澄清 | 只确认含义 | "这里写的是 sin B=0.8 吗？" |
| L1 定位 | 指出检查区域 | "先检查角 B 是否只有一个可能值。" |
| L2 概念 | 提醒相关概念 | "回想正弦函数在 0°-180° 内的对称性。" |
| L3 脚手架 | 给下一步框架 | "先列出两个候选角，再分别检查内角和。" |
| L4 方法 | 明确主要方法 | "使用补角关系和 A+B<180° 进行筛选。" |
| L5 讲解 | 完整过程 | 仅复盘模式 |

**4.4.3 错因消歧（假设驱动，SSA 为范式）**

答错 SSA 题时保留六候选：正弦定理不会 / 边角对应错 / 反三角计算错 / 忽略补角 / 忘检验存在条件 / 偶然笔误。追问链（每问区分一组候选）：①"你用的正弦还是余弦定理？为什么？"（区分定理选择）→ ②"a/sinA 里的 a 和 A 是什么关系？"（边角对应）→ ③"sinB=0.8 时 B 有几个可能值？"（补角意识）→ ④"若 B 取钝角，三角形还成立吗？"（存在性检验）。不同回答落到不同 E-ID；追问语言必须**中性确认式**（"你准备把这条线作为高来使用吗？"），禁止诱导式（"你是不是忽略了补角？"作为首问）。

**4.4.4 Skills 四件套**（沙箱 skills/，比赛版必备三个：diagnose-student、socratic-teaching、select-practice；observe-draft 留待草稿版）

| Skill | 触发描述（进目录层） | 内容要点 |
|---|---|---|
| diagnose-student | 学生作答后形成候选错因并决定是否追问 | 候选来源=库；消歧问选择规则；置信度分摊；何时微型复测 |
| socratic-teaching | 不给答案前提下分级引导 | L0-L5 定义与升级条件；一次只升一级；连续两次同级无效才升级 |
| select-practice | 需要当场追加巩固/变式题时 | 只能从 library/ 检索（search_questions.py），按 §6.9 ZPD 区间挑 |

### 4.5 判答规范

选择/判断：字面比对。填空：SymPy `simplify(expr_student - expr_answer)==0` + 3 组随机数值代入双验证；等价形式白名单（如 √3/2 与 sin60°）。解答：按题型库"评分点"逐点核对，模型陈述核对结论并给出每点依据，最终 A∈{0,1} 以答案比对为准，评分点覆盖率喂给 F。

### 4.6 回顾评价 JSON（主模型唯一出口）

```json
{
  "question_id": "Q_TRI_012", "session_id": "...", "mode": "diagnosis",
  "answer_correct": false,
  "process_familiarity": 0.3,
  "error_causes": [{"id": "E-LOG-001", "confidence": 0.7, "basis": "追问③中认为 sinB=0.8 只对应锐角"},
                    {"id": "E-CAL-001", "confidence": 0.3, "basis": "第二步移项符号错，但自行更正"}],
  "knowledge_points": ["K_TRI_004"], "question_type": "T_TRI_003",
  "hint_level_max": 0, "probe_rounds": 2, "micro_retest": {"asked": true, "correct": false},
  "review": "会列正弦定理，SSA 多解意识薄弱；建议下一题验证补角检查是否迁移。",
  "open_question": "是否主动做存在性检验",   // 未闭合观察点，进 handoff
  "flags": []
}
```

校验器检查：ID 全部存在于库；confidence 合计≤1.2；诊断模式下 hint_level_max ≤ L0；basis 非空。

### 4.7 handoff / continuity.md（原始对话模板，照此生成）

Session 关闭时**程序**统计（题数/连续数/时长/休息），**辅助模型一次低成本压缩**生成上一题摘要，重写 `continuity.md`（150-300 字，可覆盖）：

```markdown
# 当前学习连续性
日期：… 今日已完成：7题 当前连续完成：4题 今日已学习：31分钟 最近一次休息：18分钟前
上一题：题型 SSA个数判断｜经一次追问后完成｜能正确用正弦定理但首次遗漏补角｜使用提示 L1｜
未闭合问题：下一题继续观察是否主动检查补角与内角和
当前建议：不重复讲解正弦定理基础；下一题优先验证多解判断是否迁移
```

下一题系统提示词 = 长期画像摘要 + continuity.md + 当前题目。"上一题犯错"不得写成长期薄弱结论。

### 4.8 诊断轮次 Assessment Run 与 report 模式

一轮完整测评是目录不是状态机：`assessment/{goal.md, continuity.md, sessions/, coverage.md, evidence.md, final-report.md}`。goal.md=本轮目标知识范围与题量预算；coverage.md=程序维护的已覆盖 K/T 清单；轮次继续/结束由内核判定（§6.9 终止条件）。结束→创建 **report Session**（教学 Agent report 模式）：读本轮各题回顾+内核三态输出+长期画像 → 生成掌握度报告与 1-4 周计划（模板见 §6.10）。**即时报告不依赖异步画像**。

## 5. 子系统③：画像系统（操作路径级）

### 5.1 文件结构

```
profile/
├─ current -> versions/2026-08-17/
└─ versions/<日期>/{summary.md, mastery.md, misconceptions.md, strategies.md, update_report.md}
```

### 5.2 快更新路径（触发：每个 Session 关闭事件，队列串行）

1. 输入：本题 Session JSONL + 回顾评价 JSON + 当前画像 current/；
2. 程序校验回顾 JSON（4.6 校验器）；
3. **生成观测记录**（§6.3）：对回顾中每个 K 与 T 维度各一条 {dim, s, w, …}——s、w 由公式计算，辅助模型只负责把 basis 不清的字段回读 Session 补全，**不得改数值**；
4. 调内核 `kernel.update(observations)` → 内核更新 BKT 状态、错因计数、复测调度，追加写 observations 表；
5. 辅助模型增量更新 `student/detail/` 三个 md（mastery.md 由内核输出直接渲染；misconceptions/recent 由辅助模型改写文字）；
6. 程序重写 continuity.md（4.7）；
7. 幂等：以 session_id 去重，重复事件跳过；失败重试 3 次后标记 `profile_lag`，不阻塞下一题（下一题用旧摘要）。

### 5.3 Dream 整理路径（触发：每 5 个 Session 或 日终，两者先到）

1. 输入：current/ 全部文件 + 最近 N 个 Session 的回顾评价 + 内核当前三态快照；
2. 辅助模型执行五步：合并重复结论 → 处理矛盾（新证据优先，但写明弃用原因）→ 区分偶然失误与稳定问题（同错因 ≥2 次独立出现才可写"稳定"）→ 删除过时临时判断 → 重写更短 summary.md（≤400 字）；
3. 写入新版本目录 `versions/<今日>/`，`update_report.md` 记录每处变更+理由+证据 session 引用；`current` 软链切换；
4. 原始 Session 永不修改（一等证据）；画像可整目录回退（对抗长期重写退化，arXiv 2605.12978）。

## 6. 子系统④：学习状态跟踪内核（核心，`src/mastery/` 纯 Python）

**骨架 = 标准 BKT（OATutor 参考实现逐行对应）+ 三个有先例的扩展**：KT-IDEM 式 G/S 分类（pyBKT multigs）、部分得分软证据（partial credit BKT 先例 + 回火似然）、艾宾浩斯时变遗忘（pyBKT forgets 的时间参数化）。跟踪维度：每（学生 × 知识点 K）与（学生 × 题型 T）各一个 BKT 状态；错因 E 单独用衰减计数画像（§6.8）。

### 6.1 状态与参数

每维度状态：`{P_L ∈ [0,1], n_eff, S_days（稳定度）, last_review_at, history[]}`。

先验 P(L0) 由画像分层（画像只影响先验，不构成结论）：自评薄弱/分数<90 → 0.20；中等/90-110 → 0.35；较好/>110 → 0.50。学习率 **T = 0.15**（OATutor 全站用 0.1，我们的每题带追问反馈，取略高，待 M2 标定）。

### 6.2 发射参数 G/S（KT-IDEM：按题目格式×难度定类，固定表）

| 题目格式 | G（不会而对） |
|---|---|
| 判断题 | 0.50 |
| 四选一选择 | 0.25 |
| 填空 | 0.05 |
| 解答/追问确认 | 0.02 |

| 难度 d | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| S（会而错） | 0.05 | 0.08 | 0.10 | 0.12 | 0.15 |

> 猜测与难度**不再用经验折扣系数**：判断题证据弱、难题失手常见，全部由贝叶斯公式经 G/S 自然体现（G=0.5 时答对几乎不推动 P_L——数学替代了拍脑袋）。

### 6.3 观测层：一次作答 → 观测记录

沿用队友得分函数（39 条错因赋值表原样收编为 ψ(E) 查表）：

```
s = A·[0.5 + 0.5·F] + (1−A)·Σ_e conf_e·ψ(e)      # 多候选错因按置信度加权
```

语义：**s 是"概念层正确度"**——答错但仅 E-CAL 运算错（ψ=0.8）对知识点维度仍是较强的"会"证据；运算短板单独记入错因画像（§6.8），不稀释概念判断。

证据权重（只保留三类不适合进 G/S 的因素，连乘）：

```
w = hint_discount(L0:1.0, L1:0.9, L2:0.7, L3:0.4, L4:0.2, L5:0)
  × source(常规 1.0 | 教师确认 1.2 | 视觉/转录不确定 0.1)
  × format_note(微型复测判断题连问 2 题按 1 条 w=0.8 合并，防猜对刷分)
```

观测记录（追加写，不可改——即证据链）：`{obs_id, student, dim, question_id, session_id, s, w, G, S_slip, error_causes, hint_level, mode, ts}`。

### 6.4 标准 BKT 更新（w=1, s∈{0,1} 时与 OATutor BKT-brain.js 完全一致）

```
答对: P(L|obs) = P_L(1−S) / [P_L(1−S) + (1−P_L)G]
答错: P(L|obs) = P_L·S / [P_L·S + (1−P_L)(1−G)]
学习转移: P_L ← P(L|obs) + (1−P(L|obs))·T
```

### 6.5 软证据推广（部分得分 s + 权重 w，回火似然）

```
ℓ_K = [(1−S)^s · S^(1−s)]^w        # "已掌握"假设下的似然
ℓ_N = [G^s · (1−G)^(1−s)]^w        # "未掌握"假设下的似然
P(L|obs) = P_L·ℓ_K / (P_L·ℓ_K + (1−P_L)·ℓ_N)
P_L ← P(L|obs) + (1−P(L|obs))·T    # 学习转移不乘 w：练过+有反馈就有学习机会
n_eff ← n_eff + w
```

性质：w=0（L5 讲解后）证据不动、仅学习转移；s=1,w=1 退化为标准 BKT 答对分支；连续性检查进单元测试（复现队友文档 5 个算例 + OATutor 数值对拍）。

### 6.6 时间层：艾宾浩斯遗忘 + SM-2 稳定度

读取任一维度状态前，先按保持率衰减（等价于 pyBKT forgets 的时间参数化）：

```
R(Δt) = exp(−Δt·ln(10/9)/S_days)      # 定义：Δt=S 时保持率恰为 0.9
P_L ← P_L · R(Δt)                      # Δt=距该维度上次观测的天数
```

稳定度 S_days 更新（仅在"到期复测"即 Δt ≥ 0.5·S 的作答后调整）：

```
初值 S=1（首次 P_L≥0.8 时启动）
复测 s≥0.8:  S ← S×2.5（上限 60 天）    # SM-2 增长系数
复测 0.5≤s<0.8: S ← S×1.3
复测 s<0.5:  S ← max(1, S×0.3)
复测到期时刻 = last_review_at + S 天 → 进入错题重刷队列
```

由此产生自然间隔序列 1 → 2.5 → 6 → 16 → 39 天（Cepeda et al. 2006 间隔效应）。"错题重刷"入口 = 到期队列（按逾期天数×(1−P_L) 排序）。

### 6.7 三态判定与训练决策

| 判定 | 条件 |
|---|---|
| 掌握 | P_L ≥ **0.95**（OATutor/Corbett-Anderson 标准阈值）且 n_eff ≥ 2 |
| 薄弱 | P_L < 0.40 且 n_eff ≥ 2 |
| 待观察 | 其余（含单次满分：P_L 高但 n_eff<2 → 内核自动排一道确认题） |

训练决策沿用队友 D(p,n) 五类结构，条件替换：已掌握(三态=掌握) / 达标(P_L≥0.8 且 n_eff≥2，n<N_max) / 基本达标(n=N_max 且 P_L≥0.8) / 未达标转人工(n=N_max 且 P_L<0.8) / 继续训练(P_L<0.5 高优先；0.5≤P_L<0.8 巩固轮)。N_max=5。

### 6.8 错因画像

每错因 e：`c_e ← 0.9·c_e + w·conf_e`（每题衰减一次）。输出 top-N 错因（附证据 obs 引用）与六大类分布；错因 → error_causes.remedy → 变式/低一档题推荐链。

### 6.9 选题与终止（确定性脚本，辅助模型只在并列时裁决）

预测正确率：`P(c) = P_L(1−S) + (1−P_L)G`（对候选题的格式/难度取 G/S）。

- **诊断模式**：最大化期望信息增益（闭式可算）：`EIG(q) = H(P_L) − [P(c)·H(P_L|对) + (1−P(c))·H(P_L|错)]`（H=二值熵）；乘覆盖需求系数（goal.md 未覆盖维度 ×1.5）；初测每题型各 1 题起步；同维连错且前置未测 → 沿 prereq 图下探一题（ALEKS fringe 思想）。
- **训练模式（每日练习）**：选 `P(c) ∈ [0.6, 0.85]` 的题（85% 规则）；到期复测题优先插队；OATutor 式平手规则：并列取 P_L 最低维度，再随机。
- **终止（一轮测评）**：目标覆盖完成 ∨ 全维度出三态 ∨ max EIG < 0.05 bit ∨ 达题量/时间预算 ∨ 学生结束。（母稿六条的量化版）

### 6.10 报告与学习计划

报告四层：总体（题量/追问数/覆盖）→ K/T 三态视图（附 P_L、n_eff）→ 错因证据卡（结论/证据 obs 引用/替代解释/状态）→ 计划。计划生成：薄弱指数 `ρ_j = (1−P_L_j) × w_j(考频×难度) × relevance(目标分档位→题型权重表)`，按 ρ 降序装入每周可用时间（画像字段），每周产出：目标 + 题型任务（先低一档再原难度）+ 复测节点（§6.6 到期日）+ 达成判据（P_L≥0.8）。
