# 用户呈现形式 v1：产品形态与界面规格

> 日期：2026-08-18  
> 依据：`系统设计v3.3` §0、§3（用户旅程）、§5.4（Artifact 协议）、§8（证据契约）、§9（状态呈现）、§13（Qwen-MM-Plugins/edu-agent）、§18（交付顺序）；对照 `src/apps/web-test/` 现状。  
> 性质：把设计文档翻译为"用户看到什么、每屏有哪些元素、每个元素读哪份数据"，供前端（web-test → apps/web）与演示制作直接执行。

---

## 0. 一句话产品形态

> 一个**证据型的诊断教学系统**：学生以聊天 + 可选草稿做题，系统把每次作答变成**可追溯的判定、程序基准与教学总结**，跨题证据由画像模型整理成**可展开的状态与计划**；教师复核内容与诊断，改判以"取代 + 重放"呈现，永不抹除历史。

它不是"会出题的聊天机器人"，也不是"五个平铺功能页"。所有界面共享一条纪律：**只呈现有证据支撑的结论，且任何结论都能展开到原始证据**（v3.3 §0、§9.7）。

---

## 1. 呈现原则（所有页面通用，产品基调）

| 原则 | 界面表现 | 依据 |
|---|---|---|
| 结论可展开 | 每个状态/判定/错因旁边有"证据"入口，逐级展开到原始作答、片段、模型版本 | §9.7 |
| 不伪装科学 | 未校准参数一律带 `prior_only` 徽标；复测日期不稳定时显示"复测估计不稳定"而非伪造精确日期 | §9.2/§9.6 |
| 判定不装懂 | 模型不确定时输出 `unresolved`，界面呈现"待复核"而不是判错 | §12.1 |
| 跳过不是失败 | 卡片可"不作答直接回复"或跳过，只记录事件，绝不显示为答错/扣分 | §1.1.10、§5.4 |
| 版本透明 | 每次结论显示 model / prompt / 参数集 / 章节包版本（小字 mono） | §14.3 |
| 未决是合法状态 | 证据不足、profile_lag（Dream 未完成）有明确的状态提示，不催促 | §9.5、§11.3 |
| 不可信数据纪律 | 学生作答、模型文本、OCR 文本一律转义渲染（前端已实现） | §16.3 |

## 2. 学生端呈现

### 2.1 首次进入（注册 + 最小画像）

单页表单，五步可一次填完：

- **年级**（下拉）、**当前分**（数字）、**目标分**（数字）、**每周可投入时间**（下拉：1-3/4-6/7-10/10+ 小时）；
- **自认薄弱**（多选标签，来自章节包 K 列表）；
- **设备与草稿方式**（触屏手写 / 纸面拍照 / 无草稿，决定草稿模块是否启用）；
- 页面明示三件事：数据用途、草稿保存方式、**教师可见范围**；
- 提交后创建首次 `AssessmentRun`，用少量覆盖题建立证据基线。

呈现要点：画像只影响首轮选题与计划优先级，界面不得显示"已掌握/薄弱"结论（§3.1-3）。

### 2.2 首页（四个入口）

- **每日练习**：按当前计划 + 薄弱项 + 目标分权重 + 预计成功率选题；卡片显示题目预览、模式、预计耗时；
- **错题重刷**：**按复测到期程度排序**（不是按做错时间），每张卡显示错因摘要与"距下次复测 N 天"；
- **问问 AI**：学生自带题目或自由提问；库外题可教学，但界面标注"本题不计入正式画像"，只有完成 K/T/E 标注后才转证据（§3.2）；
- **报告与计划**：见 2.4。

### 2.3 单题学习页（核心界面）

#### 布局（§3.3）

```text
┌────────────────────────────────────────────────────────┐
│ 顶栏：AGMATH · 模式徽标（诊断/求助/复盘） · 独立证据徽标 │
├───────────────────────────────┬────────────────────────┤
│ 聊天与内容流（主）             │ 草稿区（可选模块）      │
│  • 题目卡（只读，章节包来源）  │  • 可调整大小           │
│  • TeachingMessage 多段回复    │  • 被引用区域高亮       │
│  • 交互卡片（可跳过）          │  • draft:// 引用可点击  │
│  • 证据条目（判定/基准/总结）  │  • 手机端全屏切换       │
├───────────────────────────────┴────────────────────────┤
│ 固定动作条：我卡住了 · 检查这一步 · 我不确定方法 · 完成本题 │
└────────────────────────────────────────────────────────┘
```

桌面：聊天与内容流为主，草稿启用时右侧可调整草稿区；手机端在"聊天 / Artifact / 全屏草稿"三个视图间切换。

#### 固定元素（每题都存在）

1. **题目卡**：题干、章节包版本（小字）；库外题（问问 AI）带"不计入正式画像"标注；
2. **模式徽标**：诊断（计入独立证据）/ 求助（提示后不计）/ 复盘（讲解不算证据）；
3. **观察指示**：当前是否正在观察草稿（"正在读你的草稿…"）；
4. **四个动作按钮**：`我卡住了`（进入求助）、`检查这一步`（提示当前步）、`我不确定方法`（方法级提示）、`完成本题`（结束 Session）；
5. **提示等级指示**：L0-L5 当前档位（小徽标）。

#### TeachingMessage 多段回复渲染（§5.4）

一条回复由多段组成，按段渲染：文字（markdown）/ 图片（artifact:// 引用 + alt 替代文本）/ 视频（标题 + 字幕 + `pending → ready|failed` 占位更新，不阻塞聊天）/ 卡片。

**Artifact 引用**（`artifact://<session>/<artifact_id>`）渲染为：
- 文件预览（图片缩略 / 视频首帧 / HTML 卡片）；
- 来源行：生成者（edu-agent / Teaching Agent）、生成状态、绑定题目与模型版本；
- 未发布/越界引用一律拒绝渲染（前端只认已发布 URI）。

**卡片**（question_card）：`提交答案` 与 `不作答，直接回复` 两条路径并排；填写区可选；**卡片非阻塞**，可跳过或忽略继续聊天。跳过/直接回复不产生失败观测。

#### 一次作答的证据呈现节律

```text
出题 → 作答（聊天/草稿，无草稿完整可用）
  → [判读中]（pending 动效，不阻塞）
  → 判定：verdict（正确/部分正确/不正确/待复核）+ rubric 逐项（达成/未达成/待澄清）
           + 面向审计的简短理由 + 不确定度
  → 程序基准：P(掌握) 数值 + prior_only 徽标 + 独立观测次数 + 参数集
  → 教学总结：模型对本题的简要过程观察（120 字内，不下长期结论）
  → 追问/探针卡（如补角判断卡，可跳过；最多三轮，由信息价值决定）
  → 完成本题 → 状态印章推进至 QUEUE_DREAM（长期画像异步更新）
```

每个判定条目可展开：评分点证据、模型版本、prompt 版本（mono 小字）。

### 2.4 报告与计划

**画像快照区**（已有雏形，report.html 需扩展）：

- 每个维度一张卡：维度名 + **五档状态徽标**（证据不足/薄弱/学习中/可能掌握/已掌握）+ P(画像) 数值；
- **程序基准 vs 最终画像双条对比**（已有实现）：差值可展开到"证据账本"（每条证据码、LR 选择、session 引用、反证、解释）；
- 观测次数、不确定度、快照版本链（supersede）；
- 无快照时显示 profile_lag 提示："画像整理中，教学继续使用上一快照"。

**复测与错因区**（待实现）：

- 下一次复测日期（I90 保持率驱动；数据不足显示"复测估计不稳定"）；
- 错因列表：suspected/confirmed/improving/resolved/superseded 六档徽标 + 证据数 × 置信 × 时效 × 相关度排序，可展开到原始证据。

**学习计划区**（§10.3，待实现）：

- 1-4 周计划卡片：任务原子（知识补讲/低一档练习/原难度练习/迁移题/延迟复测），每项含达成判据与复测条件；
- 计划由确定性约束排布，模型只生成"为什么先做这个"的自然语言解释。

## 3. 教师端呈现

### 3.1 两个独立队列（§3.4）

1. **内容复核队列**（content 管线产物）：K/T/E/Q/R 与来源字段，每条可一键展开 `field_lineage`（来源片段、页码、Agent Run、模型、Prompt、审核决定、置信度）；裁决：确认/修改/拒绝/合并；
2. **学生诊断复核队列**（student_diagnosis）：原题、草稿时间轴、聊天、判答、K/T/E 结论、替代解释、算法状态变化；改判表单（已有雏形）：观测 ID → 新结论 → 理由（必填，进审计）→ 提交后呈现"取代 + 重放基准 + 修订记录重新入队"（已实现）。

### 3.2 其余页面（阶段 C/D 呈现工作）

班级页（学生列表 + 状态概览）、学生趋势页（维度状态随时间变化）、章节包版本页（不可变版本 + manifest_hash + 发布记录）、导入导出页（官方六表派生导出）、黄金案例回归结果（评测报告）。

## 4. 对外 / 参赛呈现（2026-08-20 节点）

竞赛要求的表格、案例与演示视频**全部由正式系统派生**（§18 阶段 D），不维护临时单机分支。

1. **演示主链路**（§18 首个全链路验收场景）：学生做一道 SSA 题 → Teaching Agent 引用 `edu-agent` 生成的 SSA 动态 HTML 与一张可跳过的补角判断卡 → 学生作答或直接文字回复 → 模型主判（rubric 逐项）→ 双产物呈现 → 跨题生成更多双产物 → Dream 发布画像 → 报告页看到五档状态与证据账本 → 教师改判一条观测并重放。
2. **无草稿/跳过卡片/视频生成失败也必须能完整演示**（同一验收）——恰好也是产品卖点：设备不支持草稿不丢诊断。
3. **官方六表**：作为 PostgreSQL 派生导出（CSV/XLSX），含来源与字段血缘导出表（§7.4）。
4. **演示视频**：从正式系统录制：学生首页 → 单题学习页全交互 → 报告页证据展开 → 教师复核改判。
