## 1. 本轮结论

- 科学内核的目标：所有"数字"由确定性内核产出，模型只负责"解释"；可审计、可复现、科学准确。
- 引擎选型结论（修正"当初选型草率"的判断）：**pyBKT 保留不替换**——原始对话从未出现 pyBKT，
  它是侧设计阶段引入的；按原始对话路线补两环：**pyKT 建 kt-lab（离线评测）** 与 **DAS3H 保持率基准**。
- 全部内核抽象为 `MasteryEngine` 接口族，调用方（短记忆链、Dream、选题、计划、报告）只认接口；
  换引擎 = 注册新实现，调用方零改动。
- 判答器是内核二值观测的上游守卫：模型判答 + 校验器兜底；判答产物中的富信息
  （uncertainty/rubric 粒度/slip-guess 识别/行为特征）当前大部分被压掉，按三通道分阶段捡回。
- 数据契约以 `runtime_state_observation` 为共同观测源，唯一缺口为 `is_retention_test` 标记。

## 2. 分层模型回顾（v3.3 §9.1，不变）

```text
M_k  掌握层：习得概率（BKT）          → OATutor TS 引擎（实时） + pyBKT（校准/批量）
R_k  保持率层：当前可提取性（艾宾浩斯）→ I90 网格后验（自建）+ DAS3H 离线基准
C_e  错因层：证据状态                 → 证据集合 + 六档状态
P    画像层：Dream 大模型最终更新      → 双产物 + pyBKT Roster 程序基准 + Validator
```

三层不得混成一个数：时间衰减不改写 M；运算错误不直接等价概念掌握；提示后成功不算独立证据。

## 3. 引擎选型：三件套与数据需求

### 3.1 原始对话的选型历史（2026-08-16）

`design-docs/原始对话/` 中从未出现 "pyBKT"。对话明确路线：
**比赛版=规则/Beta/简化 BKT；商业验证=标准 BKT；积累数据后=pyKT 评测不同 KT 模型**。
pyBKT 是后期侧设计文档引入——"选型草率"的真实含义是论证缺失，不是选错。

### 3.2 三件套定位

| 组件 | 角色 | 数据需求 | 集成方式 |
|---|---|---|---|
| **pyBKT**（保留） | M_k 批量校准 + Dream 程序基准（Roster） | 每技能几十~几百学生序列后 EM fit | Python 侧车 stdin/stdout JSON-lines（现状） |
| **pyKT**（新增 kt-lab） | 离线深度 KT 评测（DKT-Forget/FoLiBiKT/LefoKT） | 几万交互起步，**只离线** | Python 库，标准化序列 CSV |
| **ktm/DAS3H**（新增） | R_k 遗忘假设离线基准（衰减计数 e^{-Δt/τ}） | 中等量带时间戳练习史 | Python 库，sklearn 流水线 |

**pyBKT 无法胜任的需求点**（确认）：墙钟时间衰减（forgets 非连续时间层 → R_k 必须自建）；
连续题难度（multigs 是分类式 KT-IDEM 非 IRT 数值难度）；部分得分软证据；实时性（纯 Python 慢、
C++ 路径有 fixed-parameters 兼容 bug，侧车已钉版打补丁）。

**DAS3H 与 I90 网格的区别**（用于 R_k 校验而非竞争）：

| 维度 | I90 网格（排程） | DAS3H（基准） |
|---|---|---|
| 本质 | 单变量记忆定律 R(Δt\|I90)=0.9^(Δt/I90)，贝叶斯后验于离散网格 | 多变量统计模型：P(对)=σ(θ+δ+技能+Σ衰减练习计数) |
| 曲线 | 固定指数形式 | τ 每技能可学，多次练习叠加体现间隔效应 |
| 用途 | 决定何时复测（保持率首降 <0.85） | 在同一批带噪观测上对比拟合优度，验证 I90 假设 |

### 3.3 数据需求分层（零数据 → 校准）

| 内核 | 零数据可用 | 需要什么 |
|---|---|---|
| OATutor TS 引擎 / I90 网格 | ✅（专家先验 / 均匀先验） | 无 |
| pyBKT | 预测可用、校准需数据 | 群体序列 EM fit，每技能独立 |
| ktm/DAS3H | ❌ | 监督训练（群体数据），推理期单学生锚定 |
| pyKT | ❌ | 深度学习，大规模数据集，仅离线 |

**训练期=跨学生统计，推理期=单学生锚定**：BKT 系是"群体参数 + 逐学生隐状态"；
DAS3H 是"群体拟合 θ/δ/τ + 单学生能力参数与衰减计数"；pyKT 是"群体网络 + 单学生序列输入"。

## 4. 统一数据契约（观测）

### 4.1 观测字段（`runtime_state_observation` 已建，逐字段对应）

| 接口字段 | 库中列 | 说明 |
|---|---|---|
| order_id（幂等键） | observation_id | 全链路幂等 |
| student_id | student_id | 学生 |
| dimension_id | dimension_id | 技能维度 |
| question_id | question_id | item 粒度（DAS3H 难度、判答、选题需要） |
| outcome | outcome → 映射 | success→1 / failure→0 / unresolved→-1 |
| timestamp | created_at | R_k/DAS3H 的 Δt |
| independent | independent | 证据质量门：非独立观测不进内核 |
| hint_level | hint_level | 与 independent 联动（CHECK 已约束） |
| supersedes | supersedes | 教师改判重放 |
| session_id | session_id | 溯源、distinct sessions 计数 |
| **is_retention_test** | ❌ **缺失** | I90 只吃延迟复测——契约缺口，需新增（payload 或新列） |

### 4.2 verdict → 观测映射（learning/index.ts 确认）

| verdict | 观测 | 说明 |
|---|---|---|
| correct | success | 直接通过 |
| incorrect | failure | 直接不通过 |
| partially_correct | 按评分点拆分 | 每测量维度对应自己的 rubric item：met→success / not_met→failure |
| unresolved | 不产生观测 | 判不了不猜测，不进内核 |

之后过两道门：独立证据门（independent=false 提示后成功不算）+ unresolved 过滤。

## 5. MasteryEngine 接口设计

### 5.1 操作族（全部内核共享的数据契约之上的同一操作集）

```ts
interface MasteryEngine {
  readonly engineId: string;              // 审计必需
  calibrate(dataset: Observation[], opts?: CalibrateOpts): ParameterSet;   // 离线
  update(obs: Observation, evidence: Evidence, params: ParameterSet): StudentState;  // 在线增量
  replay(history: Observation[], params: ParameterSet): StudentState;      // 可审计重放（Dream 基准）
  mastery(state: StudentState, dim: string): number;                        // 查询
  evaluate(dataset: Observation[], baseline?: ParameterSet): EvalReport;   // 离线对拍
}
```

### 5.2 实现注册表

| 实现 | 引擎 | 角色 |
|---|---|---|
| TsEngine | packages/mastery | 在线实时（零数据可跑） |
| PyBktSidecar | sidecars/pybkt | 校准 + Dream 权威基准 |
| KtLab | pyKT（离线） | 长期深度对照 |
| Das3hBench | ktm（离线） | R_k 遗忘假设验证 |

### 5.3 关键设计点

1. **参数集版本化进接口**：`ParameterSet` 带 ID（bkt_prior_v1 / bkt_cal_v1）+ calibration 状态；
   update/replay 显式带参，结果可追溯。
2. **引擎身份进结果**：每个输出携带 engineId + parameterSetId；Dream 的 p_baseline 必须绑定
   `PyBktSidecar.replay` + 具体参数集。
3. **幂等**：order_id 驱动的确定性重放是接口契约。
4. **错误分级**：显式 502/422，禁止静默回退（bkt-sidecar.ts 纪律升格为接口级约定）。
5. **独立接口族**：MasteryEngine（预测/状态）、RetentionEngine（I90 排程）、Verifier（判答/引用/
   算术校验）、Selector（选题评分）——按职责分，不塞上帝接口。
6. **BktParams 与 pyBKT 参数映射**：pyBKT fit 输出（prior/learns/slips/guesses）→ BktParams
   形状（probMastery/probTransit/probSlip/probGuess + id + calibration）的映射层属接口职责。

### 5.4 参数获得路径（四阶段）

| 阶段 | 获得方式 | 值 |
|---|---|---|
| 零数据 | 设计先验 BKT_PRIOR_V1 | L0=0.3（OATutor 0.1 上调）、T=0（纯诊断纪律）、S=0.1（OATutor 默认）、G=0.2（保守上调） |
| 积累期 | runtime_state_observation 沉淀 | 每技能几十~几百学生 |
| 校准期 | pyBKT 离线 EM fit → 验证 → 版本化 | 交叉验证 + 与 TS 引擎对拍差 0.0 + S/G 落 0.05~0.3 区间 |
| 持续期 | partial_fit 增量 | 参数集版本链可回退 |

纪律：只吃 independent 确认观测；量不够保持 prior_only 不伪造校准；参数集 ID 进审计链。

## 6. 判答器（观测质量守卫）

### 6.1 定位

判答器是内核二值观测的**上游生产者**：学生作答 → 判答 → verdict → 观测 → 内核。
它不是独立服务，是任务（teach-grade）+ 表（runtime_answer_verdict）+ 校验器组合。

### 6.2 执行与触发（当前实现）

- **执行**：主对话模型（deepseek-v4-flash-vision-exp）按 `teach_grade` 任务在 Pi 会话内判答
  （`runTask({taskType:"teach_grade"})`，统一 Agent 壳，非独立 API 调用）。
- **输入**：题目 + 评分点（rubric）+ 学生作答（不可信数据块，指令不执行）。
- **触发**：流程驱动（SUBMIT→GRADE 状态机 + 诊断追问 probe 最多三轮），模型不主动发起判答。
- **输出**：AnswerJudgment{verdict, rubric_items[], decision_summary, uncertainty} → 落表
  （model_id/prompt_version 审计）。
- **新架构蓝图（未实施）**：对话内自然判答（学生最后一条消息=作答），后台链 fork 副本 followUp
  产出正式判答——属 P2 教学闭环范围。

### 6.3 判答器与状态判定的关系

判答器管"答得对不对"（每次作答，LLM 按 rubric）；内核管"会不会"（每学生×技能，统计推断）。
判答器看得见"他好像会"，但**永远不写掌握度**——只把二值交给内核（写路径分离的延伸）。

## 7. 富信息捡回：三通道分级实现

判答器产出的富信息（uncertainty/rubric 粒度/slip-guess 识别/行为特征）当前大部分被压成二值
或只存审计。按风险从低到高分三通道捡回，每通道有统计语义与验证门。

### 7.1 通道 1：uncertainty → 似然折扣（P1，立即可做）

```
折扣更新：P(L|y) = P(L)·L_y^d / [P(L)·L_y^d + (1-P(L))·L_¬y^d]
          d = 1.0(low) / 0.7(medium) / 0.4(high)
```

性质：只把证据往"没有"方向调，永不翻转方向；LLM 误判代价上限=这条观测白费。
门控：对拍 DiscountedBKT 不劣于标准 BKT。

### 7.2 通道 2：slip/guess 识别 → 两传感器融合（P2，需黄金集校准）

判答器输出 slip_likelihood/guess_likelihood 作为**第二观测**进似然，不直接调 S/G：

```
P(L | 答错, LLM说失误) = S·q·P(L) / [S·q·P(L) + (1-G)·r·(1-P(L))]
q=灵敏度（真失误被认出） r=特异度（假报失误率）
```

**q/r 从黄金错因轨迹标注校准**；q>0.8 且 r<0.2 才启用，不达标不上线。
**禁止**：逐观测 S_eff 覆盖（参数篡改，破坏概率语义；且 LLM 判断与结果同源相关，
会系统性高估弱学生掌握度——双重计费）。

### 7.3 通道 3：行为特征 + C_e 证据 → 分层逐学生 S_i（P3，需群体数据）

```
S_i = σ(μ_s + β·features_i + u_i)     β 数据拟合；u_i 学生随机效应收缩
features：C_e 粗心证据计数（suspected/confirmed）+ 判答器行为特征（process_shown/速度/模式）
```

- 学生 0 数据 → S_i=群体均值（不崩溃）；C_e 证实反复粗心 → S_i 上移 → 失败自动降权。
- C_e 证据独立于二值，无双重计费。
- 识别性：区分"粗心"（高 S）与"不会"（低 L）是统计识别问题，分层收缩 + 协变量是少样本解法。

### 7.4 不做的（三条纪律）

LLM 直接写状态；LLM 直接调 S/G 数值；翻转证据方向。

## 8. 数据来源与演进

### 8.1 五条来源线

| 来源 | 产生方式 | 依赖 |
|---|---|---|
| 观测 | 产品运行副产品（判答产物） | 教学闭环（P2）上线即积累 |
| 维度/难度/rubric | 内容管线（KTQ/ER 抽取+复核） | 内容管线迁移（A） |
| 校准数据 | 真实使用积累 | 几百学生量级后启动 fit |
| 保持率数据 | **主动采集**：planner 排复测 → is_retention_test 观测 | 复测流程（P4） |
| 黄金错因轨迹 | 人工标注（比赛资料+原始对话材料） | 人工，验收前完成 |

### 8.2 数据闭环

```
观测 → 内核 → 状态快照 → 选题器（读快照选下一题）→ 学生做题 → 判答 → 新观测
```

内核既生产状态又消费状态，形成自我强化测量闭环；选题器的"学生状态快照"输入 =
调用内核 mastery() 接口的输出。

## 9. 验证方案（四路对拍）

同一份 observations.jsonl 上四路并行：

- OATutor TS 引擎（已与 pyBKT 对拍差 0.0）
- pyBKT Roster
- pyKT（DKT 基线）
- ktm（DAS3H）

指标：下一题预测 AUC/RMSE；逐维度 p_mastery 的 Spearman 秩相关；时间间隔分桶衰减曲线
与 I90 网格拟合对比。改进变体（Discounted/Contextual/Hierarchical）同样入对拍，不劣于标准
BKT 才保留。

## 10. 验收条件

1. 观测契约完整：is_retention_test 标记可用，verdict 映射可复现。
2. MasteryEngine 接口四个实现注册，同一数据四路对拍报告可生成。
3. p_baseline 可追溯：engineId + parameterSetId + replay 确定性。
4. 判答器输出扩展字段（uncertainty/slip_likelihood/行为特征）经校验器核对，落库可查。
5. 通道 1 对拍不劣于标准；通道 2 有 q/r 校准证据；通道 3 有拟合优度报告。
6. 零数据阶段 prior_only 不伪装 calibrated；参数集版本链可回退。

## 11. 实施顺序

1. P1：观测契约补 is_retention_test；MasteryEngine 接口 + 四实现注册；四路对拍脚本。
2. P1：判答器输出扩展（uncertainty 消费）+ DiscountedBKT 变体 + 对拍。
3. P2：黄金错因轨迹标注 → 校准 q/r → ContextualBKT 变体（达标才启用）。
4. P3：C_e 证据计数 + 行为特征 → HierarchicalBKT 变体（群体数据后）。
5. kt-lab 与 DAS3H 基准接入 evaluate 接口，纳入验收报告。

## 12. 遗留疑问

1. SLR integrity_passed 的完整校验规则定义位置未确认。
2. partially_correct 的逐维度映射在开放题多评分点场景下的边界（跨维度 rubric item 归属）。
3. 判答器行为特征（process_shown 等）的采集方式与存储位置（观测 payload 扩展 vs 新表）。
4. 黄金错因轨迹的标注格式与 q/r 统计口径需与教师复核流程对齐。
