## 一、项目背景与赛题理解

### 1.1 赛事信息

- **赛事**：长株潭 Agent 训练营暨创新开发大赛（命题式赛道），长沙/株洲/湘潭数据局主办，CSDN 承办；主题"Agent 智能体赋能千行百业转型升级"。奖项：一等奖 1、二等奖 2、三等奖 3、优秀奖 10。
- **截止**：官网原截止 2026-06-20 已过期，群通知延至 **8 月 20 日**（以群内最新通知为准）。
- **通用规则**：每队 1-5 人；作品必须基于大模型并至少体现**工具调用、规划或记忆之一**的 Agent 特征；必须可运行、可演示；交付物含在线 Demo、代码/部署包+README、完整结构化数据、数据整理说明、技术方案说明、≥3 完整学生案例、5 分钟以内演示视频。
- **评分权重**：业务价值 30%、技术实现 20%、创新性 20%、完成度 20%、展示表达 10%。
- **命题**：高中数学知识掌握诊断与学习规划 Agent（试点章节：**解三角形**）。主办方提供 5 份课件 PDF（教师版+学生版）及《高中数学 AI 题库模板-v1.xlsx》。

### 1.2 赛题核心要求

1. 聊天采集学生画像：年级、当前分数、目标分数、可投入时间、自认薄弱内容；
2. 少量选择/判断/填空/追问完成轻量测评，按作答**动态自适应**选后续题；
3. 每次错误尽量落到**知识点 ID、题型 ID、错因 ID**，并给出判断依据；
4. 输出章节**掌握度报告**（漏洞原因、风险等级）；
5. 结合目标分与可投入时间生成 **1-4 周学习计划**。

**必选能力（7 项）**：资料结构化、聊天式轻量测评、自适应出题、错因归因、掌握度报告、学习计划、可解释性。

**最低数据规模（硬指标）**：知识点 ≥25、题型 ≥20、常见错因 ≥20、测评题/题库 ≥80 道、诊断规则 ≥20、完整学生案例 ≥3；覆盖五个专题。

**五个专题**：①入门题型（正余弦定理、齐次转化、三角形个数/形状、面积、实际应用）；②中线/角平分线/高线（多路径解法）；③外接圆/内切圆/多三角形（公共边公共角转化）；④最值与范围（角化边+基本不等式、边化角+三角函数性质、隐含定义域）；⑤定理与模型（正切恒等式、正弦平方差、圆幂定理、隐圆、阿波罗尼斯圆、托勒密定理）。

**附加功能（加分项）**：答错后多轮追问；当前分→目标分路径规划；低一档/变式题；教师复核报告；按 Excel 模板迁移新章节；测评历史与复测建议。

**Excel 模板预设**：知识点库、题型库、错因库、带标签题库、诊断规则库、AI 结构化输出、Prompt 模板、模板总览；模板 AI 流程 = 题目+学生答案 → 识别 K/T/E ID → 检索诊断规则 → 生成解析与建议 → 更新画像；结构设计为**跨章节通用**。

### 1.3 材料包三层资产

①五专题完整教学内容体系（教师版 109 页+学生版，结构为"课程把控→必备知识→题型归纳→例题多解法→习题巩固"）；②通用诊断数据模型（Excel 模板）；③可迁移产品机制。定位：**解三角形 = 首个可插拔章节内容包/垂直切片**，产品目标为可迁移到全部高中数学章节的长期系统。

## 二、产品定位与形态

### 2.1 形态演变轨迹（重要决策史）

1. **队友初版（AGMATG）**：多模态输入→OCR/LaTeX 预处理→RAG 底座→各能力独立 Workflow（知识点诊断/高考组卷/学情规划/教案生成…）——被判定"范围严重扩大、主次颠倒"。
2. **收缩为"解三角形诊断+规划"**，再修正为"商业级骨架+有限内容范围"。
3. **草稿本形态之争**：草稿本为主交互 → 自纠偏题（题目明确"聊天式"）→ 融合为"聊天主导、草稿取证" → 用户坚持下最终定案"**草稿主交互、聊天主引导**"。
4. **架构之争**：领域工具状态机 → LangGraph 外层状态机+内层 Agent → Pi Agent+容器沙箱（工具化）→ 用户否定"太复杂" → **文件系统原生极简架构定案**。

### 2.2 最终产品定义

> "以**草稿纸作为主要数学表达空间**，以**聊天作为诊断与教学控制通道**，以**过程证据**驱动自适应测评、错因归因、掌握度判断和学习规划的高中数学教学 Agent。"

- 学生主要在数字草稿纸上画图、加辅助线、标注条件、列式和推导；Agent 在侧边聊天栏发题、追问、提示、总结，**不直接在草稿上批注**，保持接近真实考试的思考书写习惯。
- 两种使用模式：**实时数字草稿**（平板/触屏/数位板）与**纸面拍照上传**（手机/普通电脑，可写到一半求助、完成后复盘）。
- 宣传语："**不只看学生答错了什么，更观察他是怎样一步步走到这里的。**"（另版："看见学生怎么想，而不只是看答案对不对"）。
- 差异化四机制：**草稿过程可观察、诊断假设可消歧、结论证据可回放、学习计划可复测**。

### 2.3 三种模式显式区分（核心需求冲突解法）

| 模式 | 目标 | Agent 行为 |
|---|---|---|
| 诊断模式 | 获取真实独立能力证据 | 不提示解法，只中性澄清+必要追问 |
| 求助模式 | 帮学生继续完成当前题 | 逐级提示并记录提示等级 |
| 复盘模式 | 理解完整解法和错因 | 可完整讲解、正确步骤、变式训练 |

### 2.4 用户对象（四类）

- **学生端**（主界面）：左聊天右草稿双栏；画像采集（年级/当前分/目标分/每周时间/自认薄弱/设备/是否允许保存草稿）；接收题/追问/提示/总结；数字笔迹或照片表达；查看报告/证据/计划；复测。画像**只影响首题与计划优先级**，不直接形成掌握度结论。
- **教师端**（复核而非代替）：原题/答案/草稿关键帧/聊天过程；Agent 的 K/T/E 判断与置信度；区分"学生错误"与"视觉识别不确定"；确认/修改/标记"待观察"+复核理由；多次测评变化。修改不覆盖 AI 原结论（保存 AI 原结论→教师修改→理由→时间→证据）。比赛版只需单学生单结论复核页。
- **教研与内容运营端**：维护章节内容包；Excel 导入校验（ID 唯一/前置无环/解析完整/KTE 关联/规则引用/版本发布回滚/黄金案例回归/章节迁移）。
- **系统管理员与模型运营端**：模型/工具配置、Prompt 与规则版本、成本延迟、失败会话回放、数据导出删除、安全审计、评测集版本对比。

### 2.5 界面与交互设计

- 桌面双栏：聊天区 **28%-34%**、草稿区 **66%-72%**；题目卡固定/可折叠；底部提交答案框+[我卡住了]+[完成本题]。
- 草稿工具极简：一种基础笔触、橡皮或撤销、清空当前页、缩放移动画布、新建附加页；划线删除**保留真实修改轨迹**；低频操作进二级菜单需确认。用户坚持"长按停顿自动修正直线/圆/椭圆"（修正**保留原始轨迹**，系统辅助结果不用于评价学生画图能力）。
- "无限画布"= **存储无限、书写尺度相对固定的连续纸张**（禁止任意缩放，保证书写尺度与 OCR 稳定）。
- 主动求助 4 按钮（改变 Agent 观察目标）："我卡住了"/"帮我看看这一步"/"我不确定方法是否可行"/"我已经完成，开始诊断"。
- 视觉风格：米白/浅灰低对比、深色单色笔迹、中性蓝交互、橙色待确认、红色仅验证后风险错误；状态须文字+图标；手机端单栏纵向、草稿全屏、聊天可上拉面板。
- 教师"三栏复核"：左题目聊天、中草稿时间轴关键帧（点证据自动跳转）、右 AI 结论/规则/置信度/操作。
- 报告四层：①总体结论（题量/追问数/覆盖）②五档掌握度视图 ③错因证据卡（结论/证据/反证/状态）④学习计划（周目标/任务/复测条件）。
- Agent 交互纪律：**不写入草稿**（禁补全公式/画辅助线/改错/删除/覆盖标准答案）；不在连续书写时打断；观察透明（是否在看、看哪里、哪些证据入报告）；**提示等级 L0-L5**（L0 澄清 → L1 定位 → L2 概念 → L3 脚手架 → L4 方法 → L5 完整讲解仅复盘模式）；掌握度更新**必须记录提示等级**。

## 三、最终架构：文件系统原生教学 Agent（定案）

### 3.1 架构演进史（结论）

1. 领域工具版（9 个草稿工具/14 动作/状态机）→ 被否"太复杂"；
2. LangGraph 版（外层确定性状态机+内层 Pi 式观察子图）→ 论证可行但未采用；
3. Pi Agent+容器沙箱版（Extension 领域工具+propose_* 提案）→ 被否"重新变成传统业务服务"；
4. **定案：文件系统原生**——"让模型生活在一个为教学任务组织好的文件系统中"。

### 3.2 定案架构

> **"文件系统原生的教学 Agent：一题一 Session；Prompt 提供当前任务，Files 提供外部记忆，Skills 提供按需教学方法，Shell（read+bash）提供通用计算能力，Dream Agent（画像 Agent）负责跨 Session 异步画像整合。"**

- **教学 Agent 只保留 `read` + `bash` 两个工具**（不需要 write/edit 和任何领域工具）；一切能力 = 读文件+执行固定脚本（`python scripts/render_draft.py --recent 20s`、`verify_math.py "sin(B)=0.8"`、`search_questions.py --knowledge K_TRI_04`…）。"bash 就是通用工具路由器。"
- **最小工作目录**：`AGENTS.md`、`question.md`、`student/{summary.md, detail/}`、`materials/`、`history/{index.md, sessions/}`、`draft/{strokes.jsonl, state.json, latest.png, snapshots/}`、`scripts/`、`skills/{observe-draft, diagnose-student, socratic-teaching, select-practice}`、`tmp/`。不暴露数据库接口、**不需要 RAG 服务**（底层可用数据库，对 Agent 只是文件）。
- **上下文三层**：①系统提示词只放本轮最重要信息（模式/题目/诊断目标/学生摘要/提示等级/教学原则）；②Skills 目录只暴露名称+描述，需要时再 read 完整 SKILL.md（渐进式披露）；③工作区文件按需读取。
- **外部程序只做 6 件事**：创建题目 Session、准备工作目录、同步草稿文件、转发聊天消息、启动异步画像更新、保存 Session——不理解教学逻辑。

### 3.3 一题一 Session（五优势）

避免前几题长对话污染当前上下文；题目/聊天/草稿/提示/工具调用天然绑定；可独立复盘；可分别跑不同 Prompt/模型评测；Session 本身是**完整原始证据**（JSONL+树形分支+恢复）。历史是文件不是上下文：`history/index.md` 每题一行摘要+按需 grep/cat；不需要向量数据库。

### 3.4 三级记忆结构

| 层级 | 载体 | 内容 | 维护者 |
|---|---|---|---|
| 题内状态 | 当前 Pi Session | 完整题目/聊天/草稿/观察/提示/结果 | 教学 Agent |
| 日内连续性 | `continuity.md`（150-300 字） | 今日题数/连续完成数/时长/休息/上一题摘要（题型、结果、提示等级、未闭合问题）/当前建议 | Session 关闭时固定压缩（程序统计+一次低成本模型压缩），可覆盖 |
| 长期画像 | `profile/versions/<日期>/`（summary/mastery/misconceptions/strategies/update_report）| 长期掌握/错因/策略习惯 | **画像 Agent** 每日异步（Dream 式） |

- 下一题启动提示词 = 长期画像摘要 + continuity.md + 当前题目；"上一题犯错"不直接当长期薄弱结论。
- **快更新 + Dream 整理两频率**（同一画像 Agent）：每题结束快更新（知识点/独立完成/提示/暂时错因）；每 5 题或诊断结束 Dream 整理（合并重复、处理矛盾、区分偶然与稳定、删过时判断、生成更短 summary、保留原始 Session 证据）。
- 依据：Anthropic Dreams、OpenAI 沙箱记忆设计、arXiv 2605.12978（**持续反复重写长期记忆可能退化** → 原始会话为一等证据，记忆整合版本化+可回退）。
- 教学 Agent **不需要 update_mastery/update_profile 工具**——Session 已含全部信息，画像 Agent 直接提取。

### 3.5 四个最小跨题协议（补全赛题要求）

1. **Chapter Pack**：官方六类 CSV/文件（knowledge_points/question_types/error_causes/questions/diagnosis_rules/student_cases），覆盖规定数量与五专题；
2. **Assessment Run（诊断轮次）**：上层概念管理本轮目标/覆盖范围/题目 Session/停止条件/证据汇总（goal.md/continuity.md/sessions/coverage.md/evidence.md/final-report.md）；
3. **Question Handoff**：每题结束短摘要（K/T/E 候选、证据、提示等级、下一题建议）；
4. **Report Session**：教学 Agent 的 report 模式——读本轮各题摘要+长期画像，生成掌握度报告与 1-4 周计划（即时报告不能只靠异步画像）。

"当前真正缺的不是更多工具或更复杂的 Agent，而是**结构化学科内容、跨题诊断协议、掌握度解释规则、报告与学习计划输出规范**。"

### 3.6 企业多用户与高并发

- **Session ≠ Sandbox ≠ Workspace**："工作区持久化、计算环境按需租用"。
- **Session Capsule**：pi-session.jsonl + continuity.md + question.md + student-summary.md + workspace-diff.tar.zst + draft/ + metadata.json（tenant_id/student_id/question_session_id/status/last_event_id/workspace_version/profile_version）。
- **公共资料不复制**：内容包版本化+内容哈希去重（chapter-triangle-v3/skills-v7/scripts-v4）；每学生只存 Session JSONL、草稿 Stroke、少量快照、continuity、新增文件。
- **Sandbox 预热池**：租约流程（申请→挂载→执行→保存→清理→归还）；一 Sandbox 同时只服务一个 Session、一 Session 一个写入租约。
- **消息串行化**：同 Session 内串行（session_id→顺序队列）；不同学生并行；event_id 单调递增、幂等；Pi 原生支持 steering 消息排队。
- **双队列**：interactive-teaching 高优先 / daily-profile-update 低优先（忙时画像延后、夜间加 Worker）。
- **扩容指标**：等待教学消息数/活跃 Session 数/Sandbox 平均占用/模型调用并发/P95 首响应（**不要只看 CPU**）。
- **三级隔离**：tenant→student→session；路径含不可猜测 ID；Sandbox 只挂载一个题目 Session，不挂整个企业目录。

### 3.7 沙箱安全（早期方案保留为安全基线）

- 三方案：A（推荐）Pi 在可信后端、代码工具在断网容器；B Pi 也在容器只允许访问内部 Model Gateway；C Unix Socket 访问宿主机代理。比赛阶段推荐 A。
- 容器：Rootless Docker、--network none、--read-only、--cap-drop ALL、no-new-privileges、seccomp（禁 unconfined）、0.5 CPU/512MB/64 pids；超时：单次 Python 5-10s、单工具 ≤15s、单轮 8-12 次工具、单轮 30-60s、空闲自动回收；生产评估 gVisor/Kata/Firecracker。
- **三条安全原则**："Skills 负责教学纪律，Extension 负责工具权限，沙箱负责最终安全"；"文件可以作为 Agent 接口，但数据库和对象存储仍是系统事实来源"；学生信息只挂只读假名快照（不挂真名/手机号/令牌/他人信息）。
- 早期定稿定义（被 3.2 精简版替代，但 propose_* 提案+后端验证的机制保留）：状态修改一律 `propose_*`（evidence/diagnosis/state_patch/learning_plan），由后端做 Schema 验证→K/T/E 编号检查→证据引用检查→权重置信度计算→权限检查→正式写库。

## 四、草稿纸设计（核心亮点）

### 4.1 草稿纸三项职责

①学生表达载体；②Agent 观察环境（近期内容/局部区域/历史变化）；③诊断证据来源（方法选择、错误位置、修改过程、提示依赖）。

### 4.2 笔迹五层模型与时间轴

原始 strokes.jsonl 几万行坐标**不适合直接给模型读**（难以判断书写动作/公式归属/空白/语义相关范围）→ 多粒度时间轴索引，工具仍只有 read+bash：

- **Point → Stroke（一次落笔到抬笔）→ Burst（时间空间连续的若干 Stroke，如"sin B ="）→ Episode（语义上同一步骤的 Burst 组）→ Milestone（关键时刻全局快照）**。
- Burst 分组须**时间+空间联合**判断（不能只用固定 5 秒）；Episode 划分信号：长停顿/大空间跳转/撤销划除/Agent 新提示/提交/视口切换/新建区域。
- **双索引**：`timeline.json`（机器索引：active_ink_ms/idle_ms/bbox/new_ink_ratio/correction_score…）+ `timeline.md`（模型索引，几十行可搜索，每 Episode 一段）。模型先读 Markdown 再决定看哪里。
- **模型只操作片段 ID 不操作时间戳**：`python scripts/draft.py render --episode E04`、`--bursts B17,B18 --mode delta`。
- **跨度大/空白多四解法**：active_time 压缩展示（"片段1──停顿96秒──片段2"）；分面渲染（各面板编号/顺序箭头）；Delta 模式（旧浅灰/新黑/删除虚线）；Contact Sheet 总览图。
- **片段选择评分公式**：S = w_rR+w_fF+w_nN+w_cC+w_aA−w_iI−w_bB−w_sL（新近/区域重叠/新增比例/修正信号/事件邻近 − 无操作比例 − 空白比例 − 成本）；脚本输出建议片段+原因，Agent 可接受或自选。
- **intent 观察策略 7 种**：stuck/correction/method-change/after-hint/final-review/visual-confirm/history-compare（仍只是一个脚本）。
- 总纲："**原始轨迹用于存储，分层时间轴用于导航，预览图用于选择，局部渲染用于理解**"。

### 4.3 草稿可寻址引用协议（交互创新核心）

- 两个 URI Scheme：`draft://`（引用草稿）、`asset://`（引用生成图片），复用 Markdown 链接语法。
- 引用层级优先级：**Episode→Burst→Region→Stroke→时间范围**；引用必须固定草稿版本（version=47）；引用笔迹已划掉时切历史版本/幽灵笔迹显示。
- **intent 语义色**（模型输出 intent 而非十六进制）：attention 黄橙/正确绿/错误红/关系蓝/对比紫；不能只靠颜色（绿+对勾、红虚线+叉号…）。
- 画布五层：背景/学生墨迹/历史幽灵/**引用高亮层**（不写回 strokes.jsonl）/交互状态层；点击引用自动平移缩放高亮。
- 聊天 Markdown：KaTeX 公式；**禁止原始 HTML/MDX 直接执行**；draft:// asset:// 自定义处理。
- 引用生命周期：临时（悬停）→ 固定（点击）→ **证据引用**（进诊断报告长期保存）；对教师复核同样有效（点结论跳回原始草稿证据）。
- 比赛版优先级：P0=Episode/Burst 引用、draft:// 链接、三色语义高亮、点击定位、独立高亮层、KaTeX、asset:// 图片、SVG/PNG 生成、对应位置显示。

### 4.4 图文并茂（单一脚本方案）

- **一个统一 `visualize.py` + visual-explanation Skill**，不增加画图工具群；图片作为聊天消息一部分（脚本输出 `ASSET:`+`ALT:` 约定，宿主校验后转附件）。
- 四类教学图：①学生草稿引用图（裁剪/前后对比/Delta，派生讲解图不修改原稿）；②规范数学示意图（**必须确定性代码绘制，不用文生图**）；③函数与数据图（SymPy+Matplotlib）；④分步过程图（3-4 张连续小图）。
- 原则：图文紧邻呈现、删无关装饰、每图一个概念、**图像不能替代追问、不得借图泄露完整答案**；简单计算/定义回忆不配图。
- 优先级：草稿裁剪与差异图 → 静态 SVG 示意图 → 函数图 → 可交互图（商业版 JSXGraph，比赛版静态 SVG 更稳）。

### 4.5 感知与识别技术选型

- **PaddleOCR-VL 定位**（多次澄清）：文档解析与元素识别（文字/公式/表格/版面），**不是通用 VQA**（prompt_label 是任务类型不是自然语言指令）；**不能当"草稿语义分割器"**（不擅长区分原题图形/辅助线/圈画/草稿计算区/放弃推导/最终答案区）。
- 推荐**双层版面分析**：第一层通用文档结构（PP-DocLayoutV3+PaddleOCR-VL）；第二层自建轻量草稿检测器（十类左右：公式/图形/辅助线/标签/圈选/下划线/删除线/箭头/最终答案/草稿区），组合矢量规则+OpenCV+必要时小模型微调。
- 公式识别选型：PaddleOCR（版面/坐标级）→ UniMERNet/Pix2Text（困难公式）→ 多模态主模型（解释含义）→ SymPy（等价验证）；**OCR 结果不直接生成错因结论**。
- **最终感知方案（定案）**：不要求前置系统完整理解草稿，**保存完整可查询的视觉与轨迹历史，由多模态主 Agent 按当前诊断任务主动选择观察范围/时间/表示形式**：
  - 三种表示：原始事件流（回放/分析修改）/多尺度光栅快照（缩略图/近期高清/差异图/透明图层）/轻量轨迹摘要（程序生成，只帮模型决定是否继续看）。
  - 默认随轮次附带 6 项：当前题目、聊天目标、近 15-30 秒变化高清区、整体缩略图、差异图、画像相关字段。
  - 主动观察工具 9 个：inspect_region(scale/layers)/inspect_recent(seconds)/compare_canvas(t1,t2)/replay_region(短视频/关键帧)/inspect_full_canvas/inspect_raw_strokes/recognize_region(mode)/文档扫描矫正/请求学生确认。
  - 拍照输入同一链路：扫描组件（裁边/透视/去阴影）→ 原图+校正图 → 主模型观察 → 必要时 OCR/公式工具；多次拍照配准得 ΔI。
- **停笔触发与干预分离**："即时识别与即时干预是两种不同能力"——停笔触发（防抖约 700-1500ms 或 2-4s、换行、写等号、完成封闭图形、点"检查此步"、提交）只做后台识别；**是否反馈由 Tutor Policy 决定**（置信度/是否仍书写/错误是否致命/是否连续同类/会不会泄露答案）。
- 技术验证集建议：7 项、30-50 张真实草稿（PaddleOCR-VL 区域划分/公式识别率/圈选双下划线删除线规则识别/辅助线 VLM 理解/局部裁剪增益/拍照畸变/辅助线意图区分）。

## 五、Agent 与诊断设计

### 5.1 诊断状态循环（早期）→ 教学 Agent 决策集（定案）

早期：观察输入 → 判题/草稿观察 → 候选假设 → 证据充分性 → 选下一动作 → 更新状态；动作 8 个（ASK_PROBE/ASK_REASON/CONFIRM_VISUAL/INSPECT_REGION/REPLAY_CHANGE/GIVE_HINT/RETEST/FINALIZE）。

定案后教学 Agent 保持高自主性，决策集：**继续等待/中性确认/询问理由/查看更多草稿/分级提示/错因消歧/微型复测/完成本题**；不使用复杂固定流程强制每一步。

### 5.2 确认式追问与错因消歧

- 视觉推断**不得直接写入正式诊断**；推荐："我看到你从 A 点向 BC 补了一条线，并在旁边写了面积公式。你准备把这条线作为高来使用吗？"（而非"你画了高，说明你准备使用面积法"）。
- SSA 题答错保留 6 候选：不会正弦定理/边角对应错误/反三角计算错误/忽略补角/忘记检查存在条件/偶然计算错误；选择**信息增益最大**的追问而非推荐整章重学。
- 消歧流程示例：草稿有正确公式→降"公式不会"概率→追问"0°-180°同一正弦值是否可能对应两个角"→知补角再问内角和→微型判断题复测→结论"公式掌握、SSA 多解判断薄弱"。
- 追问四连问（文件2）：用正弦还是余弦→边角对应→sinB 后 B 是否唯一→B 是钝角是否成立→不同回答对应定理记忆/对应关系/分类讨论/计算稳定性问题。
- 错因输出要求：K-ID+T-ID+E-ID+判断依据；一次错误对应多候选；依据引用具体题/聊天/草稿片段；区分视觉误读与学生错误；防止生成不存在 ID。

### 5.3 证据体系（可解释性核心）

- **证据分层 E0-E4**：E0 原始（Stroke/照片/回答，不允许更新状态）→ E1 识别结果（不允许）→ E2 学生确认含义（允许）→ E3 数学验证/独立复测（允许）→ E4 教师确认（允许，权重最高）。
- 证据关系：supports / contradicts / ambiguous / recognition_uncertain / teacher_verified。
- **证据权重表**：独立中档题 1.0；独立基础题 0.7；轻提示后完成 0.4；猜测概率高选择题 0.2-0.3；学生确认草稿意图 0.5-0.8；教师确认 1.2；低置信视觉 0.1 或仅待确认；无原始依据不更新。
- **掌握度更新**：专家先验+加权 Beta（M_k~Beta(α,β)；α'=α+w_e / β'=β+w_e）。
- **正式结论门槛**：最高候选置信度 ≥0.8 **且** ≥两条相对独立证据（且视觉不确定已排除）→"较可能薄弱"；否则"待观察"。（均为可调产品参数，非赛题硬性要求）
- 数据链：原始 → 派生（快照/裁剪/OCR/描述）→ 证据 → 候选假设 → 正式结论 → 状态/计划；派生不覆盖原始，模型升级可重跑派生。
- 过程数据边界：停顿/重写/划掉**只作辅助信号**（停顿≠不会，可能是思考/分心/设备问题），只能触发中性询问或提高复测优先级。

### 5.4 终止条件（6 条）

知识范围已覆盖；最高候选达预设置信度；≥两条独立证据；下一题预期信息增益低；达题量/时间预算；学生主动结束。单次低置信观察只能"待观察"。

### 5.5 确定性边界与输出门控

- **代码/受控服务完成**：题量时间上限、允许动作、题目规则查询、DB 写入、权限、数学验证（SymPy/数值代入）、掌握度正式更新、报告字段、教师修改版本管理；**大模型无任意数据库写权限**。
- 输出门控检查：是否给最终答案/补全未完成主步骤/未验证数学结论/低置信写成事实/不存在 ID/超提示等级。

### 5.6 早期模型分工表（参考保留）

快速文本（意图/摘要）/强推理（错因分析/动作选择）/强多模态（草稿语义）/PaddleOCR-VL（精确转录）/SymPy+规则（验证）/OpenCV（图像处理）/确定性状态服务（掌握度）/PostgreSQL（检索）。假设驱动动作评分：Score(a)=w₁IG+w₂Coverage+w₃TargetValue−w₄TimeCost−w₅Interruption−w₆LeakageRisk（比赛版不需 RL，教研给探针配离散区分能力）。

## 八、掌握度与训练决策模型（解三角形熟练度模型文档）

队友的数学建模文档（基于题型库 10 类题型 + 错因库 6 大类 39 条错因）：

### 8.1 单次作答得分函数

s_n = φ(A_n, F_n, E_n) = A_n[α₀ + (1−α₀)F_n] + (1−A_n)ψ(E_n)

- A=答案正确性；F=过程熟悉度（关键步骤覆盖率）；E=错因；α₀=0.5（答对但过程不熟基准）；ψ(E) 按错因赋值表查表。
- 规则检验：A=1,F=1 → s=1 已掌握；A=1,F=0 → s=0.5 未掌握；A=0 → s=ψ(E)（运算类表层错误得分高）。

### 8.2 熟练度更新（指数滑动平均）

p₁=s₁；pₙ=(1−β)pₙ₋₁+βsₙ（n≥2）；**若 sₙ=1 则 pₙ=1 且终止该题型训练**；β=0.6 建议值；提供防波动变体 pₙ=max{pₙ₋₁, (1−β)pₙ₋₁+βsₙ} 与难度校正 s'ₙ=sₙ·d_q/d̄。

### 8.3 训练决策函数

五类判定：已掌握（p=1 终止）/达标（p≥θ_high 终止）/基本达标（n=N_max 且 p≥θ_high）/未达标转人工辅导（n=N_max 且 p<θ_high）/继续训练（薄弱：p<θ_low 高优先；巩固轮：θ_low≤p<θ_high）。θ_low=0.5、θ_high=0.8、N_max=5。初测每题型 1 题共 10 题，此后仅对未达标题型循环抽同题型新题。

### 8.4 错因库赋值（双维判定：认知阶段+概念卷入深度）

| 大类 | 条数 | 基准分 | 认知阶段 | 依据 |
|---|---|---|---|---|
| 运算错误 E-CAL | 4 | 0.80 | 过程技能层 | 表层粗心、实证占比最高（30.61%） |
| 公式记忆与运用 E-FOM | 8 | 0.50 | 转换层 | 会背不会用 |
| 审题与建模 E-MOD | 5 | 0.45 | 阅读/理解/转换层 | 影响整题方向 |
| 解题策略 E-STR | 7 | 0.40 | 策略/元认知层 | 方法选择与综合运用 |
| 逻辑推理 E-LOG | 9 | 0.35 | 推理层 | 推理断层、实证占比最低（14.98%） |
| 概念理解 E-CON | 6 | 0.20 | 理解层 | 误解最顽固、补救成本最高 |

理论依据：纽曼错误分析五阶段（阅读→理解→转换→过程技能→编码）；862 名学生错误归因实证；概念性 vs 程序性错误区分。39 条错因全部有唯一编码与得分（如 E-CAL-001 代数计算错误 0.80；E-CON-003 SSA 与全等判定混淆 0.15；E-LOG-001 SSA 解个数判断错误 0.35…）。

### 8.5 参数标定与算例

德尔菲法标定错因权重；网格搜索最大化与教师评级一致性（Cohen κ）；灵敏度检验。五个算例：初测即掌握（1 轮终止）；仅运算错误即达标（0.8=θ_high）；概念错误后 4 轮逐步掌握（0.15→0.36→0.534→1.0）；五轮渐升基本达标（0.808）；十题型整体模拟（P≈0.807、掌握率 20%、达标率 60%，T5/T6/T8/T9 转人工辅导）。扩展方向：艾宾浩斯遗忘曲线、IRT 三参数、强化学习选题、错因热力图班级报告。局限：F 自动采集依赖过程识别；w_k 需数据修正；未建模遗忘；未显式处理题内难度。

## 十、创新点体系

### 10.1 三个核心创新（对外宣传项）

1. **草稿本原生的过程感知交互**：保存连续笔迹事件 Stroke→Symbol→Expression→Solution Step→Solution Graph，每步可映射回原始笔画——可知错误发生在哪步、来自哪几笔、是识别错误还是数学错误、是否主动修改；实验=基线 A 只看答案 / B 答案+静态截图 / 实验组完整步骤轨迹，指标=错因分类准确率/教师一致率/无法归因比例。
2. **静默感知、选择性干预**：识别与反馈彻底分离（"停笔一秒就弹出反馈"会打断思考/泄露答案/形成提示依赖）；动作集{等待,确认,追问,轻提示,强提示,讲解,换题}；决策目标 G_learn+λG_info−αC_interrupt−βC_leak−γC_error；指标=下一题独立正确率/打断次数/提示依赖/过早给答案比例。
3. **可追溯的证据链诊断**：每结论=原始笔迹→识别→数学验证→错误步骤→错因候选→追问结果→诊断规则→状态更新；诊断对象 JSON{claim, evidence[], alternative_causes, confidence, status:"待复测确认"}；指标=教师诊断一致率/复核时间/修改率/可解释性评分。

### 10.2 三个支撑创新

1. **双目标自适应选题**：诊断模式 q*=argmax I(Z;R_q|H_t)（信息增益，区分多假设）；教学模式 q*=argmax[P(可完成)·G(掌握提升)]（ALEKS 知识空间内/外边界）；
2. **过程感知学生模型**：S_t=(K_t,T_t,M_t,B_t,I_t)（知识/题型策略/错因分布/行为过程特征/提示偏好）；"不只追踪会不会，还追踪怎么做、怎么错、如何修正、需要何种帮助"；
3. **可迁移 Chapter Package**：统一内容包+load_chapter("triangle_solving") 接口；扩展成本从"重新开发系统"变为"教研生产章节包"。

**不作为创新宣传**：RAG/向量库/OCR/多模态/多 Agent/本地部署/自动生成试卷教案/雷达图/错题本/文档导出/Dify 或 LangGraph 工作流/"ABCD 四类学生"/每学生专属 Skill/"AI 自动生成全部题目"/"停笔后立即反馈"。

**项目数学模型**：部分可观测控制系统 x_t（隐状态）/o_t（观测）/a_t（动作）/x_{t+1}=F(x_t,o_t,a_t)；价值 V=O_p×D_r×I_e×C_s（过程可观测性×诊断可靠性×干预有效性×内容扩展能力）。

## 十三、设计理念总结

1. **从"结果判断"转向"过程诊断"**：结构化答案+聊天+草稿+历史共同作为证据；
2. **草稿主交互、聊天主引导**："让学生继续正常做数学，让 Agent 学习观察学生"，而不是让学生学会向 Agent 描述数学；
3. **Agent 主动取证而非一次性判断**："核心不是让模型猜得更准，而是让模型能够主动减少自己的不确定性"；
4. **保持 Agent 结构简单**：少而准确的工具、最小高信号上下文、渐进式信息披露、状态外置、原始证据保留；
5. **实时教学与长期画像分离**：教学 Agent 管"现在怎么教这一题"，画像 Agent 管"长期怎么看这个学生"；
6. **不让模型直接读完整草稿 JSON**：中间导航层"原始笔迹→时间轴→候选片段→局部图片→模型理解"；模型决定看哪段，程序负责转换成适合模型看的内容。

**解决的 8-9 个核心问题**：只知道错不知道为何错；相同错误答案无法区分认知原因；传统测评需大量刷题；数学思维难以纯聊天表达；一次性大模型判断不稳定；长期上下文膨胀；画像频繁更新不稳定；诊断结论不可解释；独立 Session 缺乏连续性。

**最终能力表述**："能够观察学生真实数学解题过程，在少量题目中主动寻找最有价值的诊断证据，区分不同错误原因，并根据长期学习状态持续调整教学策略的个性化数学教学 Agent。"
