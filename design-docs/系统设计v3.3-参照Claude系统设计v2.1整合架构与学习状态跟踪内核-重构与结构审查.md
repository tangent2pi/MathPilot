## 0. 先给结论

本项目不应被建模为“一个会出题的聊天机器人”，也不应被建模为“五个彼此平铺的功能模块”。更准确的产品抽象是：

> 一个以前后端分离为产品形态、以 Pi Agent Harness 为可替换模型运行时、以证据事件为状态来源、以可发布章节包为内容载体，并可按需组合草稿、OCR、视觉、搜索和交互讲解模块的诊断型教学系统。

它包含四条互相解耦、通过契约连接的闭环：

1. **内容闭环**：教师资料 → 候选知识资产 → 人工复核 → 不可变章节包；
2. **单题闭环**：选题 → 一题一 Session → 草稿/回答/交互 Artifact/追问取证 → 程序评价+教学总结；
3. **学生状态闭环**：多组“程序评价+教学总结” → Dream 画像大模型按需回看 Session 证据 → 最终画像更新 → 校验并发布快照；
4. **教学质量闭环**：教师复核/黄金案例 → 纠正事件 → 状态重放 → Prompt、规则、参数和模型版本评测。

其中最重要的四条边界是：

- 教学模型负责判答、教学和单题观察，但不能直接改长期画像；
- 画像更新大模型拥有最终画像更新的语义决策权；传统程序只提供基准和校验。模型必须引用已有证据、解释相对基准的变化，不能凭空写任意分数；
- 艾宾浩斯时间层只描述“当前能否提取出来”，不直接把“已经学会”按时间乘没。
- 所有外部能力通过模块接口和 Provider Registry 接入；任何具体模型、OCR、搜索或插件都不是领域代码的硬依赖。

## 1. 从全部提示词恢复出的设计宪法

以下约束不是实现建议，而是后续设计不得破坏的产品宪法。

### 1.1 产品与交互

1. 试点范围是“解三角形”，但骨架必须能发布其他章节包；
2. 采用“**聊天主控制、草稿可增强**”：支持草稿时，草稿是主要数学表达空间；设备或场景不支持草稿时，完整流程退化为文字、公式、图片上传和聊天，不得因此无法诊断；
3. Agent 不修改学生草稿，不把标准答案写回草稿；
4. 同时支持实时数字笔迹和纸面拍照；
5. 一题一 Session，一题一隔离工作区；两题之间不共享原始模型上下文；
6. 题间只传递结构化连续性包和长期画像摘要；
7. 学生端首期入口为每日练习、错题重刷、问问 AI，之后可扩展；
8. 教师端不仅管理内容，还要复核学生诊断证据；
9. Teaching Agent 可在固定 Artifact 区生成文件并在回复中引用，学习页原生渲染卡片、图片和视频；
10. 卡片默认允许学生不作答而直接文字回复，跳过不能被记作答错。

### 1.2 Agent、模型与插件

1. 主教学模型、辅助模型都必须通过 `ModelProvider` 替换，可接云 API、本地 vLLM/SGLang/Ollama/llama.cpp 或兼容网关；
2. 默认主模型配置可使用 `qwen3.8-max-preview`，默认辅助模型可使用 `deepseek-v4-flash`，但二者只是配置实例而不是架构名称；
3. 主模型直接承担教学时原则上要求多模态；如果安装了独立 `MediaUnderstandingProvider`（如 Qwen-MM-Plugins API），允许使用文本主模型，但系统启动校验必须证明组合后的 `effective_multimodal=true`；
4. 辅助模型只要求可靠的文本推理、结构化输出和足够上下文，不要求多模态；
5. PaddleOCR 通过 `OCRProvider` 接入，支持本地、官方 API、自建 API、官方 MCP/CLI；复用队友 TEACHER 管线的分页 Markdown、题目切割和图片关联代码；
6. 搜索通过独立 `SearchProvider` 接口接入 Serper、Exa、Tavily、自建搜索或其他供应商；辅助模型负责查询规划、来源判断和综合；
7. Qwen-MM-Plugins 的 `core`、`api`、`search`、`edu-agent` 都是实验性可插拔模块，不预先一刀切；
8. 模型行为由版本化的 `agent.md` 策略源、运行时生成的标准 `AGENTS.md` 与按需加载的 Skills 共同约束；Agent 表面只暴露 `bash` 和 `search` 两类工具。

### 1.3 数据与状态

1. 教师上传资料先进入暂存区，教师确认后才能发布；
2. 每个正式数据字段必须能追溯到来源片段、人工判断或 AI 生成声明；
3. 学生原始作答、笔迹、聊天和模型输出是不可变事件；
4. 教师纠正不能覆盖旧结论，必须生成“取代/撤销”事件并重放状态；
5. 每个教学 Session 结束时同时产出程序生成的 `ScientificEvaluationReport` 和教学模型生成的 `TeachingSessionSummary`；Dream 画像大模型以这组双产物为主要输入，必要时沿引用回看 Session 内容，生成最终 `ProfileUpdateDecision`；
6. 时间层采用艾宾浩斯式保持率，但必须和掌握状态分离；
7. 文档必须足够精确，使 AI 开发 Agent 可以按契约并行实现，而不是靠临场猜测。

## 2. 系统边界与领域对象

### 2.1 四个边界上下文

```text
┌──────────────── Content Studio ────────────────┐
│ Upload / OCR / Extract / Stage / Review / Publish │
└──────────────────────┬─────────────────────────┘
                       │ immutable ChapterPackage
                       ▼
┌──────────────── Learning Runtime ──────────────┐
│ Select / Session / Chat / Draft / Judge / Probe │
└──────────────────────┬─────────────────────────┘
                       │ immutable EvidenceEvent
                       ▼
┌──────────────── Learner State ─────────────────┐
│ Reduce / Diagnose / Mastery / Retention / Plan │
└──────────────────────┬─────────────────────────┘
                       │ snapshot + review tasks
                       ▼
┌──────────────── Governance ────────────────────┐
│ Teacher review / replay / eval / audit / release │
└────────────────────────────────────────────────┘
```

边界之间只交换版本化对象，不直接共享内部表结构。这样可以把教学模型、内容生产 Agent、画像 Agent、前端和算法内核独立替换。

### 2.2 核心领域对象

#### 内容侧

- `SourceDocument`：教师上传的 PDF、讲义、习题、易错总结或网页；
- `SourceFragment`：页码、段落、题目框、图片区域等可引用最小片段；
- `CandidateClaim`：AI 从片段提取的候选字段及置信度；
- `ReviewTask`：教师需要确认、修改、拒绝或合并的内容项；
- `ChapterPackage`：一次发布的不可变章节包；
- `KnowledgeComponent`（K）、`QuestionType`（T）、`ErrorCause`（E）、`Question`（Q）、`DiagnosisRule`（R）；
- `MeasurementTarget`：一道题真正测量哪个 K/T、测量角色和评分证据，不等同于普通标签。

#### 学习侧

- `AssessmentRun`：有目标、预算、覆盖要求和终止条件的一轮诊断；
- `QuestionSession`：一题一会话；
- `Attempt`：一次独立提交；
- `DraftSheet`、`StrokeEvent`、`DraftSegment`、`DraftReference`；
- `AnswerVerdict`：答案与评分点判定；
- `TeachingMessage`：由文字、图片、视频和卡片引用组成的多段回复；
- `LearningArtifact`、`ArtifactVersion`、`ArtifactResponse`：受控文件产物、不可变版本和学生交互；
- `DiagnosticClaim`：带候选错因、替代解释与证据的候选诊断；
- `StateObservation`：算法内核可接受的成功/失败/未决观测；
- `InterventionEvent`：提示、讲解、变式或反馈；
- `TeachingSessionSummary`、`SessionLearningRecord`：教学模型简要总结，以及它与程序评价组成的双产物；
- `StudentSnapshot`：由通过校验的 `ProfileUpdateDecision` 幂等物化得到的当前画像状态；
- `LearningPlan`、`ReviewSchedule`；
- `TeacherCorrection`：取代旧观测或诊断的纠正事件。

### 2.3 标签与测量必须分开

题目可以关联多个知识点，但不能把一次总分无差别写入所有知识点。

每道题必须另有 `measurement_targets`：

```yaml
question_id: Q_TRI_012
tags: [K_SINE_RULE, K_SSA, K_TRIANGLE_EXISTENCE]
measurement_targets:
  - dim: K_SSA
    role: primary
    evidence_rule: rubric.ssa_branch_check
  - dim: K_SINE_RULE
    role: secondary
    evidence_rule: rubric.setup_sine_rule
  - dim: K_TRIANGLE_EXISTENCE
    role: prerequisite
    evidence_rule: probe.existence_check
```

只有对应评分点或定向追问产生了明确证据，相关维度才更新。普通 `tags` 只用于检索和展示。

### 2.4 契约先行的模块结构

系统不是把一个“大 Agent”不断加功能，也不是先做一个垂直切片再临时补齐，而是先定义稳定契约，然后把所有模块的最小实现组装成完整系统。建议代码结构如下：

```text
apps/
  web-test/                  # 首期流程验证前端
  web/                       # 后期独立美化的正式前端
services/
  api/                       # 对前端提供 OpenAPI + SSE/WebSocket
  agent-runtime/             # Pi SDK/RPC 适配、Session 编排
  content/                   # OCR、抽取、调研、复核、发布
  learning/                  # 题目 Session、判答、教学
  profile/                   # 跨 Session 画像与量化融合
  review/                    # 教师复核与状态重放
packages/
  contracts/                 # 事件、Schema、Provider 接口
  providers/model/           # 本地/API 模型实现
  providers/ocr/             # PaddleOCR 本地/API/MCP 实现
  providers/search/          # Serper/Exa/Tavily/自建搜索实现
  providers/media/           # Qwen-MM core/API 等视觉实现
  providers/explanation/     # HTML/视频/普通讲解渲染实现
  sandbox/                   # 挂载、网络、资源和写区域策略
  mastery/                   # 程序科学评价、画像 Decision 校验与重放
  provenance/                # 字段血缘、版本、审计
  ui-sdk/                    # 前后端共享的生成类型客户端
```

前端不持有模型密钥、不直连数据库，也不依赖某个模型供应商。后端通过 OpenAPI 返回稳定资源，通过 SSE/WebSocket 推送 Session 事件。首期 `web-test` 只验证登录、选题、作答、可选草稿、追问、报告和教师复核流程；后期前端专长模型只改 `apps/web` 与设计令牌，不改变领域契约。

核心只依赖 `ModelProvider`、`OCRProvider`、`SearchProvider`、`MediaUnderstandingProvider`、`ExplanationRenderer`、`SandboxProvider` 和 `AuthProvider`。每个实现都必须通过同一组契约测试，才能在配置中替换。

## 3. 用户旅程与产品页面

### 3.1 学生首次进入

1. 注册并完成最小画像：年级、当前分、目标分、每周可投入时间、自认薄弱、设备与草稿方式；
2. 系统说明数据用途、草稿保存和教师可见范围；
3. 画像只影响首轮选题覆盖和计划优先级，不直接写“已掌握/薄弱”；
4. 创建首次 `AssessmentRun`，用少量覆盖题建立证据基线。

### 3.2 学生首页

- **每日练习**：按当前计划、薄弱项、目标分权重和预计成功率选题；
- **错题重刷**：按复测到期程度排序，不是简单按做错时间排序；
- **问问 AI**：学生自带题目或自由提问。库外题可以教学，但默认不更新正式画像；只有教师或内容管线完成 K/T/E 标注后才可转为状态证据；
- **报告与计划**：查看结论、证据、未决项、下一次复测和趋势。

### 3.3 单题学习页

桌面端以聊天和学习内容流为主，草稿启用时显示可调整的草稿区；手机端在聊天、Artifact 和全屏草稿间切换。固定显示：

- 题目卡；
- 当前模式：诊断 / 求助 / 复盘；
- 当前是否正在观察草稿；
- `我卡住了`、`检查这一步`、`我不确定方法`、`完成本题`；
- 被聊天引用的草稿区域高亮；
- Teaching Agent 回复中的文字、图片、视频和交互卡片；
- 卡片上的“提交答案”和“不作答，直接回复”两条路径；
- 被回复引用的 Artifact 文件预览、来源和生成状态；
- 提示等级和本题是否计入独立掌握证据。

卡片不是阻塞式弹窗。学生可以填写卡片，也可以忽略/明确跳过并继续在聊天框回复；跳过只生成 `ArtifactSkipped` 或 `ArtifactBypassed` 事件，不生成失败观测。

### 3.4 教师端

教师端分为两个不同队列：

1. **内容复核队列**：知识点、题型、题目、错因、规则和来源字段；
2. **学生诊断复核队列**：原题、草稿时间轴、聊天、判答、K/T/E 结论、替代解释、算法状态变化。

此外提供班级页、学生趋势页、章节包版本页、导入导出页和黄金案例回归结果。

## 4. 运行架构、Pi 与模型分工

### 4.1 五种隔离角色，而不是共享历史的通用 Worker

同一模型实现可以服务多个角色，但每次运行都必须是独立 Session、独立任务提示、独立输入投影和独立输出 Schema：

| 逻辑角色 | 主要任务 | 可见输入 | 可写范围 |
|---|---|---|---|
| Teaching Agent | 多模态判答、追问、讲解、单题观察 | 当前题、当前 Session、只读画像投影 | 当前 Session 输出 |
| KTQ Extraction Agent | 从来源抽取 K/T/Q | 来源片段与 KTQ Schema | KTQ staging |
| ER Research Agent | 调研和归纳 E/R | 搜索结果、来源片段、冻结 KTQ 只读投影 | ER staging |
| Dream/Profile Update Agent（大语言模型） | 综合多组程序评价与教学总结，必要时回看 Session 证据，作最终画像更新 | 旧画像、Session 双产物、证据投影 | `ProfileUpdateDecision` |
| Deterministic Services | 在教学阶段生成 BKT/保持率/统计评价，执行数据质量、边界与算术校验、约束选题、重放 | 已验证结构化事件 | `ScientificEvaluationReport` 与校验结果，不作最终画像决策 |

其中 Teaching Agent 与 Profile Update Agent 必须使用不同 Session；前者没有长期画像写权限，后者没有教学对话权限。KTQ 与 ER 也绝不能通过“换一句 system prompt 后继续原对话”来模拟隔离。

### 4.2 Provider 能力矩阵

领域代码只依赖稳定接口：

```text
ModelProvider.generate(messages, tools, response_schema, capability_request)
OCRProvider.parse(document, mode, output_schema)
SearchProvider.search(query, policy, citation_schema)
MediaUnderstandingProvider.inspect(media_refs, task, response_schema)
ExplanationRenderer.render(explanation_spec, target)
ArtifactPublisher.publish(manifest, files, response_policy)
```

生产配置记录精确模型 ID、区域、接口协议、上下文限制、视觉/音频/工具能力、数据驻留和成本。`qwen3.8-max-preview` 与 `deepseek-v4-flash` 只是当前可测试实例，不进入领域类型名。

- 教学主模型可以直接多模态；也可以是文本模型加独立 `MediaUnderstandingProvider`。启动健康检查必须用真实图文样本证明组合能力满足 `effective_multimodal=true`；
- 辅助角色不强制多模态，按任务选择本地或 API 模型；
- PaddleOCR 通过 `OCRProvider` 提供本地、AI Studio/千帆、官方 MCP、自建服务等实现；
- 搜索只通过 `SearchProvider`，可以接 Serper、Exa、Tavily 或自建提供商；
- 所有回退都显式记录实际实现、模型和版本，不能静默改变结论来源。

### 4.3 Pi Agent Harness 的位置

Pi 提供多供应商模型 API、图像输入、Skills、Extensions、Packages，以及 SDK/RPC 嵌入方式，适合作为 `agent-runtime` 的首个实现；它不是领域数据库、画像算法或安全边界。系统应通过 Pi SDK 或 RPC 创建任务 Session，并由自己的 Orchestrator 注入工作区、`AGENTS.md`、Skills、工具和响应 Schema。

Qwen-MM-Plugins、PaddleOCR 与搜索适配器可以封装为 Pi Skill/Extension/Package，也可以由宿主侧 Broker 暴露为内部命令。无论实现形式如何，领域层看到的仍是上述 Provider 契约，避免业务代码绑死 Pi 或单个插件。

### 4.4 Agent 可见工具面

Agent 只看到两类工具：

- `bash`：允许在隔离命名空间内运行一般命令，不限制为预先列出的脚本；安全边界来自只读挂载、固定可写目录、禁外网、资源限额和超时，而不是脆弱的命令 allowlist；
- `search`：由宿主侧 Search Broker 执行并返回带引用的结构化结果，诊断场景默认关闭，内容调研场景按策略开放。

需要 OCR、视觉、图像裁剪或交互讲解时，`bash` 可调用工作区内的 `agmath ocr|media|vision|explain` CLI。CLI 只通过受控 IPC 连接宿主 Broker；沙箱本身不获得互联网、云密钥或供应商凭据。

### 4.5 单题 Session 生命周期

```text
CREATE
  → PREPARE_WORKSPACE
  → PRESENT
  → OBSERVE / WAIT
  → SUBMIT
  → GRADE
  → SCIENTIFIC_EVALUATE
  → DIAGNOSE
  → PROBE? (最多三轮，由信息价值和学生负担共同决定)
  → TEACH? (仅求助/复盘)
  → RETEST? (需要闭合候选时)
  → CLOSE
  → FINAL_SCIENTIFIC_EVALUATE
  → TEACHING_SESSION_SUMMARY
  → QUEUE_DREAM
  → BUILD_HANDOFF
```

状态机由程序控制，模型在每个状态只获得当前允许的动作。`SCIENTIFIC_EVALUATE` 的中间结果可以作为 Teaching Agent 后续追问与总结的参考；关闭时固定生成最终 `ScientificEvaluationReport` 和 `TeachingSessionSummary`。二者可以服务题间短期连续性，但都不能直接修改长期画像，统一进入 Dream 队列。

### 4.6 教学模式纪律

| 模式 | 是否可提示 | 是否形成独立掌握证据 | 目标 |
|---|---|---|---|
| 诊断 | 仅 L0 澄清 | 是 | 最大化区分与覆盖 |
| 求助 | L1-L4，按最小必要提示 | 提示后不算独立证据 | 完成当前学习 |
| 复盘 | L5 完整讲解、图文/视频、变式 | 讲解本身不算证据；随后独立复测可算 | 理解与迁移 |

保留 L0-L5，但不机械规定“必须连续两次无效才能升级”。升级应由学生明确请求、当前失败类型和认知负担决定；每次提示都记录，下一次独立复测验证是否摆脱提示依赖。

## 5. 一题一沙箱与上下文编译

### 5.1 工作区

```text
/workspace/
├── AGENTS.md                   # 工作区地图、教学纪律、输出契约
├── task/                       # 当前题、状态与预算，只读挂载
├── student/                    # 当前学生最小画像投影，只读挂载
├── chapter/current/            # 已发布章节包共享挂载，只读
├── libraries/
│   ├── knowledge/              # 知识库只读投影
│   ├── errors/                 # 错因库只读投影
│   ├── rules/                  # 诊断规则只读投影
│   └── examples/               # 获准示例只读投影
├── skills/                     # 共享 Skill 包只读挂载，不重复复制
├── draft/                      # 可选模块挂载；禁用时目录不存在
├── tmp/                        # Session 独占、可写、结束即清理
└── output/                     # Session 独占、可写、Schema 校验后接收
    ├── artifacts/              # 允许在回复中引用的固定 Artifact 区
    │   └── <artifact_id>/
    │       ├── manifest.json   # 必需；类型、文件、引用、响应策略
    │       ├── card.json       # 卡片类型时使用
    │       ├── index.html      # edu-agent 交互可视化/HTML 卡片入口
    │       ├── content.md      # 可选文本/说明
    │       └── media/          # 可选图片或视频
    └── session-result.json     # Session 结构化出口
```

章节包、知识库、错因库、规则库、Skills 和可复用媒体都以内容寻址的不可变卷共享挂载，不为每题重复复制。仓库中的版本化 `agent.md` 是策略源，Orchestrator 按任务类型编译成工作区标准文件 `AGENTS.md`；后者必须明确目录用途、教学方法、证据规则、禁止行为和按需加载 Skill 的方法。每个教学 Skill 再描述具体题型策略与工具使用。

### 5.2 工具

主模型表面只看到 `bash` 和 `search`，不另设 `read` 工具；文件读取也通过 shell 完成。`bash` 允许调用系统中已安装的一般命令、项目 CLI 或自行组合管线，但必须同时满足：

- 只有 `/workspace/tmp` 与 `/workspace/output` 可写，其他挂载和根文件系统只读；
- rootless 容器或等价沙箱，无宿主 socket、设备、用户目录和其他 Session 挂载；
- 禁止一般外网出站和 DNS，供应商密钥只在宿主 Broker；
- 每条命令有 wall-clock 超时，并限制 CPU、内存、进程数、输出字节数和临时盘；
- 命令、退出码、耗时、资源使用和输出哈希写入审计事件；
- `search` 受模式、租户、额度、域名和返回大小策略控制。

因此模型既能灵活使用 shell，又不能通过换一个命令绕开数据和网络边界。

### 5.3 三层上下文

1. 系统层：模式、题目、诊断目标、学生摘要、当前提示级别、允许动作；
2. Skill 层：仅暴露名称与触发说明；
3. 文件层：详细画像投影、知识库、错因库、资料和可选草稿按需读取。

系统每轮重新编译最小上下文，不把完整历史对话复制进下一题。

### 5.4 可引用 Learning Artifact 协议

Teaching Agent 或 `edu-agent` 可以通过 `bash` 在 `/workspace/output/artifacts/<artifact_id>/` 写入规定文件，然后在回答中引用：

```text
artifact://<session_id>/<artifact_id>
```

原始文件路径、`file://` 和外部临时 URL 不能直接发给前端。Turn Commit 阶段由 `ArtifactPublisher` 完成：

1. 路径归一化并确认所有文件位于当前 Artifact 目录；
2. 校验 `manifest.json`、卡片 Schema、MIME、大小、哈希和引用完整性；
3. 对图片解码重写，对视频转封装/扫描，对 HTML 清洗并施加 sandbox/CSP；
4. 持久化文件和元数据，生成不可变 Artifact 版本；
5. 只有发布成功的 Artifact URI 才能随 `TeachingMessage` 返回。

该协议首先是 `edu-agent` 的正式输出边界，而不是普通附件目录。`manifest.json` 声明三类产物：

```json
{
  "schema": "agmath.learning-artifact/v1",
  "artifact_id": "art_...",
  "kind": "knowledge_visualization|question_card|mixed_lesson",
  "renderer": "native_card|sandboxed_html|media",
  "entry": "index.html|card.json|media/demo.mp4",
  "response_policy": {
    "required": false,
    "allow_skip": true,
    "allow_free_text_without_answer": true
  },
  "source_refs": ["question://...", "knowledge://K_SSA"]
}
```

- `knowledge_visualization`：`edu-agent` 写 `index.html`，用动画、图形和分步交互解释知识点；
- `question_card`：写标准 `card.json` 交由前端原生渲染，或写遵循同一交互协议的 `index.html`；
- `mixed_lesson`：同一 HTML 内包含知识可视化和若干卡片，但每个问题仍有独立 `card_id` 和响应事件。

卡片语义首版支持：

```json
{
  "schema": "agmath.question-card/v1",
  "artifact_id": "art_...",
  "card_id": "card_1",
  "type": "single_choice|multiple_choice|fill_blank|true_false",
  "prompt": "请选择所有满足条件的选项",
  "options": [{"id": "A", "content": "..."}],
  "response_policy": {
    "required": false,
    "allow_skip": true,
    "allow_free_text_without_answer": true
  },
  "evidence_policy": "teaching_only|eligible_if_independent",
  "source_refs": ["question://...", "chat://.../turn/8"]
}
```

`sandboxed_html` 不直接操作学习页 DOM，而通过受限 `postMessage` 桥发送版本化事件：

```text
artifact.ready
artifact.resize
card.presented
card.answer_submitted
card.skipped
card.free_text_requested
```

前端验证 origin、artifact/session ID、事件 Schema 和一次性 interaction token 后，转换成领域事件。HTML 不能自行宣告答对或写画像；它只提交学生交互，Teaching Agent 仍负责语义判答。这样 `edu-agent` 可以自由生成生动 HTML，同时小题卡、跳过和直接回复仍进入统一的数据与审计链。

- `single_choice` 只能提交一个 option；
- `multiple_choice` 提交 option 集合；
- `fill_blank` 支持一个或多个命名空格；
- `true_false` 使用明确的 true/false/unknown 值；
- 学生可以提交 `ArtifactResponse`，也可以选择跳过或直接发送普通聊天；
- `required=false` 是默认值，未作答绝不能自动判错、扣分或更新画像；
- 卡片默认 `teaching_only`。只有题目有 MeasurementTarget、处于允许模式、学生独立作答且经过模型判答时，才可成为正式观测。

Teaching Agent 的回复采用多段消息：

```json
{
  "message_id": "msg_...",
  "parts": [
    {"type": "text", "markdown": "先观察这个图，再选择你认为成立的条件。"},
    {"type": "image", "artifact_ref": "artifact://s_1/art_img_1", "alt": "三角形边角关系图"},
    {"type": "video", "artifact_ref": "artifact://s_1/art_vid_1", "caption_ref": "artifact://s_1/art_vid_1#captions"},
    {"type": "card", "artifact_ref": "artifact://s_1/art_card_1"}
  ]
}
```

一条回复可以是纯文字、纯图片/视频，也可以混合。图片可由绘图工具、Qwen core/API 或其他 Provider 生成；视频可由 `edu-agent`/`ExplanationRenderer` 生成。耗时视频采用 `pending → ready|failed` 事件更新，前端先显示占位，不阻塞聊天。所有图片必须有替代文本，视频必须有标题、字幕或文字摘要。

## 6. 可选草稿过程取证模块

草稿是重要的增强证据源，但不是系统运行前提。`DraftProvider` 暴露统一能力：

```text
enabled, ingest_strokes(), ingest_image(), segment(), render(), resolve_reference()
```

启用时，系统组合答案、聊天、题目图片与草稿时间轴进行诊断；禁用或设备不支持时，仍可使用文字、LaTeX、图片上传、语音转写和追问完成同一 `QuestionSession`/`Attempt` 契约。任何测量规则都必须声明 `draft_required=false`，或同时提供无草稿替代证据路径。

### 6.1 原始事件与派生对象

- 原始 `StrokeEvent`：点序列、时间、压力、工具、页面、设备；永不被 AI 改写；
- `DraftBurst`：基于停笔间隔和笔画连续性形成的短片段；
- `DraftSegment`：将相邻 Burst 按空间重叠、时间距离和内容密度合并；
- `DraftSnapshot`：某片段或区域的渲染图；
- `DraftReference`：聊天可以引用的稳定地址。

### 6.2 时间轴选择

程序先做导航，不让模型直接阅读巨大 JSON：

1. 初始停笔阈值写入配置（例如 1.2 秒），但必须用真实笔迹集标定；
2. 计算每个 Burst 的时间范围、包围盒、笔画密度、页面占比、与上一 Burst 的空间距离；
3. 对“时间近且空间相邻”片段合并，对长空白和跨页强制分割；
4. 生成小型 `segments.json`，每个条目含缩略图、时间、区域、增删改标记和父子关系；
5. 模型先读索引，再选择 segment、时间段或区域渲染；
6. 如果模型选的跨度过大，脚本返回密度警告和建议子片段，不直接渲染巨图。

### 6.3 可寻址引用

聊天输出使用：

```text
draft://<session_id>/seg-017?region=r2&color=amber
```

前端将其渲染为可点击引用并临时高亮对应区域。引用只是视觉指向，不修改学生笔迹。每条诊断证据也保存同一个地址，因此教师可以一键回放。

### 6.4 识别策略

- 多模态主模型读取渲染后的近期片段、局部图或整页缩略图；
- 先确认“看到了什么”，再推断“可能意味着什么”；
- 低置信识别通过 L0 中性追问确认；
- 矢量事件用于时间、位置、删改和辅助线行为，视觉模型用于数学语义；
- 不承诺将任意草稿完整符号化；低置信内容保留为视觉证据或通过追问确认。

## 7. 内容生产线与字段级溯源

### 7.1 OCR 与题图入库

`OCRProvider` 统一承接本地和 API 模式。首个实现复用队友 `references/teammate-models/TEACHER/` 已有的分页 Markdown、版面切割、图片提取和题目关联流程，再将 SQLite 持久层替换为 PostgreSQL repository；PaddleOCR 官方 MCP 的 `ocr`、`pp_structurev3`、`paddleocr_vl` 作为可配置适配器，不把部署模式写死。

题目文本与题图必须在同一数据库事务中写入正式 staging。题图不能只留临时文件路径：

```text
question(id, stem_markdown, ...)
question_asset(id, question_id, role, image_bytes bytea, mime_type,
               source_fragment_id, page_no, bbox, content_hash, ...)
```

`role` 区分题干图、选项图、解答附件等；每张图保留原文档、页码、区域和哈希。原始大文档可以另存对象存储，但题目发布所需图像必须和题干一起进入 PostgreSQL 并受同一版本控制。

### 7.2 两个完全隔离的内容 Session

```text
UPLOAD → NORMALIZE/OCR
       → KTQ_EXTRACTION_SESSION → FREEZE_KTQ_STAGING
       → ER_RESEARCH_SESSION → LINK/VALIDATE
       → REVIEW → PUBLISH
```

1. 教师上传文档，系统保存原件哈希，OCR 为 Markdown、结构块和图片并保留页码/区域；
2. 启动全新 `KTQExtractionSession`：只给 K/T/Q 任务提示、KTQ Schema、来源片段和必要工具；它不知道后续会调研 E/R，也看不到 E/R Schema、Skill 或搜索任务；
3. 校验后冻结 KTQ staging，生成只读投影；Session 关闭，模型历史和临时工作区销毁；
4. 启动另一个全新 `ERResearchSession`：只给 E/R 调研提示、搜索工具、来源片段和冻结 KTQ 只读投影以建立外键；它看不到 KTQ 的抽取提示、候选推理、对话记录或写权限，更不能顺手重做 KTQ；
5. 搜索结果先落为 `SourceDocument/SourceFragment`，再允许形成 E/R 候选；
6. 单独的 Link/Validate 阶段构建关系和 `measurement_targets`，不把两个 Agent Session 拼接成共享上下文；
7. 写入与正式库同构的 PostgreSQL staging，教师按字段复核；
8. 发布不可变 `ChapterPackage(version, manifest_hash)`，正式学习 Session 只读取已发布版本。

“E/R Session 可看到冻结 KTQ 投影”只用于引用已存在 ID，不代表共享任务：投影中不含 KTQ 抽取过程、候选历史、原提示词或可写接口。

### 7.3 每个正式字段都有血缘

“每个数据有来源”需要四层：

```text
source_document ──< source_fragment ──< candidate_claim
                                      └──< field_lineage >── published_field
```

`field_lineage` 至少包含：

```text
package_version, entity_type, entity_id, field_path,
source_fragment_id, source_span_or_bbox, derivation_type,
agent_run_id, prompt_version, model_id, tool_call_ids,
reviewer_id, review_decision, confidence, created_at
```

这样才能回答“这道题的难度、这个错因判断依据、这条诊断规则分别来自哪里”。只用 `table_name + row_id` 只能做到行级来源，达不到提示词要求的每项数据来源。

每个可发布字段还要有 `provenance_status=direct|derived|model_generated|human_authored`。一个字段可以引用多个来源；无来源的占位值必须是 `draft_only`，发布校验对正式字段缺失 lineage 一律失败。人工原创内容也必须记录作者、时间和评审，而不能把“人工填写”当成无来源。

同一规则覆盖内容表、判答、诊断、Artifact、画像与计划，而不只覆盖 K/T/E/Q/R：系统生成的 ID/时间戳记录生成服务和事件；模型判答字段引用 `AnswerJudgment`、输入证据与模型/Prompt/Skill 版本；Artifact 引用生成 Prompt、Skill、文件哈希、知识/题目来源和发布记录；画像字段引用 `ScientificEvaluationReport`、`TeachingSessionSummary`、Session 证据、`ProfileUpdateDecision` 和参数集；教师修改字段引用 `TeacherCorrection`。数据库接收正式记录前执行 provenance completeness 校验，缺失来源的语义字段只能留在候选区。

### 7.4 模板改造

按用户提示词执行：

- 删除“使用说明、AI 输出格式、Prompt 模板、模板总览”四表；
- 删除“AI 输入拼接”列；
- “AI 识别关键词”改为“关键词”；
- 增加来源与字段血缘导出表；
- 保留官方要求的六表作为 PostgreSQL 派生导出；CSV/XLSX 只是一时生成的交付格式，不是运行时数据源。

### 7.5 发布校验

至少检查：ID 唯一、引用存在、前置图无环、答案/解析/评分点齐全、测量目标非空、K/T/E/R 外键有效、来源与授权齐全、题目去重、难度分布、三案例可运行、黄金题判答通过。

## 8. 证据、诊断与状态更新契约

### 8.1 不把所有信息压成一个 0-1 分数

一次作答应保留三个不同通道：

1. **结果通道**：答案/评分点是否正确；
2. **过程通道**：方法、步骤、草稿行为和提示依赖；
3. **错因通道**：E-ID 候选及其支持/反对证据。

队友文档中的 `ψ(E)` 可以作为教学优先级或过程质量的初始专家量表，但不直接当作 BKT 的“答对程度”。例如“答案错但只是运算错误”不能直接生成 `s=0.8` 并以分数似然推高所有知识点；系统应通过评分点或微型追问确认概念证据。

### 8.2 StateObservation

```json
{
  "observation_id": "obs_...",
  "student_id": "...",
  "dimension_id": "K_SSA",
  "question_id": "Q_TRI_012",
  "session_id": "...",
  "outcome": "success|failure|unresolved",
  "independent": true,
  "evidence_rule": "probe.supplementary_angle",
  "hint_level": 0,
  "evidence_refs": ["chat://.../turn/8", "draft://.../seg-17"],
  "model_version": "...",
  "rule_version": "...",
  "supersedes": null
}
```

只有 `success/failure` 且满足测量规则的观测进入掌握内核；`unresolved` 留在待复核/待复测队列。提示后的成功记录为教学结果，但 `independent=false`，不能直接证明独立掌握。

### 8.3 错因消歧

1. 候选只能来自题目关联 E-ID 与诊断规则；
2. 每轮选择最能区分剩余候选且不泄露答案的追问；
3. 保存支持证据、反对证据和未区分候选；
4. 三轮仍不能闭合时输出“待观察”，不能强行选一个错因；
5. 需要时用一题微型探针闭合，例如 SSA 的补角意识判断题；
6. 一个错因成为“稳定问题”至少需要两个不同题目的独立证据，或一条教师确认事件。

### 8.4 教师纠正与重放

教师改判生成：

```text
ObservationSuperseded(old_obs_id, replacement_obs_id, reason, reviewer)
```

状态归约器从最近快照向后重放，旧观测保留但不再生效。禁止把教师改判以 `w=1.2` 再加一条观测，因为那会让错误旧观测与新观测同时计数。

## 9. 量化核心：科学程序评价与大模型最终画像更新

### 9.1 为什么拆成三层

“会不会”“今天能否想起来”“通常怎么错”不是同一随机变量：

- `M_k`：知识/题型的习得概率；
- `R_k(Δt)`：距上次复测后当前可提取性；
- `C_e`：错因证据状态。

把三者混成一个数，会导致时间过去等价于“没学会”、运算错误等价于“概念掌握 0.8”、提示讲解等价于“概率自动上升”等偏差。

### 9.2 掌握层的确定性科学基线：保守 BKT

对每个学生 × 主要测量维度维护 BKT 状态。对于高置信二值观测：

```text
成功：P(L|y) = P(L)(1-S) / [P(L)(1-S) + (1-P(L))G]
失败：P(L|y) = P(L)S / [P(L)S + (1-P(L))(1-G)]
```

学习转移只在明确的学习机会后应用：

```text
P(L_next) = P(L|y) + (1-P(L|y))T_resource
```

- 纯诊断且未反馈：`T_resource=0`；
- 独立练习后得到反馈、分级提示、完整复盘分别是不同 resource class；
- 初期参数写入版本化配置并标记 `calibration_status=prior_only`；
- 有足够真实序列后，用 pyBKT 的 `multigs`、`multilearn`、`forgets` 进行拟合和时间切分验证；
- pyBKT 支持这些变体，但不替本项目自动证明任何手工常数正确。

初期可采用统一保守先验，学生自评不直接改变 P(L0)；画像只改变选题顺序。题目格式的理论猜测率可作 G 的初值，S/T 必须在报告中标明尚未校准，避免把运营分数伪装成真实概率。

这一步只回答“按已确认的逐题观测和固定公式，基准评价是多少”，不能独占画像量化。传统程序看不到跨题方法稳定性、自我纠错模式、迁移解释质量、提示依赖变化等纵向语义，因此它输出 `ScientificEvaluationReport`，不是最终画像：

```json
{
  "report_id": "ser_...",
  "session_id": "s_23",
  "prior_snapshot_id": "snap_...",
  "dimension_id": "K_SSA",
  "p_bkt_baseline": 0.71,
  "retention_estimate": {"i90_days": 4, "confidence": "low"},
  "independent_observation_count": 4,
  "hint_dependency_metrics": {},
  "data_quality_flags": [],
  "parameter_set_id": "bkt_prior_v1",
  "input_event_refs": ["obs_..."],
  "calculation_trace_ref": "calc_..."
}
```

该报告在教学阶段生成，可以反馈给 Teaching Agent 帮助选择追问和形成总结。程序可以指出“若只按 BKT，本维度为 0.71”，但不能据此直接覆盖学生画像。

教学 Session 关闭时，Teaching Agent 另行输出简短、带引用且不写长期画像的 `TeachingSessionSummary`：

```json
{
  "summary_id": "tss_...",
  "session_id": "s_23",
  "scientific_evaluation_ref": "ser_...",
  "summary": "学生能独立列出正弦定理，但第一次遗漏 SSA 补角分支；中性追问后自行修正。",
  "method_observations": [],
  "misconception_candidates": [],
  "hint_dependency": "low",
  "unresolved": [],
  "evidence_refs": ["answer://s_23/a_1", "chat://s_23/turn/8", "draft://s_23/seg-9"],
  "model_id": "...",
  "prompt_version": "..."
}
```

`ScientificEvaluationReport` 与 `TeachingSessionSummary` 组成不可拆散的 Session 双产物；前者提供科学量化锚点，后者保存教学模型才能观察到的语义过程。

### 9.3 Dream/Profile Update Agent 是独立大语言模型

长期画像只在 Dream/Profile Update 路径更新。每次 Dream 都启动全新的 `ProfileUpdateSession`；它不继承 Teaching Agent 的模型历史、不负责讲题，也不修改 BKT 参数。Orchestrator 向它提供：

- 上一个已发布 `StudentSnapshot`；
- Dream 窗口内逐 Session 配对的 `ScientificEvaluationReport` 与 `TeachingSessionSummary`；
- 摘要中的证据索引；只有发生矛盾、证据不足或需要精确判断时，才沿索引读取经过权限过滤的题目、题图、学生答案、聊天、可选草稿、提示、判答、诊断与教师纠正；
- 题目间的知识、题型、难度、表征和迁移关系；
- 画像更新 Skill、证据码表、字段 Schema 和安全边界。

这是“Dream 新 Session 读取教学双产物，并按需读取旧 Session 的可审计数据投影”，不是共享模型上下文。画像大模型综合上述信息后输出最终 `ProfileUpdateDecision`：

```json
{
  "decision_id": "pud_...",
  "baseline_report_refs": ["ser_17", "ser_23"],
  "teaching_summary_refs": ["tss_17", "tss_23"],
  "prior_snapshot_id": "snap_...",
  "dimension_updates": [{
    "dimension_id": "K_SSA",
    "p_baseline": 0.71,
    "p_final": 0.873,
    "state_final": "possibly_mastered",
    "evidence_ledger": [{
      "code": "TRANSFER_SUCCESS_DISTINCT_CONTEXT",
      "rubric_bin": "clear",
      "lr_used": 2.8,
      "session_refs": ["s_17", "s_23"],
      "evidence_refs": ["obs_71", "draft://s_23/seg-9"],
      "counterevidence_refs": ["obs_82"],
      "explanation": "在不同表征且无提示的两题中保持分类讨论；一次近迁移失败降低了证据强度"
    }],
    "alternatives": ["题目表征差异可能仍不足"],
    "uncertainty": "medium"
  }],
  "semantic_profile_updates": [],
  "review_required": false,
  "model_id": "...",
  "prompt_version": "...",
  "skill_version": "..."
}
```

`p_final`、状态、错因、方法稳定性、提示依赖和语义画像都由 Dream 大模型在该 Decision 中作最终更新。数值生效必须引用程序评价、教学总结和至少两个不同 Session 的有效证据；证据不足时，大模型应保持基准、降低置信度或只生成不影响数值的观察。

### 9.4 大模型更新仍必须可解释和可校验

画像大模型不能用一段“综合感觉”直接给分。它要提交证据账本，并用版本化似然比区间解释相对程序基准的调整：

```text
logit(P_profile) = logit(P_bkt_baseline) + Σ log(LR(code, rubric_bin))
```

首版专家先验使用区间而不是伪装成精确常数，必须标记 `prior_only` 并用教师标注和后续预测校准：

| 纵向证据码 | 触发条件摘要 | 首版允许 LR 区间 |
|---|---|---:|
| `TRANSFER_SUCCESS_DISTINCT_CONTEXT` | 跨不同表征/题型独立迁移成功 | 2.0–4.0 |
| `SELF_CORRECTION_RECURS` | 多题能无答案泄露地自我发现并修正 | 1.3–2.0 |
| `METHOD_STABLE_ACROSS_CONTEXTS` | 跨情境方法选择稳定且评分点成立 | 1.3–2.0 |
| `HINT_DEPENDENCY_DECLINES` | 可比题上提示依赖持续下降 | 1.1–1.5 |
| `REPEATED_MISCONCEPTION` | 不同题重复出现同一已确认错因 | 0.25–0.5 |
| `TRANSFER_FAILURE_DISTINCT_CONTEXT` | 原情境成功但新情境独立失败 | 0.25–0.5 |
| `METHOD_INSTABILITY` | 相近能力证据中方法无合理原因地反复摇摆 | 0.5–0.8 |

大模型选择哪些纵向关系成立、采用哪个 rubric 档位、在允许区间内使用哪个 LR，并对反证和相关性去重负责；这些都是传统程序无法独立完成的语义判断。确定性 Validator 只做四类检查：引用存在、LR 未越界、同族证据未双计数、声明的算术能重算。校验器不得自行增加证据、改变 LR 或用程序基线覆盖 `p_final`；失败时把 Decision 退回模型重试或送教师复核。

单题对错已进入 BKT 后，大模型不得再次以同一个“答对/答错”直接调整；数值账本只使用跨 Session 才成立的关系。最终报告逐项展示 `P_bkt_baseline`、大模型读取了哪些 Session 内容、每条证据码及反证、LR 选择、`P_profile`、不确定性和版本。最终画像更新者是大模型，程序承担的是科学锚点与审计护栏。

### 9.5 状态门槛

报告不只显示一个概率，至少区分：

| 状态 | 条件 |
|---|---|
| 证据不足 | 少于 2 道不同题的独立有效观测 |
| 薄弱 | 有足够证据且 P_profile < 0.40 |
| 学习中 | 0.40 ≤ P_profile < 0.80 |
| 可能掌握 | 0.80 ≤ P_profile < 0.95 |
| 已掌握 | P_profile ≥ 0.95，且至少两题独立成功，其中至少一题为迁移题或延迟复测 |

0.95 是 OATutor 使用的项目阈值，可以作为首版运营阈值，但不是所有 BKT 系统的普适定律。必须在教师一致性和后续题预测上校准。

### 9.6 时间层：艾宾浩斯式可提取性，不改写掌握概率

定义 `I90` 为该学生在该维度上预测保持率降到 0.9 所需天数：

```text
R(Δt | I90) = 0.9^(Δt / I90)
```

这是一种艾宾浩斯式指数保持率近似，而不是声称 Ebbinghaus 原始实验唯一确定了指数函数。时间层**不执行** `P(L) ← P(L)·R`。

为避免拍脑袋乘以 2.5，首版在固定稳定度网格上做可解释贝叶斯更新：

```text
I90 ∈ {0.5, 1, 2, 4, 8, 16, 32, 64} 天
P(y=1 | I90, Δt, q) = G_q + (1-G_q-S_q)·R(Δt | I90)
posterior(I90_i) ∝ prior(I90_i)·P(y | I90_i, Δt, q)
```

只有独立延迟复测更新 `I90` 分布。下一次复测时间取预测平均保持率首次低于目标阈值（首版 0.85）的时刻。数据不足时显示“复测估计不稳定”，而不是伪造精确日期。

当前答题成功率预测可以组合为：

```text
P(correct_now) = P_profile·[G + (1-G-S)·E(R)] + (1-P_profile)·G
```

这样“已习得但暂时提取困难”与“从未掌握”可在报告和教学动作上区分。

### 9.7 错因层

每个 E-ID 维护证据集合，不用一个随每题衰减的神秘计数替代证据：

- `suspected`：一个独立证据；
- `confirmed`：两个不同题目的独立证据或教师确认；
- `improving`：已有一次成功迁移但证据不足以关闭；
- `resolved`：两个不同题目的独立迁移成功且最近窗口未复发；
- `superseded`：被教师或规则版本取代。

排序分数可用 `证据数 × 置信 × 时效 × 目标相关度`，但展示时必须能展开到原始证据。

## 10. 自适应选题、终止和计划

### 10.1 两阶段选题

先选教学目标，再选具体题，避免一个总分公式把诊断、训练和复习混在一起。

#### 阶段 A：目标选择

按当前模式从以下目标中选一个：

- 新维度覆盖；
- 候选错因消歧；
- 前置知识下探；
- 延迟复测；
- 当前薄弱项训练；
- 目标分相关高频题型；
- 迁移验证。

#### 阶段 B：题目选择

硬过滤：章节包版本、测量目标、答案可验证、学生未见、模式允许、难度与设备适配。然后评分：

```text
score = coverage_gain
      + diagnostic_information_gain
      + review_urgency
      + goal_relevance
      + prerequisite_value
      - repetition_cost
      - fatigue_cost
      - leakage_risk
```

诊断模式提高信息增益与覆盖；练习模式把预测正确率控制在可学习区间；复测模式提高 `1-E(R)`。辅助模型只在完全并列或需要语言解释时裁决，不能绕过硬约束。

### 10.2 终止条件

一轮诊断满足任一条件可终止：

- 目标覆盖完成且所有关键维度至少得到一个有效观测；
- 继续出题的最大预期信息增益低于阈值；
- 达到题量或时间预算；
- 学生主动结束；
- 疲劳/连续失败达到保护阈值；
- 剩余未决项只能通过教师复核或后续延迟复测解决。

终止并不等于所有维度都有结论；“证据不足”是合法结果。

### 10.3 学习计划

计划先由确定性约束求解，再由模型转写：

1. 输入目标分、每周时间、章节包题型权重、薄弱/待观察状态、复测到期日；
2. 生成任务原子：知识补讲、低一档练习、原难度练习、迁移题、延迟复测；
3. 以时间预算、前置关系、每次学习长度和到期日为约束排入 1-4 周；
4. 每项任务写清达成判据和复测条件；
5. LLM 只负责解释“为什么先做这个”和生成自然语言，不自行增加不存在的任务。

## 11. 画像系统：教学双产物、Dream 更新与快照

### 11.1 四层状态

1. **事实层**：不可变 Session、Attempt、笔迹、聊天、观测、教师纠正；
2. **教学双产物层**：每个 Session 形成不可变 `ScientificEvaluationReport` 与 `TeachingSessionSummary`；
3. **Dream 画像决策层**：独立 Profile Update LLM 综合多组双产物并按需回看 Session 证据，输出最终 `ProfileUpdateDecision`；
4. **发布快照层**：Validator 通过后，reducer 只负责幂等物化 Decision 为 `StudentSnapshot`，不重新决定画像结论。

### 11.2 教学 Session 关闭

每个 Session 关闭后：

1. 校验 Session 输出与所有引用；
2. Teaching Agent 的模型判答生成候选 `AnswerJudgment` 与单题 `StateObservation`，校验器核对 Schema、引用和测量规则；
3. 确定性程序读取本 Session 事件，生成 `ScientificEvaluationReport`；
4. Teaching Agent 读取该程序报告和本 Session 证据，生成 `TeachingSessionSummary`；
5. 校验二者的 `session_id`、来源、版本和相互引用，作为一个 `SessionLearningRecord` 入库；
6. 将双产物加入 Dream 队列，并生成下一题短期 `handoff.md`；
7. 长期 `StudentSnapshot` 暂不改变；下一题使用上一个 Dream 快照，再叠加只限短期教学使用的 handoff。

这样程序评价能及时参与教学，又不会让每题一次的大模型画像更新造成震荡和成本浪费。

### 11.3 Dream 整理

Dream 是长期画像唯一的模型更新入口。它在日终、Session 数量阈值、双产物矛盾、教师请求或摘要过长时触发；具体触发器可配置，不把“每 5 题”写死为科学规则。

Dream Context Compiler 读取窗口内成对的程序评价与教学总结，汇总数据缺口和矛盾，并给出可按需展开的 Session 证据索引；随后启动新的画像大模型 Session。该大模型可以：

- 合并重复文字；
- 把临时观察与稳定结论分开；
- 引用结构化状态和 Session ID；
- 处理矛盾并保留双方证据；
- 根据更长窗口修订掌握度、错因、提示依赖和方法稳定性；
- 生成不超过 400 字的教学摘要。

Dream 若改变之前的画像结论，必须生成 superseding `ProfileUpdateDecision`，不能覆盖历史。程序报告是大模型更新基准，不是 Dream 的最终结果。

Validator 检查字段来源、证据权限、LR/范围、算术、自相矛盾和更新幅度；失败只触发 Dream 模型修复或教师复核，不回退成“程序自动更新画像”。通过后 reducer 才把 Decision 物化为新 `StudentSnapshot`。Dream 尚未完成时显示 `profile_lag`，教学继续使用旧快照和最新 handoff。

版本目录使用唯一 `snapshot_id` 或时间戳+哈希，不能只用日期，否则同日多次更新冲突。

### 11.4 连续性包

传给下一题的内容包含：今日题数、连续题数、学习时长、上一题方法与提示、未闭合观察、下一题建议。上一题错误不能自动升级为长期薄弱。

## 12. 模型主判答、程序提供科学校验证据

### 12.1 Teaching Agent 是最终判答主体

Teaching Agent 进入独立的 `GRADE` 状态后，读取原题、题图、评分规则、学生回答、可选草稿/图片和必要上下文，由模型完成语义判答。固定程序不是最终裁判，而是按题型提供可复核证据：选择题标准化、数值单位与容差、代数等价、解集比较、几何条件、作图约束等。

模型必须输出：

```json
{
  "verdict": "correct|partially_correct|incorrect|unresolved",
  "rubric_items": [{"id": "...", "status": "met|not_met|unclear", "evidence_refs": []}],
  "check_results": [{"tool": "symbolic_equivalence", "result_ref": "..."}],
  "decision_summary": "面向审计的简短理由，不保存隐藏思维链",
  "alternate_interpretations": [],
  "uncertainty": "low|medium|high",
  "injection_flags": [],
  "model_id": "...",
  "prompt_version": "..."
}
```

程序校验结果只作为 `check_results` 输入；模型需要解释采纳或不采纳的原因。例如符号等价工具不能判断学生是否漏写定义域，而模型可以综合题意、步骤和图形判断。程序与模型冲突、题意歧义或高不确定时，必须触发独立第二模型复判或教师队列，输出 `unresolved` 也是合法结果。

### 12.2 类型 Skill 与安全工具

不同答案类型仍使用专门 Skill 和验证工具，但它们服务模型判断：

- 选择/判断：标准化候选与题意核对；
- 数值填空：单位、精度、区间和允许形式；
- 代数表达式：安全解析、变量假设、符号等价和数值抽检；
- 方程/集合：比较解集、定义域和边界；
- 几何/图形：视觉理解与约束检查组合；
- 解答题：模型按评分点逐项判定并引用答案/草稿片段。

学生表达式不得直接交给 Python `eval` 或无限制 SymPy；校验工具使用受限语法、超时、复杂度限制和定义域检查。题干、学生回答、附件、OCR 文本和搜索结果都被标记为不可信数据；其中出现的“忽略评分规则”“运行命令”等文本不能升级为指令。

## 13. Qwen-MM-Plugins 的正确位置

四个子项目都保留为实验 Provider，不因当前主流程暂未调用就从结构中删除：

| Qwen-MM-Plugins 部分 | 项目适配 | 用途 |
|---|---|---|
| `core` | `MediaUnderstandingProvider.local` | 本地图片/视频读取、裁剪、标注、可视化，不依赖云端视觉模型 |
| `api` | `MediaUnderstandingProvider.api` | 调用云端或 OpenAI-compatible 自建视觉端点做 OCR、grounding、图像/视频理解；可让文本宿主模型获得组合多模态能力 |
| `search` | `SearchProvider.qwen_plugins` | 在 Serper、Exa、Tavily 等提供商间切换并规范化引用 |
| `edu-agent` | `ExplanationRenderer.hyperframes` + `ArtifactPublisher` | 按 Learning Artifact 协议生成知识可视化 HTML、HTML/原生小题卡或讲解视频 |

`edu-agent` 可以用于学生请求后的生动讲解，也可以异步生成复盘资产；是否进入同步链路由延迟预算、设备能力和 A/B 实验决定，不预先一刀切。维护最小修改的受控 fork，使其接收本项目 `ExplanationSpec`、证据引用、题目版本和 `agmath.learning-artifact/v1` 输出约定。

它的标准出口不是把一大段 HTML 塞进聊天 JSON，而是在固定 Artifact 目录写 `manifest.json + index.html/card.json + media/`，Teaching Agent 在回复中引用 `artifact://...`。知识点动画、小题卡和混合讲解因此共用发布、版本、缓存、安全和交互事件链；简单卡片可由前端原生渲染，复杂卡片由 `edu-agent` HTML 渲染，但两者提交相同 `ArtifactResponse` 事件。

交互 HTML 必须经过清洗，置于无同源权限的 sandboxed iframe，应用严格 CSP，禁止外部脚本、任意网络、父页面 DOM 与敏感数据访问；只允许第 5.4 节的受限消息桥。资源按哈希固定，讲解绑定题目、解法、模型、Skill 和审核版本。HTML 可以收集回答/跳过/直接回复意图，但不能自行宣告判答或写画像。

所有四类插件都设置独立 feature flag、版本固定、契约测试、质量/延迟/成本指标和无插件回退路径。PaddleOCR 仍是数学文档 OCR 的首选 Provider；Qwen API OCR 可作为对照、回退或特定媒体任务实现。

## 14. 数据存储与版本

### 14.1 建议存储

- PostgreSQL 是唯一运行时事实源：正式领域对象、题干与题图、事件索引、任务、状态快照、版本、审计；
- 对象存储：原始大文档、笔迹原始流、派生渲染图、视频和 Session 归档包；对象元数据与哈希仍在 PostgreSQL；
- 队列：内容生产、画像更新、教师复核、视频生成；
- 本地/容器文件系统：单题临时工作区；关闭后打包进对象存储；
- CSV/XLSX：只能由 PostgreSQL 生成官方交付或人工查看快照，禁止被服务读取为运行时数据库；不提供 SQLite/CSV 运行模式。

### 14.2 关键表族

```text
content: source_document, source_fragment, chapter_package,
         knowledge_component, question_type, error_cause,
         question, question_asset, measurement_target,
         diagnosis_rule, field_lineage

runtime: assessment_run, question_session, attempt, chat_turn,
         stroke_event_index, draft_segment, answer_verdict,
         diagnostic_claim, state_observation, intervention_event,
         learning_artifact, artifact_version, artifact_interaction,
         teaching_session_summary, session_learning_record

state:   scientific_evaluation_report, profile_evidence_bundle,
         profile_update_decision, mastery_state,
         retention_state, misconception_state,
         student_snapshot, review_schedule, learning_plan

review:  review_task, teacher_correction, release_record,
         evaluation_run, agent_trace
```

### 14.3 全链路版本字段

每次结论至少记录：`chapter_package_version`、`question_version`、`rule_version`、`prompt_version`、`skill_version`、`model_id`、`kernel_version`、`parameter_set_id`。否则教师无法解释同一作答为何在两次运行中得到不同结论。

## 15. 企业多租户与并发

### 15.1 请求路径

```text
Web → Backend API → OIDC/Tenant Guard → Session Orchestrator
       → Container Pool / Model Gateway
       → Event Store → Queue → Reducers/Workers
```

### 15.2 关键原则

- API 与 orchestrator 无状态；
- 前后端只通过版本化 OpenAPI 与事件流通信，前端没有数据库、对象存储或模型供应商凭据；
- 单学生状态更新按 student_id 串行，其他学生可并行；
- `session_id`、`attempt_id`、`event_id` 全链路幂等；
- 沙箱按 tenant/student/session 隔离，只读挂载章节包与画像投影；
- 热容器池减少启动延迟，Session 关闭后清空；
- 模型网关负责限流、重试、超时、成本和供应商回退；
- 内容生产和视频生成不占实时教学队列；
- PostgreSQL 行级租户约束与对象存储前缀双重隔离；
- reducer 使用乐观锁或学生分区队列，防止并发覆盖画像。

## 16. 安全、隐私和可观测性

### 16.1 认证授权不手写

默认部署 Keycloak，通过标准 OIDC/OAuth2 接入登录、MFA、会话、密码策略、身份联邦与角色；后端只实现 `AuthProvider` 适配器、租户映射和领域授权，不自制账号密码、Token 签发或找回密码流程。若企业已有 IdP，可替换 OIDC issuer 而不改变业务层。

角色至少包括学生、监护人、教师、内容审核员、租户管理员和平台运维。授权同时在 API policy 与 PostgreSQL Row-Level Security 落地，前端隐藏按钮不构成授权。

### 16.2 未成年人和数据安全

最小收集、目的告知、保存期限、查询/更正/删除、监护人同意策略、匿名学生 ID、模型调用去标识化。教师只能看其教室内学生。传输使用 TLS，数据库/对象存储加密与密钥轮换，备份做恢复演练；导出使用短期授权链接和水印，敏感审计日志不可由普通管理员修改。

### 16.3 Prompt 注入、供应链与工具边界

教师上传资料、学生文本、OCR、网页、搜索结果和插件输出均视为不可信数据；其中的“指令”不得提升为系统命令。系统提示、任务契约和数据分别封装，模型输出必须过 Schema、引用和权限校验。高风险动作不由自然语言直接授权。

shell 沙箱使用第 5 节的只读挂载、固定写区、禁外网、无宿主凭据、命令超时和资源配额，不采用命令 allowlist。搜索由隔离 Broker 完成并做 SSRF 防护、域名/IP 重解析检查、内容大小限制和恶意页面标记。

Pi、Qwen-MM-Plugins、PaddleOCR、Keycloak 等依赖固定版本和校验和，维护 SBOM、许可证清单、漏洞扫描和升级回归；自定义 Skill/Extension 上线前做代码审查。优先通过适配器直接复用成熟开源项目，只有项目特有的领域契约、画像融合和教学策略才手写，并要求类型、测试、迁移、评审和可观测性齐全。

### 16.4 网络与滥用防护

入口经反向代理/WAF，配置 TLS、CORS、CSRF、CSP、安全响应头、上传类型/大小检查和恶意文件扫描。按租户/用户/IP/任务限制请求、并发、Token、搜索费用、OCR 页数、shell 资源和生成视频时长；异常批量抓题、撞库、提示注入、越权枚举和资源消耗触发降速、封禁或人工复核。

### 16.5 可观测性

记录状态转换、工具调用、模型版本、延迟、Token、失败、Schema 重试、状态更新前后、证据引用和教师修改。可回放不等于保存模型隐藏推理；保存可审计输入、动作和结构化输出即可。

## 17. 测试与评测

### 17.1 单元与性质测试

- BKT 二值公式与 OATutor 参考实现对拍；
- `unresolved` 与提示后成功不得更新独立掌握证据；
- 多标签题只更新满足 evidence_rule 的维度；
- 教师 supersede 后状态重放结果确定；
- 保持率只改变复测优先级，不直接改 P(L)；
- 同一事件重复消费不改变状态；
- Session 工作区不可读取其他学生文件。
- Dream/Profile Update Agent 以成对的程序评价和教学总结为主输入，只能按引用读取经过授权的 Session 数据投影，不继承 Teaching Agent 模型历史；它必须在 `ProfileUpdateDecision` 中明确写出最终概率、相对程序基准的变化及证据账本；
- Validator 对画像 Decision 只校验来源、边界和计算一致性，不得静默替换成程序基准；
- 同一单题结果不得同时进入 BKT 与纵向 LR，防止双计数；
- 每个进入 Dream 的 Session 必须存在相互引用的 `ScientificEvaluationReport` 与 `TeachingSessionSummary`；
- 教学 Session 关闭不能触发长期画像模型更新，只有 Dream 路径能发布 `ProfileUpdateDecision`；
- 有草稿和无草稿实现都必须通过同一 Session 契约测试；
- Artifact 只能从固定目录发布，未引用/越界/符号链接逃逸/危险 MIME 必须拒绝；
- 原生卡片和 edu-agent HTML 卡片产生同构交互事件；
- 卡片跳过和直接回复不得产生失败观测；
- 文字、图片、视频、卡片及混合 `TeachingMessage` 均通过 Schema、权限与可访问性测试；
- 每个 Provider 的替换实现必须通过能力、错误语义、血缘和回退契约测试；
- shell 可运行非预置命令，但任何方式都不能写出固定区域、访问一般外网或超过资源/时间限额。

### 17.2 黄金数据

- 内容：25+ K、20+ T、20+ E、80+ Q、20+ R 和字段来源；
- 判答：每种答案类型的等价/非等价边界；
- 诊断：主要错因每类至少 5 条双教师标注轨迹；
- 草稿：实时笔迹、修改、跨区域、长停顿、辅助线、低清照片；
- Artifact：知识可视化 HTML、四种卡片、图片、短视频、恶意 HTML 和损坏媒体；
- 学生案例：基础薄弱、公式会但分类讨论不全、基础较好冲高分。

### 17.3 指标

- K/T/E 与教师一致率；
- 错因 top-1、top-2 与“应保持未决”的准确率；
- 下一题独立正确率预测的 Brier score/校准曲线；
- Profile Update LLM 与教师画像更新的一致率、相对程序基准的增益和校验退回率；
- `p_final - p_bkt_baseline` 的分布、证据覆盖率与每次调整的可解释率；
- 少量题目的覆盖效率和平均题数；
- 教师复核耗时与改判率；
- 提示后迁移成功率；
- 草稿引用定位正确率；
- Artifact 发布成功率、HTML 首屏/P95、卡片事件正确率和跳过误判率（目标为 0）；
- 图片替代文本、视频字幕/摘要和键盘操作覆盖率；
- P95 延迟、Session 成功率和单题成本。

### 17.4 必须做的消融

1. 只看答案；
2. 答案+静态草稿；
3. 答案+时序草稿；
4. 无错因探针 vs 有探针；
5. 原始历史上下文 vs 结构化 handoff；
6. 单一掌握分 vs 掌握+可提取性分层。
7. 仅程序基准 vs 程序基准+跨题 Profile Update LLM 最终更新；
8. 直接多模态主模型 vs 文本主模型+Qwen API 视觉；
9. 无草稿 vs 静态草稿 vs 时序草稿；
10. 普通图文讲解 vs `edu-agent` 交互 HTML。
11. 原生 JSON 卡片 vs `edu-agent` HTML 卡片；
12. 强制作答 vs 可跳过/直接回复对学习持续率和诊断质量的影响。

## 18. 模块化组装与交付顺序

这里不采用“先切一条临时比赛链路”的做法。所有正式模块从第一阶段就在组合根中存在，尚未完成的外部能力使用符合契约的 stub/fake；系统始终能一口气启动并跑完整流程，再逐模块替换实现。

### 阶段 A：冻结契约并组装全系统骨架

- 冻结 OpenAPI、事件、Provider、ChapterPackage、字段血缘、Session 状态机和数据库迁移契约；
- 建立前后端分离仓库结构、PostgreSQL、队列、对象存储、Keycloak、API、五类 Agent 任务、教学双产物→Dream 大模型更新管线、Learning Artifact、教师复核和 `web-test`；
- 每个模块先有最小可运行实现，compose/部署清单能启动整套系统；
- 所有参数标注 `prior_only` 或 `calibrated`，所有外部实现标注版本和许可证。

### 阶段 B：替换为生产级基础适配器

- 接入 Pi SDK/RPC、多模型 Provider、本地/API PaddleOCR、SearchProvider 和沙箱 Broker；
- 复用并改造队友 OCR 管线，落实题图入库和 KTQ/ER 双 Session；
- 打通 PostgreSQL RLS、OIDC、审计、备份恢复、限流和监控；
- 发布首个经过字段血缘复核的章节包并运行全链路回归。

### 阶段 C：逐模块增强和实验

- Teaching Agent 模型主判与题型校验 Skill；
- 教学阶段 `ScientificEvaluationReport + TeachingSessionSummary`、Dream LLM、`ProfileEvidenceBundle` 与可解释 Decision 校准；
- 可选草稿的实时笔迹、纸面拍照和引用；
- `edu-agent` 通过统一 Artifact 协议生成知识 HTML、小题卡、图片和视频；
- Qwen `core/api/search/edu-agent` 各自通过 feature flag 做 A/B、延迟、成本和安全评测；
- 每次只替换一个契约实现，整套集成环境持续运行，不复制出另一套“实验版”。

### 阶段 D：前端专业化与正式发布

- `web-test` 先证明学生、教师、内容和管理员流程完整；
- 冻结后端契约后，由擅长前端的模型完善 `apps/web` 的视觉系统、响应式布局、无障碍和交互细节；
- 做容量、安全、灾备、模型回退、数据迁移和运营验收；
- 竞赛要求的表格、案例和演示视频全部由这套正式系统派生，不维护临时单机分支。

### 首个全链路验收场景

学生完成一道 SSA 题 → Teaching Agent 引用 `edu-agent` 生成的 SSA 动态 HTML 和一张可跳过的补角判断卡 → 学生可作答或直接文字回复 → 模型结合回答/可选草稿和校验工具判答 → 传统程序形成 BKT/保持率评价，Teaching Agent 同时形成简要总结 → 后续不同题生成更多双产物 → Dream LLM 综合这些记录并按需回看证据，输出最终画像 Decision → Validator 验证后发布快照 → 教师改判一个观测并重放双产物与 Dream。无草稿、跳过卡片和视频生成失败时也必须完成同一验收。

## 19. Claude v2.1 结构审查

以下审查只在独立设计完成后进行。

### 19.1 Claude 的结构

Claude 文档采用：

```text
决策记录
→ 算法调研
→ 五个子系统总图
→ 内容生产线
→ 教学运行时
→ 画像系统
→ 学习状态跟踪内核
→ 赛题映射
→ 实施顺序
→ 待确认项
```

实际正文只完整展开了 ①-④；总图中的 ⑤教师复审台没有独立操作路径。

### 19.2 本设计的结构

本设计按“领域边界与证据流”组织：

```text
设计宪法
→ 领域对象与四边界
→ 契约先行的前后端与模块结构
→ 学生/教师旅程
→ Pi/Provider/隔离 Agent 与单题运行时
→ 开放 shell 的受限沙箱与可选草稿
→ 内容生产与字段血缘
→ 证据/纠正/状态契约
→ 程序科学评价/画像大模型最终更新/保持率/错因内核
→ 选题/计划/画像
→ 判答/插件/数据/并发/安全/评测
→ 全模块组装与正式发布
```

它先定义产品行为和对象，再定义算法；因此公式有明确的输入事件、权限和输出消费者。

### 19.3 逐项结论

| 审查项 | Claude v2.1 | 本设计结论 |
|---|---|---|
| 赛题必选链路 | 基本覆盖 | 可保留 |
| 一题一 Session | 清楚 | 保留，并补状态机契约 |
| 教学/画像写权限分离 | 做得较好 | 保留 |
| 内容暂存→确认→正式 | 方向正确 | 保留，升级为不可变章节包 |
| 来源追溯 | 只有行级 `sources` | 不足；改为字段级 lineage |
| 草稿 | v2.1 几乎从架构消失，工作区无 `draft/` | 恢复为一级可选模块；有无草稿都能完成全流程 |
| 教师复核 | 总图有⑤，正文没有完整流程 | 结构未闭合；拆内容复核与学生诊断复核 |
| 模型名称 | 写 `Qwen3.8-Max` | 当前准确 ID 是预览模型，应适配化 |
| DeepSeek 搜索 | 默认“DSv4f 搜索” | 模型不等于搜索服务，拆 SearchProvider |
| Agent 数量与隔离 | 宣称只有两类，但内容 Agent/教学 Agent/画像 Agent 实际混用 | 明确五种角色；KTQ/ER、教学/画像各用全新 Session |
| 判答 | 过度依赖 SymPy simplify+随机代入 | 模型主判，类型程序只提供科学校验证据 |
| 量化 | 固定程序几乎独占数值更新 | 程序生成科学评价基准，独立画像大模型综合 Session 证据作最终可解释更新 |
| 多标签归因 | 同一 s 对每个 K/T 各写一条 | 有信用分配错误；引入 MeasurementTarget |
| 部分得分 BKT | 自创分数似然，称有文献先例 | 文献先例不等于该公式已验证；首版不用软似然 |
| 学习转移 | 即使 w=0 仍统一加 T | 会把“看过讲解”直接变成掌握；按事件类型区分 |
| 遗忘 | `P_L ← P_L·R(t)` | 把习得与提取混淆；拆 M 与 R |
| 艾宾浩斯+SM-2 | 自定义乘数混合 | 不声称科学固定；用保持率+稳定度后验 |
| 0.95 门槛 | 称 OATutor/Corbett-Anderson 标准 | OATutor 的确使用 0.95，但不是普适定律 |
| 教师改判 | 作为 w=1.2 新观测 | 会双计数；必须 supersede+replay |
| 画像版本 | 以日期为目录 | 同日冲突；用唯一 snapshot_id |
| 自适应选题 | 有 EIG、覆盖和 ZPD | 方向好，但需先选目标再选题、处理多维测量 |
| 企业并发 | v2.1 未展开 | 原提示词明确要求，需独立章节 |
| UI/前后端/部署/测试 | 大部分缺失 | 前后端分离，先流程前端、后专业美化，并补部署测试 |
| Qwen-MM-Plugins | 主要只保留 edu-agent 的异步用途 | 过度收缩；core/API/search/edu-agent 都应是实验 Provider |
| edu-agent | 放在复盘/教师素材，非实时主链 | 不预先排除交互 HTML 同步讲解，由预算和实验决定 |
| 学习 Artifact | 未定义模型生成文件的稳定引用和交互协议 | 增加统一文件契约，使 edu-agent HTML、卡片、图片和视频成为一等消息内容 |
| 数据库 | 保留比赛/单机思路 | PostgreSQL 是唯一运行时事实源，CSV 仅派生导出 |
| 认证和安全 | 未形成完整产品边界 | 用 Keycloak/OIDC，并补数据、网络、注入、滥用与供应链防护 |

### 19.4 Claude 值得直接继承的部分

1. 一题一 Session、一沙箱；
2. 三层上下文与渐进披露；
3. 主模型无画像写权限；
4. 回顾 JSON 作为 Session 出口；
5. Session 快速整理与 Dream 长期整理分离的思想；本设计把快速层收敛为程序评价+教学总结，不直接更新画像；
6. L0-L5 与诊断/求助/复盘三模式；
7. 候选错因→消歧追问→微型复测；
8. 内容 staging→教师确认→正式发布；
9. 插件能力通过独立模块接入并绑定版本；
10. 选题中考虑覆盖、信息价值、前置和复测。

### 19.5 Claude 结构的根本问题

Claude v2.1 最大的问题不是“细节还少”，而是结构重心发生了偏移：

- 它以算法章节为中心，把原始设计的核心亮点“草稿过程取证”降成了几乎不存在的输入；
- 它把一次作答、知识掌握、错误类型和时间遗忘压进了一个连续分数与一个概率，导致状态含义不再单一；
- 它没有先定义可重放事件与多标签测量契约，因此后面的 BKT、教师改判和报告虽有公式，却缺少可靠输入；
- 它让确定性程序独占判答与画像量化，削弱了大模型跨题纵向观测的核心价值；
- 它没有把 Pi、Qwen-MM 四类能力、OCR/搜索 Provider、前后端分离和正式安全基础设施放入可替换模块骨架；
- 它在总图中承诺了教师复审、企业产品和五个子系统，但文档主体没有闭合这些承诺。

因此不建议在 Claude v2.1 上继续追加零散章节。更稳妥的做法是：保留其一题一 Session、渐进上下文、教学模式和教师重放思想，把模块契约、Provider、双 Session 内容管线、模型主判、教学程序评价+简要总结→Dream 大模型最终更新、Learning Artifact、字段血缘、可选草稿和企业安全作为新骨架，再迁入可复用内容。

## 20. 当前必须冻结与仍需实验的内容

### 可立即冻结

- 前后端分离和契约先行的全模块组合；
- 聊天主引导、草稿可选增强、无草稿完整流程；
- 一题一 Session；
- KTQ/ER 两个新 Session 严格隔离，教学模型与画像模型严格隔离；
- Agent 可见工具只有 `bash`、`search`，安全由沙箱环境而非命令白名单实现；
- 事件不可变、教师纠正用 supersede；
- ChapterPackage staging/review/publish；
- K/T/E/Q/R、MeasurementTarget 和每字段 lineage；
- 模型主判、程序校验工具；
- 每个教学 Session 形成 `ScientificEvaluationReport + TeachingSessionSummary`，Dream LLM 是长期画像唯一模型更新入口；
- `agmath.learning-artifact/v1`、固定 Artifact 目录、稳定引用和受限 HTML 事件桥；
- 卡片允许提交、跳过和不作答直接回复，未作答不等于失败；
- TeachingMessage 支持文字、图片、视频和卡片组合；
- Qwen `core/api/search/edu-agent` 均通过实验模块接入；
- 模型/OCR/搜索/媒体/讲解供应商适配层；
- PostgreSQL 唯一运行时事实源和 Keycloak/OIDC；
- 题间 handoff 和 Dream 摘要边界。

### 必须标为实验参数

- BKT 的 P(L0)、G、S、各 resource 的 T；
- 掌握/薄弱阈值；
- 时间片分段阈值；
- 复测目标保持率 0.85；
- 信息增益终止阈值；
- 练习预测正确率区间；
- 稳定错因所需证据数；
- Dream 触发阈值。
- 纵向证据码的 LR 与相关家族窗口；
- 直接多模态与文本主模型+视觉 Provider 的路由；
- PaddleOCR 本地/API/MCP 路由；
- Qwen 四类插件的启用范围和 `edu-agent` 同步延迟预算。
- 原生卡片与 `edu-agent` HTML 卡片的适用范围；
- 图片/视频生成 Provider、大小和同步/异步预算。

“科学”不等于把这些数写死，而是：定义清楚、来源透明、状态语义单一、能用真实数据校准、改参数后可重放和比较。
