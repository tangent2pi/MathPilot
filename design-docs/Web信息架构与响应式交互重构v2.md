# MathPilot Web 信息架构与响应式交互重构 v2

> 日期：2026-08-19
> 依据：`用户呈现形式v1`、产品重构基线 v1、系统设计 v3.3 与 frontend-design Skill。
> 目标：修复页面各自定义顶栏、导航重复、首屏跳动、教师内容流程堆叠和多端不可用。

## 1. 产品与设计命题

- 具体对象：高中数学诊断教学系统。
- 学生的单一任务：从当前证据出发，明确并完成下一步学习活动。
- 教师的单一任务：区分“内容生产、人工裁决、教学运营”，在各自责任边界内完成动作。
- 视觉命题：**证明工作台**。界面像一份持续形成的证明，而不是通用数据看板。
- 签名元素：**证据轨迹**。学习会话用纵向步骤轨迹，内容工坊用批次生产轨迹；编号只用于真实顺序。

## 2. 视觉 Token

| 角色 | Token | 值 |
|---|---|---|
| 证明纸 | `paper` | `#F7F8F4` |
| 蓝黑证明墨 | `ink` | `#17233B` |
| 推理/工具 | `indigo` | `#3347A8` |
| 裁决/警示 | `cinnabar` | `#BD3D34` |
| 已核验证据 | `pine` | `#28745F` |
| 未决提醒 | `amber` | `#A86F12` |

全站使用本地自托管的霞鹜文楷 regular/bold，数据标识使用等宽字体。正式页不加载远程字体，避免字体替换造成布局跳动。题目、对话和复核内容中的 TeX 由本地 KaTeX 资源排版，不依赖 CDN。

## 3. 唯一应用骨架

所有登录后页面只保留一套 App Shell：

```text
desktop / tablet
┌ MathPilot ┆ 当前空间/页面 ┆          账户 ┐  固定 68px
├──────────┬──────────────────────────────┤
│ 唯一侧栏 │           页面主任务         │
└──────────┴──────────────────────────────┘

phone
┌ MathPilot                              账户 ┐  固定 58px
│                页面主任务                │
└ 学习 ┆ 练习 ┆ 报告 ┆ 我的/教师主任务 ───┘  固定底栏
```

- 页面 HTML 只声明空的 `[data-app-shell]` 容器；共享脚本根据 Better Auth 主体和角色生成导航。
- Header 在身份请求前已有固定高度，不因用户名、角色导航异步出现而推动页面。
- 学生主导航：学习、练习、报告、我的。
- 教师主导航：工作台、内容、学生、设置。复核是工作台的核心任务，不重复占用一个一级入口；教师导航不混入学生入口。
- 页面 Hero 不再重复一遍导航或产品名，只解释此页任务与边界。

## 4. 页面职责

| 页面 | 单一任务 | 不在该页处理 |
|---|---|---|
| 学习工作台 | 选择下一学习活动 | 展开全部证据、内容管理 |
| 练习 | 完成一题或一次教学对话 | 长期画像判断 |
| 报告 | 查看风险、证据和下一步 | 内容裁决 |
| 我的 | 修改学习设置与查看绑定关系 | 教学内容管理 |
| 教师工作台 | 裁决候选、处理学生诊断并选择下一项待办 | 上传资料、班级运营 |
| 内容 | 建立并跟进一个资料批次 | 学生诊断改判 |
| 学生 | 找到学生并查看报告与计划 | 内容生产 |
| 设置 | 查看内容版本、质量检查与数据导出 | 日常复核和教学对话 |

## 5. 内容工坊状态机

```text
选择文件
  → 上传原件并检查本批清单
  → 明确点击“确认清单，开始处理”
  → 一个 KTQ Pi Session（原件 + 已有 KTQRE；按需使用 OCR）
  → 独立 ER Pi Session（Core + 按需 Search）
  → 内容复核队列清空
  → 发布不可变章节包
```

- 不限制必须五份，不限制只上传 PDF；文件数量来自教师真实资料批次。
- 文件选择只建立浏览器清单；上传后形成可恢复的“待确认”资料任务，不触发 Agent 或付费 OCR。待确认卡片允许继续逐份追加或移除文件；浏览器按文件发送，避免多份 Base64 聚合超过请求上限。
- 确认后 KTQ 先观察原件，再依据 `ocr-routing` Skill 判断是否需要 PaddleOCR；OCR 结果只作为版面与文字证据补充，始终与原件共同保留。
- 页面阶段为“检查资料 / 整理题目与知识 / 补充错因与规则 / 复核与发布”；模型对话和批次摘要始终可返回查看。
- 当前批次、文档 ID、KTQ/ER 独立 Session、复核进度与发布信息都保存在服务器；刷新、离开或服务重启后可继续。
- 复核题目时同时显示原文件名、页码、来源片段、题图、答案与测量维度；教师在同一弹窗完成确认、修改、退回或合并，不需要另开内部数据页寻找依据。
- 复核入口只显示当前批次的事项；全部复核通过且发布校验成功后，才出现“发布给学生”，发布版本与内容清单不可变。

## 6. 响应式验收

| 视口 | 规则 |
|---|---|
| `>=1180px` | 学习会话三栏；教师工作流主区 + 状态侧栏 |
| `721–1179px` | 学习会话两栏，草稿移到主列下；管理表格横向容器 |
| `<=720px` | 单栏、58px 顶栏、固定底部主导航；按钮至少 40px；流水线转纵向 |

所有断点必须保持：键盘焦点可见、`prefers-reduced-motion` 关闭非必要动画、表格不撑破页面、对话与 Artifact 不横向溢出。

## 7. 自检修订

最初方案倾向继续使用“每页不同的卷宗标题和印章图标”，这会再次把产品拆成多个视觉站点，已删除。保留的唯一冒险是“证明轨迹”——它只出现在确有先后关系的学习会话和内容生产线上；其他卡片不使用装饰性编号。

## 8. 2026-08-20 实机验收

- 视口：桌面 `1440×900`、平板 `834×1112`、手机 `390×844`。
- 页面：登录；学生学习、练习、报告、我的；教师工作台、内容、学生、设置；统一 Agent Session 对话。
- 身份：Better Auth 学生与教师种子账号分别登录，角色导航、默认落点和页面权限正确。
- 布局：八个截图的 `body.scrollWidth` 与 `documentElement.scrollWidth` 均不大于视口；桌面/平板顶栏为 69px，手机顶栏为 59px；移动底栏项目数按角色动态生成。
- 资料草稿：真实 API 验证创建、逐份追加、移除和刷新恢复；测试对象在验证后按精确 ID 清理。
- 空状态：画像、计划、复核队列和正式内容库均显示可操作的空状态，不伪造示例结论。
- 付费边界：验收未提交题目、未执行 OCR、未调用 SCNET/Search，避免消耗用户密钥。
